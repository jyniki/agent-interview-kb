# 系统设计题练习

设计题考的是组合运用：澄清、估算、架构、深挖、评测上线。练法和单题不同：用户要完整讲一遍，你最后按评分要点打分。

## 1 选题

```bash
python3 scripts/coach.py mock --design --track <方向> --json
```

返回题目所在目录。只读 README 的“题面”一节念给用户，其余部分（澄清假设、估算、架构、评分要点）在用户作答前都不要展示。

## 2 作答

1. 告诉用户限时（README 开头标注，一般 45 分钟），建议按 [core/13 的六步框架](../../../kb/core/13-system-design/README.md) 讲：澄清 → 估算 → 架构 → 深挖 → 权衡 → 评测上线。
2. **澄清阶段**：用户提问时，按 README 第 2 节的“本题假设”回答。用户没问到的关键问题不要主动给，记下来复盘时指出。
3. **估算阶段**：让用户说出算式。数字和 README 不一样没关系，只要假设合理、算式对。
4. **架构阶段**：用户可以口述或画图。不评价，只在模糊处追问“这个模块具体负责什么”。
5. **深挖阶段**：从 README 第 5 节和 questions.md 里挑用户没覆盖的关键点追问，追到用户答不上为止。最多追三个点。

## 3 打分与复盘

1. 读 README 的“评分要点”表，逐项给 0/1/2 分，每项一句理由。
2. 指出用户漏掉的澄清问题、没讲代价的设计、没想到的风险，并给出 README 对应小节的位置。
3. 对用户答得最弱的一两个深挖点，从 questions.md 里找对应题，用 [drill.md](drill.md) 的方式各练一题，并 `record`。
4. 让用户用 3 分钟重新讲一遍最弱的部分。不要把 README 的整段讲法贴给用户背。

## 4 记录

设计题本身不单独记分。它的追问题（`design-` 开头的题号）在用户学完这道设计题后进入复习队列：

```bash
python3 scripts/coach.py learned design/<题目目录>
```
