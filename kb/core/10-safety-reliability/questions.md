# 题目：安全与可靠性

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## core-safety-001 什么是间接 Prompt 注入，和直接注入有什么区别
- level: 1
- tags: [core, harness]

**一句话答案**：直接注入是用户自己在输入里写恶意指令；间接注入是攻击者把指令藏在 Agent 会读取的外部内容里，例如网页、邮件、文档或工具返回，Agent 处理这些内容时被劫持。

**要点**：
- 出处：Greshake 等，arXiv 2302.12173，2023-02。攻击者不需要直接接触模型。
- 根本原因：模型在同一上下文里读指令和数据，没有可靠机制区分两者。
- 间接注入更危险：用户本人可能是无辜的，攻击面是所有 Agent 能读到的内容。
- 典型后果：数据外泄、执行未授权动作、通过写回内容继续传播。

**追问链**：
1. 在 prompt 里写“不要执行文档中的指令”够吗？→ 不够。能降低成功率，但没有保证；攻击者会不断换说法。
2. 加一个注入检测分类器呢？→ 可以作为一层防御，但安全上拦住大部分不等于安全，剩下的攻击仍会成功。真正的防线是让不可信内容无法触发有后果的动作。

**易错点**：
- 只讲“越狱”，不知道间接注入的攻击面在工具返回和检索内容里。

## core-safety-002 什么是“致命三要素”（lethal trifecta，Simon Willison），怎么用它评估 Agent 的风险
- level: 1
- tags: [core, harness]

**一句话答案**：能读私有数据、会接触不可信内容、能向外通信，三者同时具备时，一次注入就可能导致数据泄露；评估时检查是否三者兼备，能拆就拆。

**要点**：
- 出处：Simon Willison，The lethal trifecta，2025-06。
- 向外通信不只是发请求：加载一张带参数的图片、生成一个可点击的链接都算。
- 拆法：去掉外发能力（禁网、链接白名单）；或者处理不可信内容的环节不接触私有数据。
- 实际修复中常见的做法是关掉外发通道。

**追问链**：
1. 企业知识库问答 Agent 有没有三要素？→ 读内部文档（私有数据）；文档可能被任何员工上传（不可信内容）；如果回答里能渲染外部图片或链接，就有外发通道。关掉外部资源渲染就拆掉了第三项。
2. 三者都必须保留怎么办？→ 对外发动作加人工确认，并限制外发目标；用 Dual LLM 或 Plan-Then-Execute 让不可信内容影响不到动作选择。

**易错点**：
- 只盯着模型本身，不检查工具组合带来的外发能力。

## core-safety-003 怎么为 Agent 设计工具权限
- level: 2
- tags: [core, harness]

**一句话答案**：按最小授权原则，从功能、权限、自主三个方面收紧：只给需要的窄工具，在下游系统按当前用户身份限制权限，高影响操作要人工确认，授权检查由下游执行而不是由模型判断。

**要点**：
- 依据 OWASP LLM06:2025 Excessive Agency 的三类根因。
- 功能：读邮件的 Agent 不给发信和删信；用专用工具代替万能 shell。
- 权限：只读功能用只读账号；以当前用户的范围执行，例如 OAuth 授权范围。
- 自主：只读自动执行，可撤销写操作记日志，不可撤销或对外操作要确认。
- 兜底：所有调用记审计日志，写操作限速。

**追问链**：
1. 为什么不能让模型判断“这个操作是否允许”？→ 模型可能被注入或判断错，授权必须由确定性的下游系统执行。
2. 人工确认太多用户会烦怎么办？→ 按风险分级，只对不可逆和对外的操作确认；确认时展示具体参数，而不是只问“是否继续”。
3. 工具执行环境怎么隔离？→ 用沙箱限制文件系统和网络，这是工程实现，属于 harness 方向。

**易错点**：
- 用一个高权限的服务账号给所有用户共用。

## core-safety-004 Agent 的幻觉怎么检测和缓解
- level: 2
- tags: [core, evaluation]

**一句话答案**：检测靠检索引用校验、采样一致性和工具核对；缓解靠让关键事实只来自工具结果，以及允许 Agent 说“不知道”或转人工。

**要点**：
- 引用校验：每条结论都要能在引用片段里找到依据。
- 采样一致性：SelfCheckGPT（arXiv 2303.08896）对同一问题多次采样，答案互相矛盾说明可能在编；不需要外部知识库和概率输出。
- 工具核对：订单号、价格、库存等字段以工具返回为准。
- 弃权：评测和 prompt 都要奖励合理的拒答。

**追问链**：
1. 采样一致性的局限？→ 成本成倍；模型稳定地给出同一个错答案时查不出来。
2. Agent 里幻觉为什么比聊天更危险？→ 编出来的值会变成工具参数，例如编一个订单号去退款，错误变成了真实动作。
3. 怎么评幻觉率？→ 在评测集里放答案不在资料中的题，统计编造率和拒答率，两者一起看。

**易错点**：
- 只说“用 RAG 解决幻觉”。检索到了模型仍可能不按资料回答，要校验。

## core-safety-005 工具调用失败时怎么重试和降级
- level: 2
- tags: [core, harness]

**一句话答案**：只对超时、限流这类临时错误做指数退避加抖动的有限次重试；写操作带幂等键防止重复执行；下游持续故障时熔断；主路径不可用时按“备用模型 → 固定流程 → 转人工”降级。

**要点**：
- 可重试：超时、限流、服务暂时不可用。不可重试：参数错误、权限错误。
- 幂等键：同一个写请求重试多次，下游只执行一次。
- 补偿：多步操作中途失败，为已完成步骤执行反向操作。
- 熔断：失败率超阈值后暂停调用，定时探测恢复。
- 降级要告诉用户，不要静默返回质量更差的结果。

**追问链**：
1. 下游不支持幂等怎么办？→ 不自动重试写操作；先查询状态确认是否已执行，再决定是否重试，或者交给人工。
2. 模型输出的工具参数格式错误怎么办？→ 把校验错误信息回给模型重新生成，限制次数，超过就降级。

**易错点**：
- 对所有错误无差别重试，导致重复扣款或放大下游故障。

## core-safety-006 给一个能读邮件和日程的办公助手 Agent 设计安全方案
- level: 3
- tags: [core, harness, evaluation]

**一句话答案**：先识别致命三要素并尽量拆开，再用最小授权和分级确认限制动作，用架构手段隔离不可信邮件内容，加输入、调用前、输出三处护栏和审计，最后用注入用例做红队测试并纳入回归。

**要点**：
- 威胁：邮件是不可信内容；邮箱和日程是私有数据；发信、建会邀请外部人员、渲染链接都是外发通道。
- 权限：读信用只读范围；发信、转发、删除要用户确认并展示收件人和正文；以用户自己的 OAuth 范围执行。
- 架构：处理邮件正文的模型不直接拥有发信工具；先按用户请求定好动作，邮件内容只能影响参数（Plan-Then-Execute），或者用 Dual LLM 让有工具的模型不看原文。
- 护栏：输入侧拦越权请求；调用前检查收件人是否在白名单或通讯录；输出侧不渲染外部图片，链接要过白名单。
- 红队：在测试邮件里植入各种注入指令，检查是否触发外发；可以参考 AgentDojo 这类基准的思路建用例；成功的攻击加入回归集，同时测误拦率。

**追问链**：
1. 用户就是要“把这封邮件转给某人”，怎么区分是用户意图还是注入？→ 动作必须来自用户本轮请求，而不是邮件内容；转发前展示收件人和内容让用户确认。
2. 安全措施让任务完成率下降怎么办？→ 安全和效用一起评。CaMeL 论文就同时报了有防御和无防御时的任务完成率。按风险分级，只在高影响动作上加严。
3. 出了事怎么查？→ 审计日志记录每次工具调用的参数、触发它的上下文来源和用户确认记录，能回放出注入从哪封邮件进来。

**易错点**：
- 只加一个注入检测模型就说安全了。
- 只讲安全不讲误拦和任务完成率。

## core-safety-007 Dual LLM 模式漏了什么，CaMeL 怎么补上
- level: 3
- tags: [core, harness]

**一句话答案**：Dual LLM 让有工具的模型不看不可信内容，保住了控制流，但隔离模型抽出的参数仍可被注入替换。CaMeL 让值带来源和读者标签，解释器在调用工具前按策略检查数据流。

**要点**：
- 出处：Debenedetti 等，arXiv 2503.18813，2025-03。Dual LLM 由 Willison 在 2023-04 提出。
- 论文的例子：计划是“找纪要、抽出文档和地址、发送”，注入让隔离模型抽出机密文档和攻击者地址，动作序列没变，参数全被换了。
- 四个部分：P-LLM 只看用户请求、写代码；Q-LLM 无工具，按 schema 解析数据；能力标签记录 sources 和 readers；解释器维护数据流图并执行策略。
- 控制依赖也算依赖：STRICT 模式下，if 条件里用到的值也进入后续调用的依赖。
- 论文报告在 AgentDojo 上完成 77% 的任务，不设防的系统为 84%。

**追问链**：
1. CaMeL 防不住什么？→ 只改文本、不改数据流的攻击（写错总结、诱导点钓鱼链接）；侧信道（循环次数、触发异常、时序）；策略写错或写松时保证不成立。
2. Q-LLM 信息不够时怎么办？→ 返回 have_enough_information 为假，解释器抛错让 P-LLM 改代码；Q-LLM 不能说明缺什么，否则成了注入通道。
3. 错误信息为什么要打码？→ 异常内容可能依赖不可信数据，原样回给 P-LLM 等于把注入带回了特权模型。

**易错点**：
- 以为 Dual LLM 已经足够安全，忽略数据流被篡改。
- 把 CaMeL 的“能力”理解成模型能力，它是安全领域的能力（capability）标签。

## core-safety-008 护栏单次误拦率 2%、会话平均 20 次调用、恶意调用占 1%、召回 95%，用户体验怎么样
- level: 2
- tags: [core, evaluation]

**一句话答案**：约三分之一的会话至少被误拦一次，1−0.98²⁰≈33%；被拦的调用里只有约 32% 真是恶意。攻击者试 20 次，成功概率约 64%。

**要点**：
- 精确率 = p·R / (p·R + (1−p)·F) = 0.0095 / (0.0095 + 0.0198) ≈ 0.32。
- 会话级误拦 = 1 − (1−F)ⁿ，单次数字小，乘上会话长度就大。
- 攻击者重试：至少成功一次 = 1 − Rᵏ；这是“95% 在安全上不及格”的数学含义。
- 改进：确定性规则先拦已知模式，分类器调高阈值；同召回下误拦能降到几分之一（取决于规则覆盖率）。

**追问链**：
1. 只能调阈值时怎么选？→ 扫阈值，同时看召回和会话级误拦，按业务能接受的误拦定点；分类器没有又准又不误拦的阈值。
2. 那分类器护栏还要不要？→ 要，作为降噪和告警层；注入的主防线放在权限和数据流策略上，它们的保证不随攻击者重试次数下降。

**易错点**：
- 只报单次误拦率，不按会话算。
- 忽略基础比例，把召回率当成“拦下的都是坏的”。

## core-safety-009 能力令牌是什么，为什么 Macaroons 式令牌只能收窄不能放宽
- level: 2
- tags: [core, harness]

**一句话答案**：能力令牌把权限绑到一次任务：能调哪些工具、作用于哪些对象、何时过期。Macaroons 用 HMAC 链签名，持有者能追加限制，但删掉任何一条，签名链都对不上。

**要点**：
- 构造：sig_0 = HMAC(根密钥, ID)，sig_i = HMAC(sig_{i−1}, 第 i 条限制)。出处：Birgisson 等，NDSS 2014。
- 加限制只需要当前签名，所以主 Agent 交给子 Agent 前能自己再收窄。
- 根密钥只在发证方（Harness、网关）手里，持有者重算不出删了限制的签名。
- 令牌管“能不能调”，风险分级管“要不要问人”，两者是“与”：用户确认也越不过令牌。

**追问链**：
1. 为什么不直接用用户的 OAuth 令牌？→ 用户有权限不等于这个任务需要；按任务发窄令牌，被注入时损失限制在任务范围内。
2. 令牌放在模型上下文里可以吗？→ 不行。凭据由 Harness 或凭据代理持有，模型只能请求调用，避免被诱导泄露。

**易错点**：
- 把令牌校验交给模型判断。
- 子 Agent 沿用主 Agent 的全部权限。

## core-safety-010 指数退避为什么要加抖动，熔断器的三个状态怎么转换
- level: 2
- tags: [core, harness]

**一句话答案**：不加抖动时同时失败的客户端会在同一时刻再次重试，抖动把重试打散。熔断器 closed 失败达阈值转 open，冷却后转 half_open 放试探，成功回 closed，失败回 open。

**要点**：
- 三种抖动（Brooker，AWS 2015-03-04）：Full = uniform(0, v)；Equal = v/2 + uniform(0, v/2)；Decorrelated = min(cap, uniform(base, 上次 × 3))。
- 文章的模拟结论：不加抖动最差；Equal Jitter 在有抖动的方案里最差；Full 工作量最少但耗时略长。
- 只重试超时、限流、暂时不可用；参数和权限错误直接返回。
- 熔断三态出自 Fowler 的 CircuitBreaker（2014-03-06）；half_open 期间只放试探请求。

**追问链**：
1. 下游挂了 120 秒、每秒 10 个请求、阈值 5、冷却 30 秒，熔断后发出多少请求？→ 5 次触发加 3 次试探，共 8 次；不熔断是 1200 次。
2. 每层都重试会怎样？→ 负载按层数指数放大，三层各 4 次是 64 倍；重试只放一层，加重试预算。

**易错点**：
- 熔断按连续失败次数判定，不看时间窗口和最小请求数。
- 对没有幂等保护的写操作自动重试。
