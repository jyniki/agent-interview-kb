# 题目：后训练入门：SFT 与偏好优化

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## core-post-001 SFT 的 loss 应该算在哪些 token 上
- level: 1
- tags: [core, training]

**一句话答案**：只算模型要生成的部分：每一轮 assistant 的回答和结束符；system、user 和工具返回都屏蔽掉。

**要点**：
- 屏蔽的位置把 label 设成忽略值，loss 只在剩余 token 上平均。
- 屏蔽 user 是因为模型不需要学“怎么写用户的话”，否则可能学会替用户续写。
- 工具返回由环境产生，不是模型的决策，计入 loss 等于让模型去背外部数据。
- 结束符必须算进去，否则模型学不会停。

**追问链**：
1. 多轮对话只算最后一轮行不行？→ 能训，但前面几轮回答没用上，样本效率低。主流是所有 assistant 轮都算。
2. 多条样本 packing 到一条序列里要注意什么？→ 用 attention mask 隔开不同样本，避免互相看见；按 token 平均时长样本权重更大，要清楚自己想要哪种平均。
3. 工具调用那段（模型输出的函数名和参数）算不算？→ 算。那是模型的决策；不算的是工具执行后返回的结果。

**易错点**：
- 只记得屏蔽 prompt，忘了屏蔽工具返回。
- 漏掉结束符，导致推理时停不下来。

## core-post-002 chat template 是什么，训练和推理不一致会怎样
- level: 1
- tags: [core, training, inference]

**一句话答案**：chat template 把消息列表拼成带角色标记和结束符的 token 序列；训练和推理用的模板不一致，模型就会看到训练时没见过的格式，效果明显变差。

**要点**：
- 不同模型的模板不同，同一基座微调出的模型也可能不同，例如一个用 `[INST]`，一个用 `<|user|>`。
- 训练预处理设 `add_generation_prompt=False`；推理时设 True，在末尾追加“助手开始回答”的标记。
- 模板一般已含特殊 token，先拼字符串再分词时要关掉分词器自动加特殊 token，避免 BOS 重复。

**追问链**：
1. 推理时忘了 `add_generation_prompt` 会怎样？→ 对需要这个标记的模型，可能接着用户的话往下写，而不是开始回答。
2. 怎么快速发现模板问题？→ 把训练样本和推理请求都 decode 成字符串对比，检查角色标记、换行和特殊 token 是否逐字一致。

**易错点**：
- 以为模板只是“显示格式”，不影响模型行为。

## core-post-003 LoRA 的原理是什么，它省的是什么
- level: 2
- tags: [core, training]

**一句话答案**：冻结原权重，只训练一个低秩增量 ΔW = BA；省的是梯度和优化器状态的显存以及每个任务的存储，前向反向的计算和激活基本不省。

**要点**：
- 前向：`h = W₀x + BAx`，r 远小于 d 和 k，再乘缩放 α/r。
- 初始化：A 随机高斯，B 为 0，训练开始时 ΔW = 0。
- 推理前可合并 `W = W₀ + BA`，不加延迟。
- 原论文摘要：相对 Adam 全参微调 GPT-3 175B，可训练参数少约 10000 倍，显存少约 3 倍。

**追问链**：
1. 为什么 B 初始化为 0 而不是两个都随机？→ 保证起点就是原模型，训练从原模型出发平滑地改；两个都随机会在第一步就给模型加噪声。
2. LoRA 加在哪些矩阵上？→ 原论文多数实验只加在 Wq 和 Wv；实践中常扩展到所有线性层，需要看任务和预算。
3. QLoRA 又多做了什么？→ 把冻结的基座量化成 4 bit NF4，梯度穿过量化基座流到 LoRA；论文报告单张 48GB GPU 可微调 65B 模型。

**易错点**：
- 说 LoRA“训练更快”。每步计算量没少多少，主要省的是显存和存储。

## core-post-004 讲一下 InstructGPT 的 RLHF 流程
- level: 1
- tags: [core, training]

**一句话答案**：三步：用人工示范做 SFT；对同一 prompt 的多个回答人工排序，训练奖励模型；用 PPO 在奖励上优化策略，并用对 SFT 的 KL 惩罚拉住它。

**要点**：
- 奖励模型 loss：`−log σ(r(x,y_w) − r(x,y_l))`，K 个回答拆成 C(K,2) 对一起训，论文 K 在 4 到 9 之间。
- RL 目标：奖励减去 `β·log(π^RL/π^SFT)`，再可选加 γ 倍预训练数据的对数似然（PPO-ptx）。
- PPO-ptx 用来减轻对齐税，即对齐后部分公开任务掉点。
- 人工评测中 1.3B 的 InstructGPT 比 175B 的 GPT-3 更受偏好。

**追问链**：
1. 为什么要 KL 惩罚？→ 奖励模型只在 SFT 分布附近可信，策略跑远了会钻奖励模型的空子（reward hacking）；KL 让策略留在奖励模型可信的区域。
2. 为什么用排序而不是直接打分？→ 人对绝对分数的标准不一致，比较两个回答哪个好更稳定。
3. 奖励模型多大？→ 论文只用了 6B，说这样省算力，并提到 175B 奖励模型训练可能不稳定。

**易错点**：
- 把 KL 项说成“对参考模型的正则化”就停住，说不出它防的是 reward hacking。

## core-post-005 从 RLHF 的目标推导 DPO 的 loss
- level: 3
- tags: [core, training]

**一句话答案**：KL 约束的奖励最大化有闭式最优解，反解出奖励等于 β 倍对数比加 β·log Z(x)；代入只看奖励差的 Bradley-Terry 模型后 Z(x) 抵消，得到只含策略和参考模型的分类 loss。

**要点**：
- 目标：`max E[r(x,y)] − β·D_KL[π ‖ π_ref]`。
- 最优解：`π*(y|x) = π_ref(y|x)·exp(r(x,y)/β) / Z(x)`。
- 反解：`r(x,y) = β·log(π*/π_ref) + β·log Z(x)`。
- 代入 `σ(r(y_w) − r(y_l))`，Z(x) 相减消去：`L = −log σ(β·log(π_θ(y_w)/π_ref(y_w)) − β·log(π_θ(y_l)/π_ref(y_l)))`。
- 论文默认 β = 0.1。

**追问链**：
1. 为什么不能直接用闭式解？→ Z(x) 要对所有可能回答求和，算不出来；DPO 的关键是让它在比较中抵消。
2. DPO 的梯度有什么特点？→ 每个样本乘以 `σ(r̂(y_l) − r̂(y_w))`，模型排错的对权重更大；论文报告去掉这个权重模型会退化。
3. π_ref 用什么？→ 优先用 SFT 模型，因为偏好数据是从它采的；没有时先在好回答上做一次最大似然微调，减小分布偏移。
4. β 大小意味着什么？→ β 越大，越不允许偏离参考模型；越小越激进地拟合偏好。

**易错点**：
- 推到最后忘了说明 Z(x) 为什么能消掉。
- 说 DPO“没有奖励”。它有隐式奖励 `β·log(π_θ/π_ref)`，只是不单独训练奖励模型。

## core-post-006 DPO 和 PPO 式 RLHF 怎么选
- level: 2
- tags: [core, training]

**一句话答案**：DPO 离线、简单、只需策略和参考两个模型，适合已有高质量偏好对的场景；PPO 在线采样、更复杂，但能在当前策略的分布上持续学，奖励可以来自规则或模型。

**要点**：
- DPO 不需要训练时采样，不需要奖励模型和价值模型。
- DPO 的局限：只能学数据里出现过的对比；数据是旧模型采的，和当前策略分布差得越远效果越差。
- PPO 的代价：同时维护策略、参考、奖励、价值四个模型，调参难。
- 折中：用当前策略反复采样、打分、重组偏好对，再跑 DPO（在线或迭代 DPO），见 [training/02](../../tracks/training/02-preference-optimization/README.md)。

**追问链**：
1. 如果任务有可验证的奖励（如代码测试），倾向哪种？→ 倾向在线 RL：奖励可以实时算，不需要人工偏好对。GRPO 这类方法省掉价值模型，见 [training/03](../../tracks/training/03-grpo-family/README.md)。
2. DPO 训练时 chosen 的对数概率也在下降，正常吗？→ 常见现象。loss 只要求两者的差拉开，不保证 chosen 本身上升。Pal 等（arXiv 2402.13228，2024-02）从理论上说明了这一点，并观察到在 chosen 和 rejected 编辑距离小的数据上更明显，提出了 DPO-Positive。要监控，严重时会伤到生成质量。

**易错点**：
- 认为 DPO 在所有情况下都等价于 RLHF。等价只在最优解层面成立，实际受数据分布和优化过程影响。

## core-post-007 偏好数据怎么构造，有哪些坑
- level: 2
- tags: [core, training, evaluation]

**一句话答案**：来源有人工排序、强模型当评委、可验证结果和自采样打分；主要的坑是 chosen 和 rejected 分布差太大、长度差系统性存在、标签噪声和评测集污染。

**要点**：
- 人工：贵、慢，标注一致性有限。
- 模型评委：便宜，但继承评委偏好，如偏爱长回答、偏爱某个位置。
- 可验证：通过测试或答案比对的当 chosen，只适用于能自动判对错的任务。
- 自采样：贴近当前策略分布，但打分器偏差会被放大。

**追问链**：
1. chosen 全来自强模型、rejected 全来自弱模型有什么问题？→ 模型可能只学到两种模型的风格差异，而不是质量差异。尽量让两者来自同一个策略的不同采样。
2. 怎么发现长度偏差？→ 统计 chosen 和 rejected 的长度分布；训练后看输出长度是否持续上涨而质量没涨。
3. 用模型评委时怎么降低位置偏差？→ 交换两个回答的顺序各判一次，不一致的丢掉或记为平局。

**易错点**：
- 只谈数据量，不谈 chosen 和 rejected 的可比性。

## core-post-008 SFT 里 packing 多条样本到一条序列，要改哪些地方
- level: 2
- tags: [core, training]

**一句话答案**：注意力 mask 改成按样本隔开的块对角，位置编号在每条样本开头重置，每条样本首个 label 置为忽略值；还要意识到 loss 从按样本平均变成了按 token 平均。

**要点**：
- 只用因果 mask 时，后面的样本能看见前面样本的 token，输出和单独跑时不同，即交叉污染；加分隔符解决不了。
- 位置不重置时，即使隔开了注意力，绝对位置编码不同，输出仍不同。
- 错位后，前一条结束符的“下一个 token”是后一条的开头，这个位置不该产生 loss。
- 按 token 平均时长样本权重更大：1 个 token 和 9 个 token 的两条样本，短样本权重从 1/2 降到 1/10。

**追问链**：
1. 怎么验证 packing 写对了？→ 把 packed 序列里的某条样本单独前向一次，logits 应和 packed 时逐元素一致。
2. 用 FlashAttention 时边界从哪来？→ 变长接口需要每条样本的累计长度（cu_seqlens），可由在样本开头归零的 position_ids 推出；后端不认这个边界时会静默退化成只有因果 mask。
3. 梯度累积会带来什么问题？→ 每个 micro-batch 除以自己的 token 数再平均，等于按 micro-batch 平均；应除以整个 batch 的全局 token 数。

**易错点**：
- 只改了 attention mask，忘了重置位置。
- 以为打开 packing 只影响吞吐，不影响 loss 的含义。

## core-post-009 LoRA 为什么用 A 随机、B 为 0 初始化，α/r 缩放起什么作用
- level: 2
- tags: [core, training]

**一句话答案**：B 为 0 让起点等于原模型，A 随机保证 B 的梯度不为 0；两个都为 0 则梯度恒为 0 训不动。α/r 让改变秩 r 时第一步的更新幅度基本不变，少重调学习率。

**要点**：
- ∂L/∂B = (α/r)·G·(Ax)ᵀ 含 A，∂L/∂A = (α/r)·Bᵀ·G·xᵀ 含 B；B = 0 时第一步只有 B 在动。
- Adam 的更新近似“学习率 × 符号”，与梯度大小无关；输出改变量约 lr·(α/r)·‖Ax‖₁，‖Ax‖₁ 随 r 线性增长，乘 1/r 抵消。
- 论文：调 α 和调学习率大致等价，所以把 α 设为第一个尝试的 r，不再调。
- PEFT 默认 `scaling = lora_alpha / r`，rsLoRA 改为 `lora_alpha / sqrt(r)`。

**追问链**：
1. 两个都随机初始化会怎样？→ BA ≠ 0，训练开始前模型就被加了随机扰动，起点不再是原模型。
2. 合并后为什么推理不加延迟？→ W = W₀ + (α/r)·BA 和 W₀ 同形状，前向逐元素等价；代价是合并后不同 adapter 的请求不能放进同一个 batch。
3. GPT-3 175B 上 r = 4、只加 Wq 和 Wv，可训练参数多少？→ 96 层 × 2 × 4 × (12288 + 12288) ≈ 1887 万，约是 175B 的万分之一。

**易错点**：
- 说成“A 为 0、B 随机”，方向记反（虽然对称也能训，但不是论文写法）。
- 把 α/r 说成正则项。它只是缩放，不改变可表达的增量空间。

## core-post-010 InstructGPT 为什么把一个 prompt 的 C(K,2) 个比较放在同一个 batch 元素里
- level: 2
- tags: [core, training]

**一句话答案**：同一排序拆出的对高度相关，打散后每个回答被用于 K−1 次独立更新，奖励模型一个 epoch 就过拟合；成组时 K 个回答各前向一次，比每对两次前向省算力。

**要点**：
- loss 是 −1/C(K,2)·E[log σ(r(y_w) − r(y_l))]，K 在 4 到 9 之间。
- K = 9 时 36 对：成组 9 次前向，打散 72 次。
- 论文附录 C.2：batch 64 个 prompt，最多 2304 对；平局丢弃；只训 1 个 epoch。
- loss 只看奖励差，奖励只定义到一个常数；RL 前加偏置，让示范回答平均分为 0。

**追问链**：
1. Bradley-Terry loss 对奖励差 Δ 的导数是什么？→ −σ(−Δ)；已排对且拉开的对梯度接近 0，排错的对接近 −1。
2. 奖励模型验证准确率为什么到不了 1？→ 标注员之间本来就不完全一致，标签有噪声，准确率上限由它决定。
3. 为什么奖励模型只用 6B？→ 省算力，且 175B 奖励模型训练不稳定，不适合初始化 PPO 的价值函数。

**易错点**：
- 只说“为了效率”，漏掉过拟合这个主要原因。

## core-post-011 DPO 训练中 chosen 和 rejected 的 log 概率都在下降、loss 却在降，原因和对策是什么
- level: 3
- tags: [core, training]

**一句话答案**：loss 只约束两者对数比之差，rejected 降得更多就行；编辑距离小的对还会压低差异 token 之后的正确 token。对策：单独监控 chosen，用 DPOP 或加 NLL 项。

**要点**：
- β = 0.1 时，chosen 降 5 nats、rejected 降 20 nats，margin 从 0 增到 1.5，loss 从 0.693 降到 0.201。
- 梯度对 chosen 和 rejected 大小相等、方向相反，权重是 σ(r̂(y_l) − r̂(y_w))。
- Pal 等（arXiv 2402.13228）：只差一个 token 的对，在之后的位置上 log π(y_w) − log π(y_l) 对 logits 的梯度是 s_l − s_w，会压低正确 token 的 logit。
- DPOP 在 σ 内减去 λ·max(0, log π_ref(y_w)/π_θ(y_w))，论文默认 β = 0.3、λ = 50。

**追问链**：
1. 这一定是坏事吗？→ 不一定。原始 RLHF 只说 y_w 比 y_l 好；但 chosen 本身是合格答案时，概率下降意味着离开好答案，会伤生成质量。
2. 训练时看哪些指标？→ chosen 和 rejected 的隐式奖励分开画，加上 chosen 的 log 概率；只看 margin 和准确率会漏掉。
3. 去掉梯度里的权重项会怎样？→ 变成提高 y_w、压低 y_l 的 unlikelihood 式目标，DPO 论文报告模型会退化，输出变成重复的词。

**易错点**：
- 以为 loss 下降就说明 chosen 概率在上升。
