## core-llm-001 BPE 分词是怎么工作的，词表大小怎么取舍
- level: 1
- tags: [core, training]

**一句话答案**：BPE 从字符或字节出发，反复把最高频的相邻对合并成新 token，直到词表达到目标大小；词表大则序列短、推理快，但嵌入层和输出层变大，低频 token 训练不足。

**要点**：
- 出处：Sennrich 等，arXiv 1508.07909，用于解决机器翻译里的生僻词问题。
- 字节级 BPE 在 UTF-8 字节上做，任何字符串都能编码，没有未登录词。
- SentencePiece 直接在原始句子上训练，不依赖按空格预分词，适合中文、日文。
- 公开例子：Llama 3 词表 128K，英语样本上每 token 字符数从 Llama 2 的 3.17 提高到 3.94。

**追问链**：
1. 为什么中文在一些模型上特别费 token？→ 训练语料里中文少，高频合并对少，中文会被切成很碎的字节片段。扩词表、加中文语料可以改善。
2. 这对 Agent 有什么影响？→ 预算、截断、计费都按 token 算。同一段内容在不同模型上 token 数不同，预算要用目标模型的 tokenizer 实测。
3. 特殊 token 有什么用？→ 标记角色、轮次、工具调用的起止，是模型和推理框架之间的协议。模板拼错会导致角色混淆或不停输出。

**易错点**：
- 说“token 就是词”。一个词可以是多个 token，一个 token 也可以跨越空格。

## core-llm-002 写出注意力公式，为什么要除以 √d_k
- level: 1
- tags: [core]

**一句话答案**：`softmax(QKᵀ/√d_k)·V`；Q 和 K 内积的方差随维度增长，不缩放的话打分过大，softmax 接近 one-hot，梯度变小。

**要点**：
- `QKᵀ` 是每对 token 的相关度，softmax 后作为权重对 V 加权求和。
- 解码器加因果掩码，每个位置只看自己和之前的位置。
- 多头：把向量切成多个头，各自算注意力再拼接，让不同头学不同的关注模式。
- 打分矩阵是 n × n，计算和显存随序列长度平方增长。

**追问链**：
1. 为什么方差随维度增长？→ 假设 Q、K 各分量独立、均值 0、方差 1，内积是 d_k 项之和，方差是 d_k，除以 √d_k 后方差回到 1。
2. 平方复杂度对 Agent 意味着什么？→ 上下文越长越贵、越慢。工具结果不加裁剪地堆进上下文，代价会快速上升。
3. 注意力本身知道 token 顺序吗？→ 不带掩码的注意力是置换等变的，不知道顺序；因果掩码会带来隐式位置信息（NoPE 模型也能训练），但实践中仍加显式位置编码。

**易错点**：
- 说除以 √d_k 是“为了归一化概率”。概率归一化是 softmax 做的，缩放是为了控制打分的尺度。

## core-llm-003 MHA、MQA、GQA 有什么区别，为什么要减少 KV 头
- level: 2
- tags: [core, inference]

**一句话答案**：MHA 每个查询头配一组 K、V；MQA 所有查询头共享一组；GQA 分组共享，组数介于两者之间。减少 KV 头是为了缩小 KV Cache，缓解解码时的显存带宽瓶颈。

**要点**：
- 解码每一步都要读出全部历史 K、V，瓶颈常在显存带宽而不是算力。
- MQA（Shazeer，arXiv 1911.02150）解码最快，质量有一定损失。
- GQA（Ainslie 等，arXiv 2305.13245）质量接近 MHA、速度接近 MQA；论文用原预训练算力的 5% 把 MHA 模型继续训练成 MQA 或 GQA。
- MLA（DeepSeek-V2）把 K、V 压成低维潜向量缓存，论文报告比 DeepSeek 67B 的 KV Cache 减少 93.3%。

**追问链**：
1. GQA 能省多少？→ KV Cache 按 KV 头数比例缩小。Llama 3 8B 有 32 个查询头、8 个 KV 头，比同结构 MHA 小 4 倍。
2. 已经训好的 MHA 模型能改成 GQA 吗？→ 可以。GQA 论文把同组 K、V 头的参数做均值池化，再用少量算力继续训练。

**易错点**：
- 以为 MQA、GQA 减少的是计算量。主要减少的是 KV Cache 的显存和读取带宽。

## core-llm-004 RoPE 的原理是什么，PI 和 YaRN 怎么做长度扩展
- level: 2
- tags: [core, training]

**一句话答案**：RoPE 按位置把 Q、K 的每两维旋转一个角度，旋转后内积只依赖相对距离；PI 把位置下标线性缩小到训练范围内，YaRN 按频率分段插值并加注意力温度修正。

**要点**：
- RoPE 出处：Su 等，arXiv 2104.09864。用旋转矩阵编码绝对位置，同时在注意力里得到显式的相对位置依赖。
- 不同维度对的旋转频率不同，底数 θ 控制频率范围；Llama 3 用 θ = 500,000。
- PI（Chen 等，arXiv 2306.15595）把 LLaMA 扩到 32768，微调不到 1000 步。
- YaRN（Peng 等，arXiv 2309.00071）称所需 token 比此前方法少 10 倍、训练步数少 2.5 倍。
- ALiBi 是另一条路：不加位置向量，按距离给注意力打分加线性惩罚。

**追问链**：
1. 为什么 RoPE 直接外推会变差？→ 超过训练长度后，低频维度会出现训练时没见过的旋转角度，注意力打分分布偏离训练分布。PI 论文指出外推可能产生极大的注意力分数。
2. PI 的代价是什么？→ 所有位置被同比例压缩，高频维度里相邻位置的区分度也被压小，所以需要微调恢复。YaRN 的分段处理就是为了少动高频维度。
3. 模型宣称支持 128K，就能用好 128K 吗？→ 不一定。要区分原生训练长度、外推支持长度和有效利用长度，后者要用“大海捞针”或多跳检索类测试实测。

**易错点**：
- 说 RoPE 是“相对位置编码，所以天然能外推”。它的内积只依赖相对距离，但训练外的角度仍会让效果退化。

## core-llm-005 Kaplan 和 Chinchilla 的 Scaling Law 结论有什么不同
- level: 2
- tags: [core, training]

**一句话答案**：Kaplan 发现 loss 随参数、数据、算力呈幂律下降，建议算力优先给大模型；Chinchilla 发现给定算力时参数量和 token 数应同比例增长，当时的大模型普遍训练不足。

**要点**：
- Kaplan 等（arXiv 2001.08361）：宽深比在较大范围内影响不大；大模型更省样本，可以不训到收敛。
- Hoffmann 等（arXiv 2203.15556）：模型大一倍，训练 token 也要多一倍。
- 代表结果：70B 的 Chinchilla 用 1.4T token，和 280B 的 Gopher 算力相同。
- “每参数约 20 token”来自 1.4T ÷ 70B，是经验比例。

**追问链**：
1. 为什么现在很多模型训练 token 远超 20 倍参数？→ Chinchilla 只优化训练算力。模型要服务大量请求时，推理成本占大头，用更多数据训练更小的模型更划算。
2. Scaling Law 能预测下游任务效果吗？→ 它拟合的是预训练 loss。loss 和下游指标的关系不一定平滑，需要单独评测。

**易错点**：
- 把“20 token / 参数”说成定律，或说成 Kaplan 的结论。

## core-llm-006 温度、top-k、top-p 分别怎么影响输出，温度设 0 为什么还会不一致
- level: 2
- tags: [core, inference]

**一句话答案**：温度缩放 logits 控制分布尖锐程度，top-k 只保留前 k 个，top-p 只保留累计概率到 p 的最小集合；温度 0 不一致的主因是推理内核缺少批不变性，批大小随负载变化导致数值结果变化。

**要点**：
- 温度：logits 除以 T，T 小于 1 更确定，大于 1 更发散。
- top-p 出自 Holtzman 等（arXiv 1904.09751），截掉不可靠的长尾，同时保留多样性；论文指出最大似然解码会产生平淡、重复的文本。
- Thinking Machines（2025-09）：浮点加法不满足结合律，计算顺序随批大小变化，概率接近时会选出不同 token。批不变内核下 1000 次生成全部一致，否则出现 80 种结果。

**追问链**：
1. Agent 里工具参数生成用什么设置？→ 低温或贪心，配合结构化输出约束，减少格式错误。
2. 想复现线上一次失败，靠固定 seed 和温度 0 够吗？→ 不够。服务端批处理会引入差异。可靠的做法是记录完整轨迹，按记录回放工具结果。
3. 什么时候需要较高温度？→ 需要多样候选时，例如多次采样投票，或生成多个方案再筛选。

**易错点**：
- 把温度 0 不一致归因于“GPU 并发随机”。按这篇博客的分析，前向计算本身通常是逐次确定的，变化来自批大小。

## core-llm-007 KV Cache 为什么存在，怎么估算它的大小
- level: 2
- tags: [core, inference, harness]

**一句话答案**：历史 token 的 K、V 不会变，缓存下来避免每步重算；大小等于 2 × 层数 × KV 头数 × 头维度 × 元素字节数 × 序列长度 × 并发数。

**要点**：
- 推理分两段：Prefill 并行处理输入，受算力限制；Decode 每步一个 token，要读完整个 KV Cache，受显存带宽限制。
- 例子：Llama 3 8B，32 层、8 个 KV 头、头维度 128、FP16，每 token 128 KiB，8K 上下文约 1 GiB。
- 同结构改成 MHA 是每 token 512 KiB，这就是 GQA、MLA 要省的部分。
- Agent 每步追加工具结果，KV Cache 随步数增长；稳定的前缀可以被缓存复用。

**追问链**：
1. 一张 80 GB 的卡跑这个 8B 模型，32K 上下文能并发几个请求？→ 统一用 GB。按 [inference/01](../../tracks/inference/01-kv-cache-memory/README.md) 的假设：引擎可用 90%（72 GB），扣权重约 16 GB 和预留 4 GB，剩约 52 GB；每个 32K 请求 131,072 B × 32,768 ≈ 4.3 GB，52 / 4.3 ≈ 12 个。
2. 显存不够时有哪些方向？→ 减少 KV 头（GQA、MLA）、KV 量化、分页管理减少碎片、淘汰或压缩旧 token。这些属于 inference 方向，见 [inference/01 KV Cache 与显存估算](../../tracks/inference/01-kv-cache-memory/README.md)。
3. 这对 Agent 的上下文设计有什么约束？→ 工具结果要裁剪；系统提示和工具定义放在前面并保持不变，才能命中前缀缓存；中途改动前缀会让之后的缓存全部失效。

**易错点**：
- 公式漏掉系数 2（K 和 V 各一份），或用查询头数代替 KV 头数。
- 只算单请求，忘了乘并发数。

## core-llm-008 BPE 编码一个新词时为什么要按合并规则的顺序，不能取最长匹配
- level: 2
- tags: [core]

**一句话答案**：训练时片段是按合并顺序一步步长出来的，编码要每次合并 rank 最小的相邻对才能复现同样的切分；最长匹配会先吃掉别的片段，切出训练时没见过的序列。

**要点**：
- 训练：按词频统计相邻对，合并最高频的一对，记下规则，重复到目标次数；词表大小 = 初始符号数 + 合并次数（Sennrich 等，3.2 节）。
- 编码：每轮在当前序列里找规则表 rank 最小的相邻对合并，GPT-2 的 `encoder.py` 用 `min(pairs, key=bpe_ranks.get)`。
- 反例：玩具语料上学到 es、est、est</w>、ne 等规则。`nest` 按 rank 得 n + est</w>；最长匹配先取 ne，剩下 s、t、</w> 合不上，变成 4 个 token。
- 词表越大序列越短，但嵌入参数变多，尾部 token 训练不足，可能成为 glitch token。

**追问链**：
1. 训练时为什么不统计跨词的相邻对？→ 论文为了效率，可以直接在“词 → 频次”字典上训练；跨词合并也会让切分依赖上下文。
2. 字节级 BPE 解决了什么，代价是什么？→ 初始符号是 256 个字节，任何字符串都能编码；训练语料里少见的文字会被切到字节级，一个汉字可能要 3 个 token。
3. 同一个词在不同位置切法会不同吗？→ 会。词尾符号或前导空格不同，切分就不同，所以先拼接再分词和分别分词再拼接，token 序列可能不一样。

**易错点**：
- 以为编码是“在词表里找最长的已知片段”。

## core-llm-009 RoPE 的内积为什么只依赖相对位置，为什么超过训练长度仍会退化
- level: 3
- tags: [core, training]

**一句话答案**：把每两维看成复数并乘 e^{imθ}，内积变成 Re[q̃·conj(k̃)·e^{i(m−n)θ}]，只剩 m−n；但低频维度波长超过训练长度，训练中没转满一圈，推理时出现没见过的角度。

**要点**：
- 旋转是正交变换，R(m)ᵀR(n) = R(n−m)；各维度对的内积都只依赖 m−n，求和也是。
- 频率 θ_i = base^(−2i/d_h)：第 0 对波长约 6.3 个 token，最后一对接近 2π·base。
- d_h = 128、base = 10000、训练长度 4096 时，64 对里有 18 对转不满一圈（推导）。
- PI 把所有频率压小 s 倍；NTK-aware 改底数让最高频不变、最低频压小 s 倍；YaRN 按 r = L/λ 分段，高频不动、低频按 PI 插值，再加注意力温度。

**追问链**：
1. PI 为什么需要微调？→ 最高频维度上相邻 token 的角度差从 1 弧度变成 1/s 弧度，近邻 token 难以区分。
2. YaRN 的注意力温度怎么实现才没有开销？→ 把 q、k 都乘 √(1/t)，等价于打分乘 1/t，可以并进 RoPE 的 cos、sin 表；论文推荐 √(1/t) = 0.1·ln(s) + 1。
3. Hugging Face 的 rotate_half 和论文写法一样吗？→ 一个是前后两半配对，一个是相邻两维配对，数学等价但权重排列不同，转换原始权重时要对 W_Q、W_K 做 permute。

**易错点**：
- 说“RoPE 是相对位置编码，所以天然能外推”。

## core-llm-010 已知 Llama 3 8B 的 32 层、d=4096、32 个查询头、8 个 KV 头、d_ff=14336、词表 128,256，估算参数量和每 token 前向 FLOPs
- level: 2
- tags: [core, training, inference]

**一句话答案**：每层注意力 2.5d²、SwiGLU 10.5d²，共 13d²，32 层约 7B，加嵌入和输出头约 8.03B；前向每 token 约 2 倍矩阵乘参数，约 15 GFLOPs，长上下文另加注意力。

**要点**：
- 经典的每层 12d² 假设 MHA（4d²）和 d_ff = 4d 的两矩阵 FFN（8d²）；GQA 和 SwiGLU 让它变成 13d²，套 12d² 低估约 8%。
- 嵌入 V·d 和输出头 d·V 不共享，合计 1.05B，占 13%，不能忽略。
- 2N：每个参数每 token 一次乘加记 2 FLOPs；输入嵌入是查表不算，输出头要算。
- 注意力打分和加权每 token 约 4·L·d·T，8K 位置上约 4.3 GFLOPs，占前向约 22%（推导）。
- 训练约 6N 每 token（反向约前向 2 倍），总算力 C ≈ 6ND。

**追问链**：
1. d_ff = 14336 怎么来的？→ 4d 取 2/3（三个矩阵和两矩阵 FFN 参数对齐），乘 ffn_dim_multiplier 1.3，再向上取整到 1024 的倍数。
2. Kaplan 的前向式子注意力项系数为什么是 2 而不是 4？→ 它按因果 mask 下平均每个位置只看一半上下文，把 Σ_t 4·L·d·t 摊到每个 token 就是 2·L·d·T。
3. 怎么确认自己的估算没漏项？→ 按 config 精确数参数，和模型卡或 safetensors 的参数总数对到个位；漏偏置、head_dim、是否共享嵌入都会对不上。

**易错点**：
- 把 2N 里的 N 和“不含嵌入的 N”混用，或者忘了输出头的矩阵乘。

## core-llm-011 为什么 Pre-LN 比 Post-LN 好训练，RMSNorm 和 SwiGLU 各改了什么
- level: 2
- tags: [core, training]

**一句话答案**：Pre-LN 只归一化子层输入，残差恒等路径直通，初始化时梯度稳定，可不用 warm-up；RMSNorm 去掉减均值和偏置；SwiGLU 用 SiLU 门控，宽度取 2/3 保持参数量。

**要点**：
- Post-LN：h = LN(h + Sublayer(h))；Pre-LN：h = h + Sublayer(LN(h))，最后再加一个 LN。
- Xiong 等（arXiv 2002.04745）证明 Post-LN 初始化时输出层附近梯度期望大，需要 warm-up；Pre-LN 去掉 warm-up 也能达到可比效果。
- Pre-LN 的代价：残差流范数随深度增长，深层子层贡献相对变小。
- RMSNorm（Zhang、Sennrich）：x / RMS(x) · g，保留缩放不变、去掉平移不变，论文报告提速 7% 到 64%。
- SwiGLU（Shazeer 2020）：三个矩阵，d_ff 缩到 2/3，和原 FFN 参数、计算对齐。

**追问链**：
1. Llama 里的 post_attention_layernorm 是 Post-LN 吗？→ 不是。它作用在 FFN 子层的输入上，名字指“注意力之后”，结构仍是 Pre-LN。
2. RMSNorm 为什么要在 float32 下算？→ 平方求均值在 BF16 下误差累积，Hugging Face 的实现先转 float32 再转回。
3. x 的均值为 0 时 RMSNorm 和 LayerNorm 有什么关系？→ 两者相等（不计偏置和 ε），区别只在是否减均值。

**易错点**：
- 说 Pre-LN “没有缺点”，或者把除以 √d_k 当成归一化层的作用。
