# 题目：强化学习入门：从策略梯度到 PPO

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## core-rl-001 把 LLM 生成写成 MDP，状态、动作、奖励分别是什么
- level: 1
- tags: [core, training]

**一句话答案**：状态是 prompt 加已生成的 token，动作是下一个 token，转移是把 token 拼到末尾，奖励通常只在序列结尾给一次。

**要点**：
- 单轮生成的转移是确定的；Agent 多轮里工具返回由环境决定，转移有随机性。
- 折扣 γ 常取 1。
- 也可以把整段回答当一个动作，问题退化成上下文赌博机。

**追问链**：
1. token 级和序列级建模有什么区别？→ token 级需要给每个中间 token 估优势，通常要价值模型；序列级只需要一个回答级的基线，可以用多次采样的平均奖励代替。
2. Agent 场景里工具返回算动作吗？→ 不算。它是环境写回的工具结果，计算策略梯度时要屏蔽这些 token。

**易错点**：
- 把整个对话历史当成“动作”，说不清 token 级和序列级两种视角。

## core-rl-002 策略梯度为什么可以减去基线，基线有什么要求
- level: 2
- tags: [core, training]

**一句话答案**：只依赖状态的基线乘以得分函数后期望为 0，所以减去它不改变梯度期望，只降低方差；基线不能依赖当前动作。

**要点**：
- 推导：`E_a[∇log π(a|s)·b(s)] = b(s)·∇Σ_a π(a|s) = b(s)·∇1 = 0`。
- 常用基线是状态价值 V(s)，减去后得到优势 A = Q − V。
- 直觉：不减基线时，所有正奖励动作都被推高；减去后只有比平均好的才被推高。

**追问链**：
1. 基线依赖动作会怎样？→ 上面的求和不能把 b 提到外面，期望不再为 0，梯度有偏。
2. LLM 里常用什么当基线？→ PPO 用 critic 的 V；RLOO 用同一 prompt 其他 k−1 个样本的平均奖励；GRPO 用组内均值，并除以组内标准差（Dr. GRPO 去掉了标准差，见 [training/03](../../tracks/training/03-grpo-family/README.md)）。
3. reward-to-go 为什么也能降方差？→ 当前动作影响不了它之前的奖励，那部分只贡献噪声，去掉不改变期望。

**易错点**：
- 只说“减基线降方差”，证明不出为什么无偏。

## core-rl-003 GAE 是什么，λ 怎么影响偏差和方差
- level: 2
- tags: [core, training]

**一句话答案**：GAE 是各步 TD 残差的指数加权和 `Σ (γλ)^l δ_{t+l}`；λ = 0 只看一步 TD，方差低但 V 不准时有偏，λ = 1 是蒙特卡洛回报减基线，无偏但方差高。

**要点**：
- TD 残差：`δ_t = r_t + γV(s_{t+1}) − V(s_t)`。
- 从后往前递推：`A_t = δ_t + γλ·A_{t+1}`；critic 的回归目标是 `A_t + V(s_t)`。
- GAE 论文：λ < 1 只在价值函数不准时引入偏差；实验中最优 λ 明显小于最优 γ。
- PPO 论文 MuJoCo 实验用 γ = 0.99、λ = 0.95。

**追问链**：
1. LLM 只有结尾奖励时，GAE 会怎样？→ 中间步 r_t 为 0，优势全靠 V 的差值传播；V 训不准时偏差大。这是很多 LLM RL 方法去掉 critic 的原因之一。
2. γ 和 λ 的作用有什么不同？→ γ 定义了要优化的目标本身（多看重远期奖励）；λ 只影响优势估计的偏差方差折中。

**易错点**：
- 把 λ 说成折扣因子。

## core-rl-004 PPO 的 clip 目标是什么，为什么要取 min
- level: 2
- tags: [core, training]

**一句话答案**：目标是比率乘优势与 clip 后比率乘优势取 min；clip 让比率超出 [1−ε, 1+ε] 后不再获益，min 让目标成为未 clip 目标的下界，只拦有利方向走太远的更新，不拦纠错的更新。

**要点**：
- 公式：`L = E[min(r·Â, clip(r, 1−ε, 1+ε)·Â)]`。
- `r_t = π_θ(a_t|s_t) / π_old(a_t|s_t)`，一批数据可以复用多个 epoch。
- Â > 0：r 超过 1+ε 后梯度为 0；Â < 0：r 低于 1−ε 后梯度为 0。
- 如果 Â > 0 但 r 已经小于 1−ε，min 取未 clip 项，梯度照常，可以拉回来。
- 论文建议 ε = 0.2，其 MuJoCo 对比中这个设置平均分最高。

**追问链**：
1. 不加 clip 直接多轮优化 `r·Â` 会怎样？→ 比率会被推得很远，更新过大，策略崩掉。论文 MuJoCo 实验里“不 clip 也不加惩罚”的设置平均分为负。
2. 完整 loss 还有哪些项？→ 共享参数时加价值损失 `−c1·(V − V^targ)^2` 和熵奖励 `+c2·S`；论文 Atari 用 c1 = 1、c2 = 0.01。
3. clip 能严格保证新旧策略差距吗？→ 不能。它只去掉了继续推动的梯度，多个 epoch 后比率仍可能超出范围；实践中会监控 KL 或 clip 比例，超标就提前停止本轮更新。

**易错点**：
- 以为 clip 是把比率硬截断、两个方向都拦。min 的作用是让变坏的方向不被拦。

## core-rl-005 PPO 的 clip、KL 惩罚和对参考模型的 KL 有什么区别
- level: 2
- tags: [core, training]

**一句话答案**：clip 和 KL 惩罚都是相对本轮的旧策略，控制单次更新的步长；对参考模型的 KL 相对 SFT 模型，控制整个训练过程不跑出奖励模型可信的区域。

**要点**：
- PPO 的 KL 惩罚版本：β 自适应，KL 小于 d_targ/1.5 时 β 减半，大于 d_targ×1.5 时加倍；论文实验里效果不如 clip。
- RLHF 中对参考模型的 KL 常加进奖励：`R = r − β·log(π/ρ)`，期望为 β·KL。
- GRPO 把对参考模型的 KL 直接放进 loss。

**追问链**：
1. 有了 clip，为什么还要对参考模型的 KL？→ clip 只管单步，很多步累积后策略可以离初始模型很远，开始钻奖励模型的空子。
2. KL 用什么估计量？→ 从策略采样、r = p/q 时，k1 = −log r 无偏但方差大；k3 = (r − 1) − log r 无偏且恒非负；k2 = (log r)²/2 有偏但方差小。
3. β 设大设小各有什么后果？→ 太大策略学不动；太小容易 reward hacking 和语言退化。可以像 Ziegler 等那样用控制器让 KL 贴近目标值。

**易错点**：
- 把 PPO 的 clip 和 RLHF 的 KL 当成同一个东西。

## core-rl-006 LLM 场景的 RL 和经典 RL 有哪些不同，这些不同怎样影响算法设计
- level: 3
- tags: [core, training, harness]

**一句话答案**：动作空间是整个词表、轨迹长、奖励稀疏、从 SFT 模型出发、rollout 贵、价值模型和策略同规模；所以有去掉价值模型的组内基线、对参考模型的 KL、序列级比率和非生成 token 的 mask。

**要点**：
- 去掉 critic：奖励只在结尾、critic 难训准且显存翻倍，用同一 prompt 多次采样的均值做基线（RLOO、GRPO）。
- 防退化靠对参考模型的 KL，而不是经典 RL 里的熵奖励。
- 比率单位：PPO 逐 token 算比率，奖励却是序列级的，这是 GSPO 的出发点。
- Agent 多轮：工具返回不是策略动作，要从 loss 里屏蔽；环境有随机性，rollout 更慢。
- 成本结构：rollout（推理）常是最大开销，所以训练系统要把推理和训练分开优化。

**追问链**：
1. 什么时候还值得保留 critic？→ 有中间奖励、轨迹很长需要逐步信用分配，或者每个 prompt 采多条太贵时。
2. 从 SFT 出发对探索有什么影响？→ 起点好，但分布集中，容易熵塌缩，只在少数高概率答案附近打转；DAPO 的 Clip-Higher 针对的就是这个，见 [training/03](../../tracks/training/03-grpo-family/README.md)。
3. 多轮 Agent 的奖励只在最后给，中间工具步怎么分功劳？→ 结果奖励加组内基线只能整体分配；需要细粒度时用过程奖励或分步验证，见 [training/05](../../tracks/training/05-reward-verifier/README.md)。

**易错点**：
- 只列差异，不说每条差异导致了哪个设计选择。

## core-rl-007 口述 GAE 的从后往前递推，done 和截断分别怎么处理
- level: 2
- tags: [core, training]

**一句话答案**：先算每步 TD 残差 δ_t，再从最后一步往前递推 `A_t = δ_t + γλ·(1 − done_t)·A_{t+1}`，回报目标是 `A_t + V(s_t)`。

**要点**：
```
def gae(rewards, values, dones, gamma, lam):
    # values 比 rewards 多一个元素：最后一个是 bootstrap 用的 V(s_T)
    T = len(rewards)
    adv = [0.0] * T
    last = 0.0
    for t in reversed(range(T)):
        nonterminal = 1.0 - dones[t]
        delta = rewards[t] + gamma * values[t + 1] * nonterminal - values[t]
        last = delta + gamma * lam * nonterminal * last
        adv[t] = last
    returns = [a + v for a, v in zip(adv, values[:-1])]
    return adv, returns
```
- 回合结束处要切断：下一状态的 V 和后续优势都不能传过来。
- 优势常在 batch 内再标准化一次。

**追问链**：
1. LLM 里 values 和 rewards 在哪些位置有值？→ 每个生成 token 一个 V；奖励只在最后一个 token 上（加上逐 token 的 KL 惩罚，如果放在奖励里）。prompt 和工具返回位置要 mask 掉。
2. 截断（达到长度上限）和真正结束一样处理吗？→ 不一样。截断时应该用 V(s_T) bootstrap，而不是当作终止；很多实现在这里出错。

**易错点**：
- 忘了处理 done，把下一条轨迹的价值传进当前轨迹。

## core-rl-008 从期望回报出发推导策略梯度，环境转移为什么不需要可导
- level: 2
- tags: [core, training]

**一句话答案**：用 ∇p = p·∇log p 把梯度写成 E[f·∇log p]；轨迹对数概率里环境转移项与 θ 无关，求导后消失，只剩各步 ∇log π；再按因果性只留 reward-to-go。

**要点**：
- `∇E_{x~p_θ}[f(x)] = Σ ∇p_θ·f = E[f·∇log p_θ]`，只要求 p_θ 可导，不要求 f 可导，所以奖励可以是规则或单元测试。
- `log P(τ) = log p(s_0) + Σ log π_θ(a_t|s_t) + Σ log P(s_{t+1}|s_t,a_t)`，后一项对 θ 求导为 0。
- t 之前的奖励 r_k 乘 ∇log π(a_t|s_t) 期望为 0，因为 r_k 在 a_t 采样前已确定，而得分函数的条件期望为 0。
- 结果：`∇J = E[Σ_t G_t·∇log π_θ(a_t|s_t)]`，单样本估计就是 REINFORCE。

**追问链**：
1. 这个估计量的主要问题是什么？→ 方差大：回报里累加了整条轨迹后续的随机性，所有正奖励动作都被推高。所以要减基线、用优势。
2. 和监督学习的交叉熵梯度有什么关系？→ 交叉熵梯度是 ∇log π(标签)；策略梯度是 ∇log π(采样动作) 乘一个权重（回报或优势）。权重恒为 1 时就是对自己采样结果做 SFT。
3. LLM 里 token 级和序列级写法的梯度一样吗？→ γ = 1、奖励只在末尾时一样：log π(y|x) 是各 token log 概率之和，每个位置的 reward-to-go 都等于 R。

**易错点**：
- 以为需要对奖励函数或环境求导。
- 说不清为什么可以去掉动作之前的奖励。

## core-rl-009 为什么 PPO 的 clip 目标被叫做悲观下界，clip 能严格限制新旧策略的差距吗
- level: 3
- tags: [core, training]

**一句话答案**：min 的一项就是未截断目标 ρÂ，clip 目标逐项不大于它，ρ=1 处一阶相同；但 clip 只去掉继续推的梯度，不把比率拉回，多 epoch 后仍会超出，要靠 KL 早停补救。

**要点**：
- 代理目标 L^CPI = Ê[ρÂ] 用旧策略的状态分布，只在 θ_old 附近可信；TRPO 给出真实目标 ≥ 代理目标 − C·(max D_TV)² 的下界。
- `min(ρÂ, clip(ρ)Â) ≤ ρÂ`：只在比率变化让目标变好时忽略它，变坏时保留（PPO 论文第 3 节）。
- 第一个 minibatch ρ = 1，梯度等于普通策略梯度；之后共享参数的其他样本会把某些 ρ 推出区间。
- Engstrom 等（2020）观察到 PPO 训练中最大比率持续超出 1+ε。
- 补救：近似 KL 超阈值就早停本轮更新、监控 clip 比例、降学习率或减少 epoch。

**追问链**：
1. 只写 clip 不写 min 会怎样？→ Â > 0 而 ρ < 1−ε 时梯度也被清零，策略在错误方向走远后拉不回来。
2. clip 比例接近 1 说明什么？→ 本轮更新已经走得太远，大部分 token 不再贡献梯度，学习率或 epoch 数过大。
3. PPO 的 KL 惩罚版本怎么调 β？→ 每轮算 d = KL(π_old, π_θ)；d < d_targ/1.5 时 β 减半，d > 1.5·d_targ 时加倍。论文实验里效果不如 clip。

**易错点**：
- 把 clip 当成硬信任域。
- 说“下界”却说不出是谁的下界（是未截断代理目标 L^CPI 的下界）。

## core-rl-010 奖励只在末尾、200 个 token 的回答、γ=1、λ=0.95 时，GAE 会出什么问题
- level: 3
- tags: [core, training]

**一句话答案**：末尾奖励传到第 t 个 token 只剩 λ^(T−1−t) 倍，首个 token 约 4e-5，优势主要由有偏的 V 决定；可让 critic 目标用 λ=1，或预训练、去掉 critic。

**要点**：
- `Â_t = Σ (γλ)^l δ_{t+l}`；V ≡ 0 时 Â_t = λ^(T−1−t)·R。
- λ = 1 时中间的 V 全部裂项消掉，Â_t = G_t − V(s_t)，不管 V 准不准都无偏；λ < 1 只在 V 不准时有偏。
- VC-PPO（2025-03）把这叫奖励信号衰减：critic 用 λ = 1，策略用 λ = 0.95（Decoupled-GAE），并离线预训练 critic。
- VAPO（2025-04）让策略的 λ 随长度 l 变：λ = 1 − 1/(αl)。

**追问链**：
1. 为什么不干脆策略也用 λ = 1？→ 方差变大，收敛慢；这是偏差和方差的取舍，VC-PPO 选择只对 critic 用 λ = 1。
2. 从奖励模型初始化 critic 有什么问题？→ 奖励模型只在 EOS 上训练过，越靠前的前缀分越低，δ_t 带正偏差，越靠前的 token 优势越偏正，回答长度会塌缩。
3. 什么情况下干脆去掉 critic？→ 结果奖励、可验证任务、显存紧时，用同一 prompt 多次采样的组内基线（RLOO、GRPO）。

**易错点**：
- 以为 λ 和 γ 一样会改变优化目标。
- 忽略 critic 准确度，只说“λ 越大方差越大”。
