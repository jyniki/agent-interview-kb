# 04 DAPO：大规模长 CoT RL 的四个工程改进

## 1 解决什么问题

DeepSeek-R1 报告了大规模 RL 的效果，但没有公开足够的训练细节，社区复现普遍遇到困难。作者在 Qwen2.5-32B 基座上直接跑朴素 GRPO，效果明显达不到 DeepSeek 报告的同基座 R1-Zero 式训练。分析后归结为几个问题：

| 问题 | 现象 |
|---|---|
| 熵塌缩 | 策略熵随训练快速下降，同一组的回答几乎一样，探索不足 |
| 有效样本变少 | 全对的题越来越多，这些组优势为 0，batch 里有梯度的题不断减少 |
| 样本级 loss 不适合长 CoT | 长回答里每个 token 的权重变小，好的长推理学不到，坏的长回答（乱码、重复）罚不动 |
| 截断带来奖励噪声 | 超长被截断的回答统一给惩罚，推理正确只是太长的回答也被罚 |

论文的目标是开源一套完整的大规模 RL 系统：算法、基于 verl 的训练代码和数据集。

## 2 方法

### 2.1 两个前置决定

- **去掉 KL 项**（2.3 节）。RLHF 里 KL 用来防止模型偏离初始模型太远；训练长 CoT 推理模型时，模型分布本来就会大幅偏离初始模型，这个约束没有必要。
- **规则奖励**（2.4 节，式 7）。避免奖励模型被 hack，直接用可验证任务的最终正确性：

```
R(ŷ, y) = 1    若 is_equivalent(ŷ, y)
        = −1   否则
```

`y` 是标准答案，`ŷ` 是模型预测的答案。

### 2.2 DAPO 目标（式 8）

```
J_DAPO(θ) = E[(q,a)~D, {o_i}~π_θold(·|q)]
    (1 / Σ_{i=1..G} |o_i|) Σ_{i=1..G} Σ_{t=1..|o_i|}
        min( r_{i,t}(θ) Â_{i,t} , clip(r_{i,t}(θ), 1−ε_low, 1+ε_high) Â_{i,t} )

s.t. 0 < |{ o_i | is_equivalent(a, o_i) }| < G

r_{i,t}(θ) = π_θ(o_{i,t} | q, o_{i,<t}) / π_θold(o_{i,t} | q, o_{i,<t})
Â_{i,t}    = (R_i − mean({R_i})) / std({R_i})
```

- `(q, a)`：问题和标准答案；`G`：每题采样数；`|o_i|`：第 i 个回答的 token 数；
- `ε_low`、`ε_high`：解耦后的下、上 clip 边界；
- 约束条件：一组里答对的数量严格介于 0 和 G 之间，即过滤掉全对和全错的题；
- 优势仍是组内标准化，和 GRPO 一样保留了除以 std。

和 GRPO（[02 DeepSeekMath](02-deepseekmath-grpo.md) 式 3）相比，改了四处：clip 上下界解耦、加了采样约束、分母从“每条回答各自的长度”改成“整组的总 token 数”、去掉 KL。

### 2.3 四项技术

**Clip-Higher（3.1 节）**。上 clip 边界会限制低概率 token 的提升。论文的例子：ε = 0.2、优势为正时，旧概率 0.01 的 token 最多升到 0.012，旧概率 0.9 的 token 上界是 1.08，等于不受限。所以高概率的“利用”token 很容易继续变大，低概率的“探索”token 很难被提上来。实测被上 clip 截断的 token 平均概率低于 0.2（图 3a），支持这个判断。做法是只调大 ε_high，ε_low 保持不变，因为加大 ε_low 会把这些 token 的概率压到 0，让采样空间塌缩。论文取 ε_low = 0.2、ε_high = 0.28。

**Dynamic Sampling（3.2 节）**。全对（或全错）组的优势为 0，不产生梯度，batch 的有效样本数下降，梯度方差变大。图 3b 显示准确率为 1 的题的比例在训练中持续上升。做法：过采样，过滤掉准确率为 0 或 1 的题，一直采到 batch 填满有效样本。论文认为这不一定降低训练效率：同步 RL 系统里生成时间主要由长尾样本决定，多采一些题影响不大。

**Token-Level Policy Gradient Loss（3.3 节）**。GRPO 先在每条回答内对 token 求平均，再在回答之间平均，每条回答权重相同，长回答里每个 token 的贡献就小。改成所有 token 一起求和、除以总 token 数后，长序列对梯度的影响更大；从单个 token 看，某个生成模式只要会提高或降低奖励，不论出现在多长的回答里，都会被同等地推高或压低。

**Overlong Reward Shaping（3.4 节）**。先做 Overlong Filtering：屏蔽被截断样本的 loss，论文发现这一步就明显稳定了训练。再加 Soft Overlong Punishment（式 13），在长度上限前设一段缓冲区：

```
R_length(y) = 0                                   若 |y| ≤ L_max − L_cache
            = ((L_max − L_cache) − |y|) / L_cache  若 L_max − L_cache < |y| ≤ L_max
            = −1                                  若 |y| > L_max
```

`L_max` 是允许的最大长度，`L_cache` 是缓冲区长度。缓冲区内惩罚从 0 线性降到 −1，越长罚得越多。这个惩罚加到规则正确性奖励上。

**数据集（3.5 节）**。数学答案形式多样，规则解析容易出错。作者把答案改写成整数（例如答案形如 (a+√b)/c，就让 LLM 改题，使期望答案变为 a+b+c），得到 DAPO-Math-17K，共 1.7 万道题。

### 2.4 训练配置（4.1 节）

| 项 | 值 |
|---|---|
| 框架 | verl，基线为朴素 GRPO |
| 优化器 | AdamW，恒定学习率 1e-6，前 20 个 rollout 步线性 warm-up |
| rollout | prompt batch 512，每题 16 个回答 |
| 训练 | mini-batch 512，即每个 rollout 步 16 次梯度更新 |
| 长度 | 期望最大长度 16,384，缓冲区 4,096，生成上限 20,480 |
| clip | ε_low = 0.2，ε_high = 0.28 |
| 评测 | AIME 重复 32 次取 avg@32，温度 1.0，top-p 0.7 |

注意每个 rollout 步有 16 次梯度更新，所以 clip 在这里真的起作用；这和 DeepSeekMath 每次探索只更新一次不同。

## 3 关键实验结论

- **四项技术逐项叠加都有提升**（表 1），叠加顺序是 Overlong Filtering → Clip-Higher → Soft Overlong Punishment → Token-level Loss → Dynamic Sampling。论文报告完整 DAPO 用 R1-Zero 同基座训练一半的步数就超过了它。
- **Clip-Higher 抬高了熵**（图 2），生成更多样。
- **Token-level loss 的直接收益较小，但让训练更稳**，长度增长更健康（图 4：不用时熵和长度出现不健康的上涨）。
- **Overlong Filtering 稳定训练并提升效果**（图 5）。
- **Dynamic Sampling 让收敛更快**（图 6）。虽然要多采样，但需要的训练步数更少，总时间没有明显增加。
- **训练动态的监控经验**（4.3 节）：
  - 回答长度和验证集准确率一起看，长度并不总在增长，可能长时间停滞甚至下降；
  - 训练集奖励通常稳定上升，但和验证集准确率相关性不大，说明会过拟合训练集；
  - 熵要保持在合适区间，太低失去探索，太高出现乱码和重复；保持熵缓慢上升有利于性能。
- **反思行为逐渐出现**（4.4 节、表 2）。训练早期几乎没有检查和回溯，后期出现。

## 4 局限与后续工作

论文本身没有单独的局限一节。从论文内容可以看到的边界：

- 只在数学任务上验证，作者说可以迁移到其他任务，但没有实验。
- 答案被改写成整数，适合规则验证，不代表开放答案的场景。
- 仍然保留了按 std 归一化的优势，[05 Dr. GRPO](05-dr-grpo.md) 认为这会带来难度偏差。
- 动态采样要过采样，在生成成本高或异步系统里，代价需要重新评估。
- 仍用 token 级重要性比率。[06 GSPO](06-gspo.md) 认为 token 级比率在长序列和 MoE 上噪声大，改成序列级。

和 Dr. GRPO 的对比是常考点：两者都处理长度带来的偏差。DAPO 用整组总 token 数做分母，Dr. GRPO 用一个固定常数（如生成长度上限）做分母，两种做法都让 token 的权重不再取决于它所在回答的长度。DAPO 保留 std 归一化，Dr. GRPO 去掉。

工具调用场景里，截断原因要区分：长度上限造成的截断可以借鉴 DAPO 的处理，工具超时造成的截断是环境问题，见 [training/04 第 2 节](../tracks/training/04-agentic-rl/README.md#2-多轮-rollout-与环境交互)。

## 5 面试常见追问

1. 为什么只调大上 clip，不调大下 clip？→ 上 clip 限制的是正优势 token 的概率上涨，对低概率 token 限制最严，调大它给探索留空间；下 clip 限制负优势 token 的概率下降，调大会把这些 token 压到接近 0，采样空间塌缩。
2. 动态采样会不会让训练变慢？→ 要多采样，但同步系统里生成时间由长尾样本主导，多几道题影响小；而且每步都是有效梯度，收敛需要的步数更少。论文图 6 显示总体更快达到同样效果。
3. token 级 loss 和样本级 loss 的数学区别？→ 样本级是 `(1/G) Σ_i (1/|o_i|) Σ_t ℓ_{i,t}`，长回答每个 token 权重是 `1/(G|o_i|)`；token 级是 `Σ_i Σ_t ℓ_{i,t} / Σ_i |o_i|`，每个 token 权重相同。前者让长的错误回答罚得轻，后者没有这个问题。
4. 为什么去掉 KL？→ 长 CoT 推理训练中，模型分布本来就要大幅偏离初始模型，KL 约束反而限制能力提升。代价是失去对漂移的约束，需要靠 clip、监控熵和长度来保证稳定。
5. 截断样本为什么不能直接给负奖励？→ 推理正确但写得太长的回答也会被罚，模型分不清是推理错了还是太长了，引入奖励噪声。先屏蔽截断样本的 loss，再用缓冲区内的线性惩罚，把“别写太长”作为单独、平滑的信号。
6. 训练时该监控什么？→ 回答长度（配合验证集准确率）、训练奖励、熵、生成概率。熵快速下降说明塌缩，熵暴涨常伴随乱码和重复；训练奖励上升而验证集不动说明过拟合。
