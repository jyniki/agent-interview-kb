## 1 解决什么问题

PPO 是 LLM 的 RL 微调阶段最常用的算法，论文指出它有两个问题：

- **价值模型太贵**。PPO 的价值函数（critic）通常是和策略同规模的另一个模型，带来大量显存和计算开销。
- **价值模型难训准**。LLM 场景里奖励模型通常只给最后一个 token 打分，要训一个在每个 token 上都准确的价值函数并不容易。

另外，PPO 的常规做法是把逐 token 的 KL 惩罚加进奖励（论文式 2），这让优势的计算变复杂。

## 2 方法

### 2.1 PPO 回顾

```
J_PPO(θ) = E[q~P(Q), o~π_θold(O|q)] (1/|o|) Σ_t min( ρ_t A_t , clip(ρ_t, 1−ε, 1+ε) A_t )    （式 1）
ρ_t = π_θ(o_t | q, o_<t) / π_θold(o_t | q, o_<t)

r_t = r_φ(q, o_≤t) − β · log( π_θ(o_t | q, o_<t) / π_ref(o_t | q, o_<t) )                    （式 2）
```

- `q`：问题；`o`：旧策略采样的回答，`o_t` 是第 t 个 token；
- `π_θ`、`π_θold`：当前策略和采样时的旧策略；`π_ref`：参考模型，通常是初始 SFT 模型；
- `A_t`：优势，用 GAE 基于奖励和学到的价值函数 V_ψ 计算；
- `ε`：clip 范围；`β`：KL 系数；`r_φ`：奖励模型。

### 2.2 GRPO 目标

对每个问题 q，从旧策略采一组 G 个回答 {o_1 … o_G}，最大化：

```
J_GRPO(θ) = E[q~P(Q), {o_i}~π_θold(O|q)]
    (1/G) Σ_{i=1..G} (1/|o_i|) Σ_{t=1..|o_i|} {
        min( ρ_{i,t} Â_{i,t} , clip(ρ_{i,t}, 1−ε, 1+ε) Â_{i,t} ) − β · D_KL[π_θ ‖ π_ref]
    }                                                                                      （式 3）
ρ_{i,t} = π_θ(o_{i,t} | q, o_{i,<t}) / π_θold(o_{i,t} | q, o_{i,<t})
```

和 PPO 相比的两处改动：

1. **基线换成组内平均奖励**，`Â_{i,t}` 只由同组回答的相对奖励算出，不需要价值模型。论文的理由之一：奖励模型本来就是用同一问题下不同回答的比较数据训出来的，组内相对的算法和它的性质一致。
2. **KL 直接加进 loss**，不加进奖励，避免把 `Â_{i,t}` 的计算弄复杂。

KL 用 Schulman（2020）的无偏估计，保证非负：

```
D_KL[π_θ ‖ π_ref] = π_ref(o_{i,t}|q,o_{i,<t}) / π_θ(o_{i,t}|q,o_{i,<t})
                    − log( π_ref(o_{i,t}|q,o_{i,<t}) / π_θ(o_{i,t}|q,o_{i,<t}) ) − 1      （式 4）
```

（记 x = π_ref/π_θ，有 x − log x − 1 ≥ 0，在 x = 1 时取等号。）

### 2.3 两种优势

**结果监督**（4.1.2 节）：每个回答只在结尾有一个奖励。组内标准化后，回答里所有 token 共享这个值：

```
Â_{i,t} = r̃_i = (r_i − mean(r)) / std(r)
```

**过程监督**（4.1.3 节）：过程奖励模型（PRM）给每个推理步骤打分，`index(j)` 是第 j 步最后一个 token 的位置。所有步骤奖励一起标准化，每个 token 的优势是它之后所有步骤标准化奖励之和：

```
r̃_i^{index(j)} = (r_i^{index(j)} − mean(R)) / std(R)
Â_{i,t} = Σ_{index(j) ≥ t} r̃_i^{index(j)}
```

### 2.4 迭代 GRPO（算法 1）

随着训练进行，旧奖励模型可能不足以监督当前策略。迭代版本在每轮里：用策略的采样结果构造奖励模型的新训练集，带 10% 历史数据的回放机制继续训奖励模型；把参考模型重置为当前策略；再继续训策略。

### 2.5 论文的超参数（4.2 节）

| 项 | 值 |
|---|---|
| 起点 | DeepSeekMath-Instruct 7B |
| RL 数据 | SFT 数据里和 GSM8K、MATH 相关的 CoT 格式题，约 144K 道 |
| 策略学习率 | 1e-6 |
| KL 系数 β | 0.04 |
| 每题采样数 G | 64 |
| 最大长度 | 1024 |
| batch 大小 | 1024 |
| 每次探索后的更新次数 | 1 |

注意最后一项：每批采样只更新一次，此时 π_θold 和 π_θ 在更新前相同，比率为 1，clip 实际上不起作用。附录 A.1.6 的梯度推导就是在 π_θold = π_θ 的假设下做的。

## 3 关键实验结论

- **RL 在只用部分数据时也有效**。RL 只用了 GSM8K、MATH 相关的 CoT 题，但在所有评测上都超过 RL 前的 Instruct 模型，包括没有 RL 数据的领域外任务。
- **统一范式**（5.2.1 节，式 5）。SFT、RFT、DPO、Online RFT、PPO、GRPO 的梯度都可以写成同一形式，区别只在三个组件：数据来源、奖励函数、梯度系数。

  ```
  ∇_θ J_A(θ) = E[(q,o)~D] ( (1/|o|) Σ_t GC_A(q, o, t, π_rf) · ∇_θ log π_θ(o_t | q, o_<t) )
  ```

  `D` 是数据来源，`π_rf` 是奖励函数，`GC_A` 是算法 A 给每个 token 的梯度系数。
- **在线优于离线**（图 5）。Online RFT 早期和 RFT 差不多，后期明显更好：策略和 SFT 模型差得越远，实时采样的价值越大。
- **梯度系数要分正负和大小**。GRPO 优于 Online RFT：Online RFT 不惩罚错误回答，对所有正确回答一视同仁；GRPO 按奖励值有区别地强化和惩罚。
- **过程监督优于结果监督**：GRPO+PS 好于 GRPO+OS。
- **迭代 RL 有效**（图 6），提升主要来自第一轮迭代。
- **RL 提升 Maj@K，不提升 Pass@K**（图 7，温度 0.7）。论文的解读：RL 让输出分布更稳，把 Top-K 里本来就有的正确回答推到前面，而不是增强基础能力。这条结论后来被反复引用。

## 4 局限与后续工作

论文自己承认的：

- 只用指令微调阶段的题目和朴素的核采样，作者认为这可能是 RL 只提升 Maj@K 的原因；未来要试分布外题目和树搜索类采样（5.2.3 节）。
- 所有方法都完全相信奖励信号，但奖励不总可靠，论文举例 PRM800K 约 20% 的标注有误；要研究对噪声奖励鲁棒的算法。
- 奖励模型的泛化、不确定性和高质量 PRM 都是待解决方向。

后续工作针对 GRPO 本身的改进：

| 问题 | 改进 | 精读 |
|---|---|---|
| `1/|o_i|` 带来长度偏差，`std(r)` 带来难度偏差 | 去掉两处归一化 | [05 Dr. GRPO](05-dr-grpo.md) |
| 熵塌缩、零优势组、长回答 token 权重小、截断噪声 | Clip-Higher、动态采样、token 级 loss、超长惩罚 | [04 DAPO](04-dapo.md) |
| token 级比率噪声大，MoE 上不稳 | 序列级比率和 clip | [06 GSPO](06-gspo.md) |
| 用规则奖励在大规模上训练推理 | R1-Zero 直接从基座做 GRPO | [03 DeepSeek-R1](03-deepseek-r1.md) |

## 5 面试常见追问

1. GRPO 为什么能省显存？→ 不需要价值模型。价值模型通常和策略同规模，省掉的是一个模型的权重、梯度和优化器状态。代价是每题要采 G 个回答，rollout 开销变大。
2. 组内一致（全对或全错）时会怎样？→ `r_i − mean(r)` 全为 0，优势为 0，这组不产生策略梯度，只剩 KL 项；另外 std 为 0，实现里要加一个小常数防止除零。DAPO 的动态采样就是过滤这类组。
3. GRPO 的 KL 和 PPO 的 KL 有什么区别？→ PPO 把 `−β log(π_θ/π_ref)` 加进每个 token 的奖励，再进 GAE；GRPO 把 KL 作为 loss 里的单独一项，用 `x − log x − 1` 这个非负无偏估计，优势只由奖励决定。
4. 论文里每批只更新一次，clip 还有用吗？→ 更新前 π_θ = π_θold，比率恒为 1，clip 不触发；目标退化为带优势权重的策略梯度加 KL。clip 只有在同一批数据上更新多次（μ > 1）时才起作用。
5. 怎么理解“RL 提升 Maj@K 不提升 Pass@K”？→ 采 K 个回答时至少一个对的概率没变，说明能力上限没变；多数投票变好，说明正确回答在分布里的概率被推高了。论文把原因部分归于只用了训练集内的题和朴素采样。
6. 为什么说 SFT、DPO 也是“RL”？→ 统一范式下它们的梯度都是 `GC · ∇log π`。SFT 的系数恒为 1，RFT 只对正确回答为 1，DPO 的系数由隐式奖励差决定，PPO/GRPO 由优势决定。区别在数据是在线还是离线、奖励来自规则还是模型、系数怎么算。
