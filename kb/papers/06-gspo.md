# 06 GSPO：序列级重要性比率

> 论文：Group Sequence Policy Optimization
> 作者：Chujie Zheng（第一作者、通讯作者）、Shixuan Liu、Mingze Li 等，通讯作者还有 Bowen Yu（阿里巴巴 Qwen 团队）

> 相关章节：[training/03 GRPO 及其变体](../tracks/training/03-grpo-family/README.md#5-gspo把重要性比率放到序列级)、[training/04 Agentic RL](../tracks/training/04-agentic-rl/README.md)

## 1 解决什么问题

论文的出发点是 GRPO 在训练超大模型时不稳定，经常出现灾难性、不可逆的崩溃。作者观察到，一旦崩溃，回退到之前的检查点、仔细调 clip 范围、加长生成长度或换 RL 题目都救不回来。

**为什么需要重要性比率**。模型越大、越稀疏（MoE）、回答越长，越需要大的 rollout batch 来用满硬件。为了提高样本效率，通常把一大批 rollout 分成多个 mini-batch 依次更新，这就产生了 off-policy：后面几个 mini-batch 的样本来自旧策略 π_θold，不是正在优化的 π_θ。clip 的作用就是把过于 off-policy 的样本排除在梯度估计之外。

**论文认为 GRPO 的目标是“不适定”的**（第 3 节）。重要性采样的原理是：

```
E_{z~π_tar}[ f(z) ] = E_{z~π_beh}[ (π_tar(z) / π_beh(z)) · f(z) ]      （式 4）
```

它依赖从行为分布里取大量样本（N ≫ 1）求平均，权重才能起到校正分布的作用。GRPO 在每个 token 位置算一个比率 `π_θ(y_{i,t}|x, y_{i,<t}) / π_θold(y_{i,t}|x, y_{i,<t})`，但每个位置的下一个 token 分布只有一个样本，起不到校正作用，反而给梯度引入高方差噪声。噪声随序列长度累积，再被 clip 放大，最终导致崩溃。

论文提炼出一条原则：**优化目标的单位要和奖励的单位一致**。奖励是给整个序列的，校正却在 token 级做，这就不对。

## 2 方法

### 2.1 记号

- `x`：问题，`D`：问题集；`y`：回答，`|y|` 是它的 token 数；
- `π_θ(y|x) = Π_t π_θ(y_t | x, y_<t)`：整个回答的似然；
- `r(x, y) ∈ [0, 1]`：Verifier 给的奖励；
- 论文在 PPO 和 GRPO 公式里省略了 KL 项，说明它不是本文重点。

### 2.2 GSPO 目标（4.1 节）

```
J_GSPO(θ) = E[x~D, {y_i}~π_θold(·|x)]
    (1/G) Σ_{i=1..G} min( s_i(θ) Â_i , clip(s_i(θ), 1−ε, 1+ε) Â_i )             （式 5）

Â_i = ( r(x, y_i) − mean({r(x, y_i)}) ) / std({r(x, y_i)})                      （式 6）

s_i(θ) = ( π_θ(y_i|x) / π_θold(y_i|x) )^(1/|y_i|)
       = exp( (1/|y_i|) Σ_t log( π_θ(y_{i,t}|x, y_{i,<t}) / π_θold(y_{i,t}|x, y_{i,<t}) ) )   （式 7）
```

- `s_i(θ)` 是序列级比率，等于各 token 比率的几何平均；
- clip 对每个回答整体做一次：比率超出范围，整个回答被排除；
- 优势仍是组内标准化，和 GRPO 一样。

**为什么开 `|y_i|` 次方**：降低方差，把 `s_i` 控制在统一的数值范围内。不做长度归一化的话，少数几个 token 的似然变化就会让序列比率剧烈波动，而且不同长度的回答需要不同的 clip 范围。

**clip 范围小几个数量级**。因为比率定义变了，GSPO 和 GRPO 的 clip 范围通常差几个数量级。实验里 GSPO 的左右 clip 范围是 3e-4 和 4e-4，GRPO 是 0.2 和 0.27（经过调参以保证对比公平）。

### 2.3 梯度分析（4.2 节）

省略 clip 后：

```
∇J_GSPO = E[ (1/G) Σ_i  s_i(θ) · Â_i · (1/|y_i|) Σ_t ∇ log π_θ(y_{i,t}|x, y_{i,<t}) ]          （式 10）

∇J_GRPO = E[ (1/G) Σ_i  Â_i · (1/|y_i|) Σ_t  w_{i,t}(θ) · ∇ log π_θ(y_{i,t}|x, y_{i,<t}) ]     （式 12）
w_{i,t}(θ) = π_θ(y_{i,t}|x, y_{i,<t}) / π_θold(y_{i,t}|x, y_{i,<t})
```

区别在于 token 对数似然的梯度怎么加权：

- GRPO 里每个 token 乘自己的 `w_{i,t}`。这些权重在优势为正时落在 (0, 1+ε]，为负时落在 [1−ε, +∞)，彼此不相等，影响会随训练累积；
- GSPO 里同一回答的所有 token 乘同一个 `s_i(θ)`，权重相同，消除了这个不稳定因素。

### 2.4 GSPO-token（4.3 节）

多轮 RL 等场景可能需要比序列级更细的优势调整，于是有一个 token 级变体：

```
J_GSPO-token = E[ (1/G) Σ_i (1/|y_i|) Σ_t min( s_{i,t}(θ) Â_{i,t} , clip(s_{i,t}(θ), 1−ε, 1+ε) Â_{i,t} ) ]   （式 13）
s_{i,t}(θ) = sg[s_i(θ)] · π_θ(y_{i,t}|x, y_{i,<t}) / sg[π_θ(y_{i,t}|x, y_{i,<t})]                         （式 14）
```

`sg[·]` 是 stop-gradient（PyTorch 的 detach）。第二个因子数值上恒为 1，所以 `s_{i,t}` 数值上等于 `s_i`，但梯度流过每个 token 自己的对数似然。当回答内所有 token 的优势相同时，GSPO-token 和 GSPO 的目标、clip 条件和梯度在数值上完全一致；区别是它允许每个 token 有不同的优势。

## 3 关键实验结论

实验设置：从 Qwen3-30B-A3B-Base 微调出的冷启动模型，每批 rollout 分成 4 个 mini-batch 更新。GRPO 基线必须配 Routing Replay 才能在 MoE 上正常收敛，GSPO 不需要。

- **训练全程稳定**（图 1）。增加训练算力、定期更新题目集、加长生成长度，GSPO 都能持续提升。
- **同样算力和题目消耗下效率更高**（图 1）。训练奖励和评测表现都好于 GRPO。论文称 GSPO 已用于最新 Qwen3 模型的 RL 训练。
- **clip 掉的 token 比例反而高两个数量级**（5.2 节、图 2）。调整 clip 范围也不改变这个数量级差距。GSPO 用来估计梯度的 token 少得多，效率却更高，论文据此认为 GRPO 的 token 级梯度估计本身噪声大、利用样本的效率低。
- **MoE 上的专家激活波动**（5.3 节）。48 层的 Qwen3-30B-A3B-Base，每次梯度更新后，同一个 rollout 样本在新策略下约有 10% 的激活专家和旧策略不同，层数越深越明显。这让 token 级比率剧烈波动。
- **Routing Replay 对 GRPO 是必需的**（图 3）。做法是缓存旧策略激活的专家，算比率时在新策略里“重放”同样的路由，让分子分母用同一个激活网络。没有它 GRPO 训练不能正常收敛。代价是额外的显存和通信开销，也限制了 MoE 的实际容量。
- **GSPO 去掉了对 Routing Replay 的依赖**。论文的解释：GSPO 只关心序列似然，对单个 token 的似然不敏感；MoE 模型的语言建模能力一直在，序列似然不会剧烈波动。

## 4 局限与后续工作

论文没有单独的局限一节，实验也只报告了训练曲线，对比对象只有 GRPO。阅读时要注意：

- 只在一个 MoE 模型规模和一种冷启动设置下对比，dense 模型和其他算法（如 DAPO、Dr. GRPO）没有直接比较。
- 序列级 clip 会整条丢掉回答，论文没有讨论这对长回答或稀有正确回答的影响。
- 优势仍除以 std，GSPO 不处理 [05 Dr. GRPO](05-dr-grpo.md) 说的难度偏差；聚合是先对回答内 token 求平均（式 10 里的 `1/|y_i|`），也没有采用 [04 DAPO](04-dapo.md) 的 token 级聚合。这几个改动方向是正交的。

论文提出的工程意义（5.4 节）：训练引擎（如 Megatron）和推理引擎（如 SGLang、vLLM）的数值精度不一致，实践中通常用训练引擎重算旧策略的似然。序列级似然对精度差异更宽容，GSPO 有可能直接用推理引擎返回的似然，省掉重算。这对部分 rollout、多轮 RL 和训推分离框架尤其有用。相关的工程问题见 [training/04 第 3 节](../tracks/training/04-agentic-rl/README.md#3-工具返回的-loss-mask) 和 [training/07 RL 训练框架](../tracks/training/07-training-systems/README.md)。

多轮 Agent 场景里轨迹更长、token 级比率噪声累积更多，这是 training/04 把 GSPO 列为改进方向的原因，见 [training/04 第 4 节](../tracks/training/04-agentic-rl/README.md#4-多轮信用分配)。

## 5 面试常见追问

1. 为什么说 GRPO 的 token 级比率“起不到校正作用”？→ 重要性采样要靠大量样本平均才能校正分布；token 级比率在每个位置只有一个样本，只是一个随机的乘性噪声。噪声随长度累积，被 clip 放大后导致崩溃。
2. 序列比率为什么要开 `1/|y|` 次方？→ 不开的话，序列比率是所有 token 比率的乘积，几个 token 的变化就能让它指数级波动，而且长短回答的比率尺度差别巨大，需要不同的 clip 范围。开方后是几何平均，数值范围统一。
3. GSPO 的 clip 范围为什么这么小？→ 比率是每 token 对数比率的平均再取指数，长回答里各 token 的偏差被平均掉，`s_i` 非常接近 1，所以 clip 范围要小几个数量级才会起作用。论文用 3e-4 和 4e-4。
4. clip 掉更多 token 为什么效率反而更高？→ 论文的解读：GRPO 保留下来的 token 级梯度本身噪声大，用得多不代表学得好；GSPO 按整个回答决定用或不用，信号更可靠。
5. 为什么 GSPO 对 MoE 更稳？→ MoE 每次更新后约 10% 的激活专家会变，单个 token 的概率可能剧烈变化，token 级比率随之波动；整个序列的似然由模型的语言建模能力决定，变化平缓。GRPO 要靠 Routing Replay 固定路由，代价是显存、通信和模型容量。
6. 多轮 Agent 训练想要 token 级优势怎么办？→ 用 GSPO-token：比率数值上仍是序列级的 `s_i`，但通过 stop-gradient 让每个 token 可以有自己的优势。工具结果 token 仍要用 mask 排除。
