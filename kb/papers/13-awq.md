# 13 AWQ：按激活找显著通道的权重量化

## 1 解决什么问题

论文的出发点是端侧部署：本地运行能减少云端成本、离线可用、保护隐私，但模型太大，设备资源有限。低位宽的只量化权重（weight-only）能大幅降低显存占用，但难做好：

| 做法 | 缺陷 |
|---|---|
| QAT（训练时量化） | 训练成本高，难以扩展到大模型 |
| PTQ 的朴素做法：逐组四舍五入（RTN） | 低位宽时精度损失大 |
| GPTQ：用二阶信息做误差补偿 | 重构过程可能过拟合校准集，在分布外领域扭曲学到的特征（图 8）；对部分模型（如 LLaMA-7B、OPT-66B）需要重排技巧才好用 |

论文关注 W4A16 这类只量化权重的设置（另一类是 W8A8，权重和激活都量化到 INT8），理由是它既降低显存门槛，又能加速访存受限的逐 token 生成。

## 2 方法

### 2.1 观察：只保护 1% 的显著权重就够了（3.1 节、表 1）

INT3、组大小 128 量化 OPT 模型，保留一小部分输入通道为 FP16，其余量化：

- 按**权重大小**（L2 范数）选通道保留 FP16，提升和随机选差不多；
- 按**激活大小**选通道，只保留 0.1% 到 1% 的通道就能大幅改善困惑度。

论文的解释：输入特征幅度大的通道通常更重要，保留对应权重就保留了这些特征。所以虽然只量化权重，判断哪些权重重要却要看激活，这就是“activation-aware”。

**问题**：混合精度（一部分 FP16、其余 INT3）不增加多少总比特数，但系统实现困难、对硬件不友好。

### 2.2 用缩放代替混合精度（3.2 节）

量化函数（式 1）：

```
Q(w) = Δ · Round(w / Δ),   Δ = max(|w|) / 2^(N−1)
```

- `w`：一组（group）权重；`N`：量化位数；`Δ`：由组内绝对值最大值决定的缩放因子。

对一个权重 `w` 乘 `s > 1`、对输入 `x` 除以 `s`，数学上等价，但量化后的误差不同（式 2、式 3）：

```
Err(Q(w) x)          = Δ  · RoundErr(w / Δ)    · x
Err(Q(w·s)(x/s))     = Δ' · RoundErr(w·s / Δ') · x · (1/s)
```

`Δ'` 是缩放后新的量化因子。论文的三个经验判断：

1. `RoundErr` 近似在 [0, 0.5] 均匀分布，平均约 0.25，缩放不改变它；
2. 只放大单个元素通常不改变组内最大值，所以 `Δ' ≈ Δ`；
3. `Δ` 和 `x` 都是 FP16，没有量化误差。

于是新旧误差之比约为 `(Δ'/Δ) · (1/s)`，`s > 1` 时显著权重的相对误差变小。

**验证**（表 2，OPT-6.7B，1% 显著通道乘 s）：s 从 1 增到 2，困惑度明显改善；s 继续增大，显著通道的相对误差继续变小，但 `Δ` 发生变化的组越来越多（s = 4 时 21.2% 的组变了），非显著通道的误差被 `Δ'/Δ > 1` 放大。最好的困惑度出现在 s = 2。所以缩放时要同时考虑非显著通道。

### 2.3 自动搜索缩放因子（式 4、式 5）

对每一层，找让量化后输出最接近原输出的逐输入通道缩放：

```
s* = argmin_s L(s)
L(s) = ‖ Q(W · diag(s)) (diag(s)^(−1) · X) − W X ‖                 （式 4）
```

`W` 是原 FP16 权重，`X` 是在一小份校准集上缓存的输入特征，`s` 是每个输入通道的缩放；`diag(s)^(−1) · X` 通常能融合进前一个算子（如 LayerNorm）。量化函数不可导，直接反向传播不行，近似梯度的方法收敛不稳定。

所以用一个很小的搜索空间：

```
s = s_X^α,   α* = argmin_α L(s_X^α)                                 （式 5）
```

`s_X` 是每个通道激活的平均幅度，`α ∈ [0, 1]` 在保护显著通道和非显著通道之间平衡（0 不缩放，1 最激进），在 [0, 1] 上网格搜索，实验用 20 个格点。另外加权重裁剪，最小化量化的 MSE。

**优点**（3.2 节末）：不做回归（如 GPTQ 的重构），也不做反向传播；只统计每个通道的平均激活幅度，对校准集依赖小、不易过拟合、需要的数据更少，能保住校准集分布以外的知识。

### 2.4 TinyChat：把省下的显存变成速度（第 4 节）

**为什么只量化权重能加速端侧生成**（4.1 节、图 3，Llama-2-7B 在 RTX 4090 上，batch 为 1）：

- 生成阶段比上下文阶段慢得多：论文报告生成 20 个 token 要 310 ms，处理 200 token 的 prompt 只要 10 ms；
- 生成阶段访存受限：4090 峰值算力 165 TFLOPS、带宽 1 TB/s，算术强度低于 165 就受访存限制，FP16 生成阶段的算术强度约为 1；
- 权重访存远多于激活访存。权重量化到 4 位，算术强度约提高到 4，理论峰值提高约 4 倍。

**难点**：W8A8 存储和计算用同一种精度，反量化可以放进 kernel 的收尾；W4A16 存储和计算精度不同，反量化必须放进主计算循环。

**TinyChat 的做法**：

- **即时反量化**：硬件没有 INT4 乘 FP16 的指令，要先反量化；把反量化融合进矩阵乘 kernel，避免把反量化后的权重写回 DRAM，矩阵乘矩阵和矩阵乘向量都这样做。
- **SIMD 感知的权重打包**：反量化一个 4 位权重要 1 次移位、1 次按位与、1 次 FMA，而真正的计算只有 1 次 FMA。ARM 上把 32 个 4 位权重按 w0, w16, w1, w17, … 重排进 128 位寄存器，3 条 SIMD 指令就能解出全部 32 个权重（图 4），论文报告最多 1.2 倍加速；GPU 上按 w{0,2,4,6,1,3,5,7} 每 8 个打包。
- **kernel 融合**：LayerNorm 全部算子融合成一个 kernel；QKV 投影融合，位置编码即时计算；预分配 KV Cache，在注意力 kernel 内更新。4090 上每个 FP16 kernel 约 0.01 ms，和 kernel 启动开销相当，所以减少 kernel 数直接带来加速。

## 3 关键实验结论

实验设置（5.1 节）：只量化权重、分组量化，组大小默认 128；主要看 INT4 和 INT3；校准集取自 Pile 的一小部分，避免过拟合特定下游领域；主要用 WikiText-2 困惑度评估。基线是 RTN（组大小 128 时已经很强）和 GPTQ（含重排版本）。

只写结论方向，以及论文报告的系统指标：

- **缩放和混合精度效果相当**（表 3）：OPT 系列 INT3-g128 下，AWQ 稳定好于 RTN，和保留 1% FP16 的混合精度相当，但对硬件友好。
- **LLaMA、Llama-2 各个规模上好于 RTN 和 GPTQ**（表 4），包括带重排的 GPTQ。
- **不同架构也有效**（表 5）：Mistral（GQA）和 Mixtral（MoE）。
- **指令微调模型**（图 5）：Vicuna 7B、13B 的 INT3 量化，用 GPT-4 对比量化版和 FP16 版，两种顺序都测一次消除位置偏差，AWQ 好于 RTN 和 GPTQ。
- **多模态模型**（表 6、表 7、图 6、图 7）：只量化 OpenFlamingo-9B 的语言部分，各种 few-shot 设置下都好于已有方法；在 VILA 上 INT4 在 11 个视觉语言评测上基本无损。论文称这是首个 VLM 低位宽量化研究。
- **代码和数学**（表 8）：INT4-g128 下和 FP16 相当，好于已有方法。
- **和 GPTQ 正交**（表 9）：INT2 极低位宽时，AWQ 和 GPTQ 结合能进一步缩小差距。
- **校准数据更省**（5.3 节、图 8a）：论文报告比 GPTQ 少用约 10 倍校准序列（16 条对 192 条）就能达到更好的困惑度。
- **对校准集分布更稳健**（图 8b）：OPT-6.7B INT3，在 PubMed 和 Enron 之间交叉校准与评测，校准和评测分布不同时，AWQ 困惑度只变差 0.5 到 0.6，GPTQ 变差 2.3 到 4.9。
- **系统加速**（5.4 节，论文报告）：TinyChat 相比 Huggingface FP16 实现，在桌面、笔记本和移动 GPU 上平均 3.2 到 3.3 倍；Jetson Orin 上比已有系统快 1.2 到 3.0 倍，比 llama.cpp 最多快 1.7 倍，比 AutoGPTQ 至少快 2.6 倍；VILA 在 Orin 上约 3 倍。论文还报告可以在 64GB 的 Jetson Orin 上部署 Llama-2-70B，在 8GB 显存的笔记本 RTX 4070 上以约 33 token/s 运行 Llama-2-13B，而 FP16 连 7B 都放不下。

## 4 局限与后续工作

论文没有单独的局限一节。从论文内容能看到的边界：

- **只量化权重**。加速来自 batch 小、访存受限的生成阶段；Prefill 和大 batch 时更接近计算受限，W4A16 的收益会变小，见 [inference/04 第 4 节](../tracks/inference/04-quantization/README.md#4-量化什么在哪个阶段加速)。要在计算受限时加速，需要 W8A8（如 SmoothQuant）或 FP8。
- **不处理 KV Cache**。长上下文时 KV 显存可能超过权重，需要 KV 量化，见 [inference/04 第 7 节](../tracks/inference/04-quantization/README.md#7-kv-cache-量化)。
- **评估以困惑度为主**。困惑度接近不代表多步推理和工具调用能力不变；后续研究发现量化对推理和 Agent 能力的影响随任务难度变化，见 [inference/04 第 8 节](../tracks/inference/04-quantization/README.md#8-量化对-agent-能力的影响)。
- **误差分析是近似的**：`Δ' ≈ Δ` 和 `RoundErr` 均匀分布都是经验假设，所以需要搜索 α，而不是直接给出最优缩放。
- 论文第 3.2 节正文说 OPT 上的消融在“表 5”，但对应结果实际在表 3，表 5 是 Mistral/Mixtral 的结果；读原文时注意。

相关工作的对比见 [inference/04 第 5 节](../tracks/inference/04-quantization/README.md#5-ptqgptq-与-awq) 的 GPTQ 与 AWQ 对比表。AWQ 的“用等价缩放把量化难度转移”和 SmoothQuant 思路相近：SmoothQuant 把激活的离群值难度搬到权重上，让两者都能用 INT8；AWQ 放大显著权重通道，让它们的相对量化误差变小。

## 5 面试常见追问

1. 为什么只量化权重，却要看激活来找重要权重？→ 输出误差是“权重误差乘以输入”。输入幅度大的通道，同样的权重误差会被放大；这些通道对应的特征也更重要。论文实验里按权重大小选通道和随机选差不多，按激活大小选只保留 0.1% 到 1% 就有明显改善。
2. 缩放为什么能减小误差？→ 权重乘 s、输入除以 s，数学等价。缩放后的绝对误差 `Δ'·RoundErr·x/s`，在 `Δ'` 基本不变、`RoundErr` 期望不变时，相对误差约缩小为 1/s。s 太大时组内最大值变大，`Δ'` 变大，其他通道的误差被放大，所以要搜索。
3. α 是什么？怎么定？→ 缩放因子 `s = s_X^α` 的指数，s_X 是通道平均激活幅度。α = 0 不缩放，α = 1 最激进。对每层在 [0, 1] 上网格搜索（论文用 20 个点），目标是量化后该层输出和原输出的差最小。
4. AWQ 和 GPTQ 的区别？→ GPTQ 逐列量化，用 Hessian 逆把误差补偿到未量化的列，做的是重构，依赖校准数据、有过拟合风险；AWQ 只统计激活幅度并做等价缩放，不做重构也不反传，校准数据少、对分布更稳健。两者可以结合，INT2 时一起用效果更好。
5. W4A16 为什么在端侧能加速？大 batch 服务时呢？→ batch 为 1 的生成阶段算术强度约为 1，严重访存受限，权重读取占主导，权重压到 4 位，读的字节少约 4 倍。大 batch 或 Prefill 时更接近计算受限，INT4 权重还要反量化回 FP16 再算，收益变小甚至变慢，这时 W8A8 或 FP8 更合适。
6. 缩放因子 `diag(s)^(−1)` 作用在输入上，推理时会多一次乘法吗？→ 通常不会。它可以融合进前一个算子，比如前面 LayerNorm 的缩放参数或前一层线性层的输出。
