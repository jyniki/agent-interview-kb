# 08 Search-R1：用 RL 训练模型调用搜索引擎

> 论文：Search-R1: Training LLMs to Reason and Leverage Search Engines with Reinforcement Learning

> 相关章节：[training/04 Agentic RL](../tracks/training/04-agentic-rl/README.md#6-search-agent-的-rl以-search-r1-为例)、[core/07 RAG 与搜索](../core/07-rag-search/README.md)
> 相关方向：training、harness

## 1 解决什么问题

让 LLM 用上外部搜索，之前有两类做法：

| 做法 | 缺陷 |
|---|---|
| RAG：用输入当查询检索，把段落放进上下文 | 即使用提示做多轮多查询检索（如 IRCoT），模型在训练中也没有学过怎么和搜索引擎有效交互 |
| 把搜索当工具：提示或训练模型调用 | 提示方法难泛化到预训练没见过的任务；训练方法依赖大量高质量标注轨迹，而且搜索操作不可微，无法端到端梯度下降 |

DeepSeek-R1 证明了只用结果奖励的 RL 能训出推理能力，但它不会用工具（见 [03 DeepSeek-R1](03-deepseek-r1.md) 第 4 节）。把 RL 用到“推理 + 搜索”上，论文列出三个挑战：

1. **RL 框架与稳定性**：怎么把搜索引擎放进 RL，特别是检索回来的内容怎么处理才能稳定优化。
2. **多轮交替推理与搜索**：模型要能根据问题难度多次搜索、动态调整检索策略。
3. **奖励设计**：简单的结果奖励能不能引导出有意义、稳定的搜索行为。

## 2 方法

### 2.1 带搜索引擎的 RL 目标（式 1，附录 A 式 6）

```
max_{π_θ}  E_{x~D, y~π_θ(·|x; R)} [ r_φ(x, y) ] − β · D_KL[ π_θ(y|x; R) ‖ π_ref(y|x; R) ]
```

`R` 是搜索引擎；`π_θ(·|x; R)` 是交替推理和检索的生成过程，论文记作 π_θ(·|x) ⊗ R；轨迹 `y` 既有模型生成的 token，也有搜索返回的段落。普通 RLHF 目标假设整个 `y` 都由策略生成，这里不成立。

### 2.2 检索 token 的 loss mask（3.1 节）

轨迹里检索回来的 token 不是策略采样的，对它们做同样的优化会导致“意料之外的学习动态”。做法是定义指示函数 `I(y_t)`：模型生成的 token 为 1，检索 token 为 0，策略梯度只在 1 的位置算。

PPO 版本（式 2）：

```
J_PPO(θ) = E[x~D, y~π_old(·|x; R)]
    (1 / Σ_t I(y_t)) Σ_{t: I(y_t)=1} min( ρ_t A_t , clip(ρ_t, 1−ε, 1+ε) A_t )
ρ_t = π_θ(y_t | x, y_<t; R) / π_old(y_t | x, y_<t; R)
```

`A_t` 由 GAE 基于后续奖励和学到的价值函数计算。

GRPO 版本（式 3）：

```
J_GRPO(θ) = E[x~D, {y_i}~π_old(·|x; R)]
    (1/G) Σ_i (1 / Σ_t I(y_{i,t})) Σ_{t: I(y_{i,t})=1} { min( ρ_{i,t} Â_{i,t} , clip(ρ_{i,t}, 1−ε, 1+ε) Â_{i,t} ) − β D_KL[π_θ ‖ π_ref] }
```

计算 KL 时同样屏蔽检索 token。

注意 GRPO 版本的分母是每条轨迹各自的有效 token 数，按 [05 Dr. GRPO](05-dr-grpo.md) 的分析会带来长度偏差；章节里给的是 DAPO 式按整组 token 数聚合的写法，见 [training/04 第 3 节](../tracks/training/04-agentic-rl/README.md#3-工具返回的-loss-mask)。

### 2.3 多轮 rollout（3.2 节，算法 1）

```
y ← ∅, b ← 0
while b < B:                                        # B 是最大动作预算
    逐 token 生成，直到遇到 </search>、</answer> 或 <eos>
    if 生成了 <search>q</search>:
        d = R(q);  y ← y + <information>d</information>
    elif 生成了 <answer>…</answer>:
        return y
    else:
        y ← y + "My action is not correct. Let me rethink."
    b ← b + 1
return y
```

要点：生成到检索调用的结束标记就停，由系统执行检索，再把结果包进 `<information>` 接回序列；格式不对时追加一句“让我重新想”而不是直接终止。

### 2.4 模板和奖励（3.3、3.4 节）

模板（表 1）只规定结构：每次拿到新信息先在 `<think>` 里推理；缺知识就用 `<search>` 查询，结果在 `<information>` 里返回；可以搜任意多次；不需要外部知识时直接在 `<answer>` 里作答。刻意不加“必须反思”“必须搜索”这类内容偏好，以便观察 RL 自然的学习过程。

奖励只用结果的精确匹配（式 4）：`r_φ(x, y) = EM(a_pred, a_gold)`。不加格式奖励，因为训练出的模型已经能很好地遵守结构；不训练神经奖励模型，沿用 R1 的理由：大规模 RL 中模型对奖励形式敏感，重训奖励模型增加成本和复杂度。

### 2.5 实验配置（4.3 节、附录 B.2）

| 项 | 值 |
|---|---|
| 模型 | Qwen2.5-3B、7B 的 Base 和 Instruct（附录 C 另有 14B） |
| 检索 | E5 检索器，2018 年维基百科语料，默认 top-3 段落 |
| 训练数据 | NQ 和 HotpotQA 训练集合并 |
| 评测 | 7 个问答集（3 个通用、4 个多跳），EM |
| 默认算法 | PPO |
| PPO | 策略学习率 1e-6，价值模型 1e-5；GAE λ = 1、γ = 1；训练 500 步 |
| GRPO | 学习率 1e-6，每题 5 个回答（沿用 verl 的设置） |
| 共同 | KL 系数 0.001，clip 0.2，温度 1.0，top-p 1.0；batch 512，mini-batch 256 |
| 长度 | 序列最长 4096，单次回答最长 500，检索内容最长 500 |
| 动作预算 B | 4 |
| 硬件 | 单节点 8 张 H100，FSDP 加 CPU offload，vLLM 做 rollout |

训练发散时，按训练奖励曲线取最近一个稳定的检查点评测。

## 3 关键实验结论

具体 EM 数字见 [training/04 第 3 节和第 6 节](../tracks/training/04-agentic-rl/README.md#6-search-agent-的-rl以-search-r1-为例)，这里只写结论方向。

- **整体上优于不检索、RAG、IRCoT、Search-o1、SFT、拒绝采样和不带检索的 R1 式 RL 等基线**（表 2），领域内和领域外都成立。Base 和 Instruct 模型都有效。7B 相对第二名的差距比 3B 大，论文认为更大的模型更会学习搜索。
- **PPO 与 GRPO**（5.1 节、图 2a、表 3）：GRPO 收敛更快，因为 PPO 的 critic 需要预热；GRPO 训练久了会出现奖励崩溃，PPO 更稳；最终训练奖励相近。论文因此默认用 PPO。
- **Base 与 Instruct**（5.2 节、图 2b）：Instruct 收敛更快、起点更高，但训练后两者最终奖励非常接近。
- **回答长度先降后升再稳定**（5.3 节、图 2c）：前 100 步左右长度骤降，模型去掉多余的填充词；之后长度和奖励一起明显上升，因为模型开始频繁调用搜索，检索段落让回答变长。有效搜索次数随训练增加（图 2d）。
- **检索 token mask 是关键设计**（5.4 节、表 4、附录 D 图 3 和表 6）：在 3B 和 7B Base 上，屏蔽检索 token 都更稳定、效果更好。
- **每次返回几段**（附录 G、表 7）：top-5 前 200 步收敛最快，之后奖励下降、变得不稳定；top-3 最终最好。论文的推测：1 段召回不够；5 段噪声多，不仅影响推理，还可能让模型在 RL 中学到“检索内容常常没用”，从而少用检索。
- **GRPO 组大小**（附录 H、表 8）：组越大收敛越快、训练奖励越高，但更容易崩溃；组小（大小为 1 时退化为 REINFORCE）训练更稳，在没见过的任务上泛化更好。
- **案例分析**（附录表 10 到表 20）：成功案例包括多步分解、改写查询、在信息足够时停止搜索；失败案例包括没能分解问题、写不出合适的查询、被不相关的检索结果误导。

## 4 局限与后续工作

论文结论里提到的方向：更复杂的奖励机制、根据不确定性动态调整检索、结合多种工具、接入搜索以外的信息源、多模态推理。

从论文设置可以看出的局限（章节里也有总结）：EM 只适合短答案的事实问答；检索环境是静态的维基百科，真实搜索引擎有时效、噪声和费用；动作预算为 4，做不了长链路研究任务；只有结果奖励，多余的检索和必要的检索拿到同样的信号，信用分配粗（见 [training/04 第 4 节](../tracks/training/04-agentic-rl/README.md#4-多轮信用分配)）；GRPO 版本按每条轨迹的有效 token 数归一化，带长度偏差。

同类工作 R1-Searcher 用两阶段奖励先引导模型学会调用检索，对比见 [training/04 第 6 节](../tracks/training/04-agentic-rl/README.md#6-search-agent-的-rl以-search-r1-为例)。多轮训练的长尾和异步 rollout 问题见 [training/04 第 5 节](../tracks/training/04-agentic-rl/README.md#5-异步-rollout-与长尾)；多轮场景下 token 级比率噪声累积的问题，GSPO 给出了序列级的改法，见 [06 GSPO](06-gspo.md)。

## 5 面试常见追问

1. 为什么要屏蔽检索 token？→ 它们不是策略采样出来的，它们在策略下的概率没有意义；对它们算策略梯度等于让模型去“学会生成检索结果”，引入错误的学习信号。屏蔽后它们仍留在上下文里影响后续 token，但本身不产生梯度。论文消融显示屏蔽后更稳、效果更好。用 GRPO 时 KL 也要屏蔽。
2. Search-R1 默认用 PPO 还是 GRPO？为什么？→ 默认 PPO。GRPO 收敛快，但训练久了会奖励崩溃；PPO 需要 critic 预热，但更稳，最终奖励相近。PPO 的 GAE 取 λ = 1、γ = 1，不打折，等价于把末端奖励原样往前传，再减价值基线。
3. 只用 EM 奖励，不加格式奖励和搜索奖励，模型怎么学会搜索？→ 模板规定了结构，基座模型能产生一些带搜索的轨迹；搜索能提高答对率，答对的轨迹被强化，搜索行为跟着被强化。论文观察到有效搜索次数随训练上升。代价是早期探索依赖基座能力；R1-Searcher 用第一阶段的调用奖励解决这个问题。
4. 每次检索返回几段合适？→ 论文实验里 top-3 最好。太少召回不够，太多噪声大，而且噪声会在 RL 中让模型学到“检索没用”。这说明检索质量会通过奖励反过来塑造策略的搜索行为。
5. 训练早期回答变短说明什么？→ Base 模型一开始有很多填充词，RL 先把它们去掉；之后模型开始频繁搜索，检索段落进入序列，长度和奖励一起上升。所以长度曲线要结合有效搜索次数和奖励一起看。
6. 把 Search-R1 用到真实业务的搜索 Agent，要改哪些地方？→ 奖励换成适合开放答案的评分器（F1、评委或规则组合）；检索换成真实搜索并做缓存和超时处理，超时截断不应给负奖励；动作预算放大，配合异步 rollout；考虑加调用次数的效率项或过程信号；loss 聚合改成 token 级或常数分母，避免长度偏差。
