# 01 ReAct：推理与行动交替

> 论文：ReAct: Synergizing Reasoning and Acting in Language Models
> 作者：Shunyu Yao（第一作者）、Jeffrey Zhao、Dian Yu、Nan Du、Izhak Shafran、Karthik Narasimhan、Yuan Cao（Princeton、Google Research Brain team）
> arXiv：[2210.03629](https://arxiv.org/abs/2210.03629)，v1 2022-10-06（本文核对 v3，ICLR 2023 版）
> 相关章节：[core/02 Agent 架构与设计模式](../core/02-agent-architecture/README.md)
> 相关方向：core、harness

## 1 解决什么问题

论文发表前，“让模型推理”和“让模型行动”是两条分开的研究线：

| 做法 | 代表 | 缺陷 |
|---|---|---|
| 只推理 | Chain-of-Thought（CoT） | 推理是“静态黑箱”，只用模型内部知识，不接触外部世界，容易事实幻觉，错误沿推理链传播 |
| 只行动 | WebGPT、SayCan 等用语言模型生成动作或计划 | 不对高层目标做抽象推理，也不维护工作记忆，长任务里会丢失进度、重复无效动作 |
| 半推理 | Inner Monologue（IM） | “内心独白”只是环境反馈的复述（当前状态、还差什么），不是真正的推理 |

论文的判断：当“上下文 → 动作”的映射需要大量隐式计算时（例如要综合前几步的观察才能给出最终答案），直接学这个映射很难，需要一个显式的推理步骤。

## 2 方法

### 2.1 扩展动作空间

论文第 2 节的形式化：

```
c_t = (o_1, a_1, …, o_{t-1}, a_{t-1}, o_t)     # 第 t 步的上下文
a_t ~ π(a_t | c_t)                              # 策略按上下文选动作

Â = A ∪ L                                       # ReAct 的扩展动作空间
c_{t+1} = (c_t, â_t)     若 â_t ∈ L             # 思考只更新上下文
```

- `o_t`：环境在第 t 步返回的观察（即本库说的工具结果）；
- `a_t`：作用于环境的动作，`A` 是任务原有的动作空间；
- `L`：语言空间。从 `L` 里选出的动作叫思考（thought）或推理轨迹，它不改变环境，也没有观察返回，只是把推理结果追加进上下文，供后续步骤使用；
- `π`：策略，本文里是冻结的大模型加 few-shot 提示。

因为 `L` 无限大，在这个空间里学策略需要很强的语言先验，所以论文主要用冻结的 PaLM-540B 加少量人工写的轨迹做提示，不做训练。

### 2.2 两种思考密度

| 任务类型 | 思考怎么出现 | 原因 |
|---|---|---|
| 知识密集推理（HotpotQA、FEVER） | 稠密：每步都是 Thought → Action → Observation | 推理是主体 |
| 决策（ALFWorld、WebShop） | 稀疏：由模型自己决定什么时候插入思考 | 动作步数多，每步都想既浪费又没必要 |

论文列出的思考用途：分解目标、制定计划、注入常识、从观察中提取要点、跟踪进度、处理异常并调整计划。

### 2.3 知识任务的动作空间

为 HotpotQA 和 FEVER 设计了一个简单的维基百科 API，只有三个动作：

```
search[entity]   返回实体页面的前 5 句；页面不存在时返回 top-5 相似实体
lookup[string]   返回当前页面中包含该字符串的下一句（模拟 Ctrl+F）
finish[answer]   结束任务并给出答案
```

论文明确说这个 API 比当时的词法或神经检索器弱得多，目的是逼模型用语言显式推理“下一步查什么”。

### 2.4 与 CoT-SC 组合

论文观察到 ReAct 更“有据”，CoT 推理结构更好但容易幻觉，于是提出两条回退规则：

- **ReAct → CoT-SC**：ReAct 在给定步数内没给出答案，就退回 CoT-SC。步数上限 HotpotQA 为 7、FEVER 为 5。
- **CoT-SC → ReAct**：n 个 CoT-SC 样本里多数答案出现次数少于 n/2（内部知识不够自信），就改用 ReAct。

CoT-SC 基线采 21 条 CoT，温度 0.7，取多数答案。

### 2.5 微调

用 ReAct 生成的 3,000 条答对的轨迹微调 PaLM-8B 和 62B，方法类似 STaR 的自举。

## 3 关键实验结论

- **ReAct 稳定优于只行动（Act）**。知识任务和决策任务都是如此，说明推理对指导行动、尤其是综合最终答案有用。
- **ReAct 与 CoT 互有胜负**。FEVER 上 ReAct 更好，因为支持和反驳的陈述往往只差一点，检索准确知识更关键；HotpotQA 上 ReAct 略差于 CoT。
- **错误分析（表 2，人工标注 200 条 HotpotQA 轨迹）**：CoT 的主要失败模式是幻觉；ReAct 几乎没有幻觉，但推理错误更多，其中一种 ReAct 特有的模式是反复生成之前的思考和动作、跳不出循环；检索没返回有用信息也是 ReAct 失败的重要来源，一旦搜偏就很难恢复。论文把这概括为事实性和灵活性的取舍。
- **组合最好**。两种回退方式各在一个任务上最好，并且只用 3 到 5 个 CoT-SC 样本就能达到 21 个样本的 CoT-SC 水平（图 2）。
- **微调后 ReAct 反超**（图 3）。在 8B、62B 上直接提示时 ReAct 最差，因为小模型从上下文示例里很难同时学会推理和行动；只用 3,000 条轨迹微调后，ReAct 成为四种方法里最好的。微调 Standard 或 CoT 等于教模型背知识，微调 ReAct 或 Act 教的是“怎么查”，后者更能泛化。
- **稀疏思考的价值**（表 3）。ALFWorld 上同样的轨迹去掉思考做 Act 提示，ReAct 在 6 组提示排列下都更好。Act 的典型失败是不会把目标拆成子目标，或丢失环境当前状态。
- **ReAct 优于 IM 式思考**（ReAct-IM 消融）。只复述环境反馈的思考，常常判断不出子目标是否完成、下一个子目标是什么，也缺少“东西可能放在哪”的常识推理。
- **人可以改思考来纠正行为**（图 5）。在 ALFWorld 里删掉一句幻觉思考、补上一句提示，Agent 就能走回正轨。

## 4 局限与后续工作

论文自己承认的局限：

- 动作空间大的复杂任务需要更多示例才能学好，很容易超出上下文长度（第 6 节）。
- 提示方式下能支持的推理和行动行为有限，离领域专用的 SOTA 方法差距还大，作者认为用更多人工标注数据微调是方向。
- 重复循环的问题，作者猜测和贪心解码有关。
- 接入外部环境有风险（查到隐私信息、做出有害动作），实验只用了维基百科和 WebShop 这类没有危险动作的环境（伦理声明）。

后续工作：

- 今天的原生函数调用把 Action 变成结构化输出，但“推理 → 行动 → 观察”的循环没变，见 [core/02 第 4 节](../core/02-agent-architecture/README.md#4-常见模式)。
- 论文结尾提到的“与强化学习结合”，在 Search-R1 这类工作里成了现实：模型通过 RL 学会何时检索，见 [08 Search-R1](08-search-r1.md) 和 [training/04 Agentic RL](../tracks/training/04-agentic-rl/README.md)。
- 循环跑飞、步数失控的问题，工程上由 Harness 的步数预算和终止条件管住，见 [harness/01](../tracks/harness/01-loop-and-harness/README.md)。
- 同一作者后来提出 τ-bench，评测这类 Agent 在多轮对话里能否遵守政策，见 [10 τ-bench](10-tau-bench.md)。

## 5 面试常见追问

1. ReAct 和 CoT 的本质区别是什么？→ CoT 只在语言空间里推理，依赖模型内部知识；ReAct 把思考当成一种不影响环境的动作，和真实动作交替出现，推理决定查什么，查到的结果再修正推理。前者容易幻觉，后者推理灵活性下降、受检索质量影响。
2. 为什么 ReAct 在 HotpotQA 上不如 CoT？→ 论文的错误分析：交替结构限制了推理的灵活性，推理错误更多，包括重复循环；维基 API 很弱，搜不到有用信息时推理被带偏。FEVER 上需要精确事实，检索的价值更大，所以 ReAct 更好。
3. 决策任务里为什么用稀疏思考？→ ALFWorld、WebShop 一条轨迹几十步，每步都想会浪费 token，大部分步骤是机械动作。让模型自己决定何时思考，只在拆目标、判断子目标完成、推断物品位置时插入。
4. ReAct 和 Inner Monologue 有什么区别？→ IM 的独白只是环境状态和剩余目标的复述，属于对外部反馈的反应；ReAct 的思考可以分解目标、引入常识、调整计划。ReAct-IM 消融里 IM 式思考在大多数任务类型上更差。
5. 小模型直接用 ReAct 提示效果差，怎么办？→ 论文图 3：8B、62B 提示时 ReAct 最差，用 3,000 条 ReAct 自己生成的正确轨迹微调后反超所有方法。今天的做法是用轨迹数据做 SFT，再用 RL 进一步训练，见 [training/01](../tracks/training/01-trajectory-data/README.md)。
6. 今天还有必要写 Thought: / Action: 这种文本格式吗？→ 大多数系统改用原生函数调用，动作是结构化 JSON，解析更可靠；思考部分由模型自带的推理能力承担。但循环结构、工具结果写回上下文、需要终止条件，这些和 ReAct 一样。
