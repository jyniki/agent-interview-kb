# 12 投机解码：用小模型猜、大模型验

> 论文：Fast Inference from Transformers via Speculative Decoding
> 作者：Yaniv Leviathan、Matan Kalman（两人为共同一作）、Yossi Matias（Google Research）
> arXiv：[2211.17192](https://arxiv.org/abs/2211.17192)，v1 2022-11-30（本文核对 v2，ICML 2023 版）
> 相关章节：[inference/03 投机解码](../tracks/inference/03-speculative-decoding/README.md)、[inference/05 Agent 服务](../tracks/inference/05-agent-serving/README.md)
> 相关方向：inference

同一时期 DeepMind 的 Chen 等（arXiv 2302.01318，2023-02）独立提出了几乎相同的方法，叫 speculative sampling。本文只精读 Leviathan 等这一篇。

## 1 解决什么问题

大的自回归模型解码慢：生成 K 个 token 要串行跑 K 次模型。

之前的加速方法要么对所有输入同等降本（蒸馏、稀疏化、量化、改架构），要么做自适应计算（早退等）。它们通常要改架构或重新训练，而且不保证输出和原模型一致。

论文的两个观察：困难的语言建模任务里常有容易的子任务，小模型就能近似得很好；大模型推理的瓶颈常常不是算力，而是显存带宽和通信，有空闲算力可以用来提高并发。于是借鉴处理器里的投机执行（例如分支预测），并把它推广到随机的情形：任务以一定概率被需要。

## 2 方法

### 2.1 记号

`M_p` 是要加速的目标模型，`p(x)` 是它在当前前缀下的下一个 token 分布；`M_q` 是草稿模型，分布为 `q(x)`；`γ` 是每轮草稿猜的 token 数。2.2 节指出 argmax、top-k、nucleus、温度等都能写成“从调整后的分布标准采样”（argmax 就是把非最大值置零再归一化），所以下面的 `p`、`q` 都指调整后的分布。

### 2.2 投机采样（2.3 节）与一轮流程（算法 1）

单个 token 的规则：从 q 采 x；若 `q(x) ≤ p(x)` 接受，否则以概率 `1 − p(x)/q(x)` 拒绝；拒绝后从 `p'(x) = norm(max(0, p(x) − q(x)))` 重新采。一轮的完整流程：

```
for i = 1..γ:                                   # 草稿模型自回归猜 γ 个
    q_i(x) ← M_q(prefix + [x_1, …, x_{i−1}]);  x_i ~ q_i(x)

p_1(x), …, p_{γ+1}(x) ← M_p(prefix), …, M_p(prefix + [x_1, …, x_γ])    # 目标模型并行算 γ+1 个位置

r_1, …, r_γ ~ U(0, 1)
n ← min( {i − 1 | 1 ≤ i ≤ γ, r_i > p_i(x_i)/q_i(x_i)} ∪ {γ} )         # 接受的个数

p'(x) ← p_{n+1}(x)
if n < γ:  p'(x) ← norm(max(0, p_{n+1}(x) − q_{n+1}(x)))                # 有拒绝时用修正分布
t ~ p'(x)
return prefix + [x_1, …, x_n, t]
```

每轮至少产出 1 个 token（最坏情况下目标模型串行调用次数也不会多于普通解码），最多 γ+1 个。全部接受时，第 γ+1 个位置的 p 免费再采一个。

### 2.3 正确性证明（附录 A.1）

记接受概率 `β = Σ_x min(p(x), q(x))`，修正分布的归一化常数正好是 `1 − β`：

```
P(接受且 x = x')  = q(x') · min(1, p(x')/q(x')) = min(q(x'), p(x'))
P(拒绝且 x = x')  = (1 − β) · p'(x') = p(x') − min(q(x'), p(x'))
P(x = x')         = min(p(x'), q(x')) + p(x') − min(p(x'), q(x')) = p(x')
```

附录 A.2 还比较了普通拒绝采样：它的接受概率不超过投机采样的接受概率，可能低得多，所以效率更差。

### 2.4 接受率（3.1、3.2 节）

**定义 3.1**：给定前缀，接受率 β 是按投机采样接受 `x ~ q` 的概率。假设各位置的 β 独立同分布，记 `α = E(β)`。一轮产出的 token 数服从上限为 γ+1 的截断几何分布：

```
E(# generated tokens) = (1 − α^(γ+1)) / (1 − α)                 （式 1）
```

论文定义了一个散度并给出 α 的计算方式：

```
D_LK(p, q) = Σ_x |p(x) − M(x)|,  M(x) = (p(x) + q(x)) / 2
引理 3.3：  D_LK(p, q) = 1 − Σ_x min(p(x), q(x))
定理 3.5：  β = 1 − D_LK(p, q)
推论 3.6：  α = 1 − E(D_LK(p, q)) = E(min(p, q))
```

`D_LK` 是 [0, 1] 内的对称散度：p = q 时为 0，支撑集不相交时为 1。

### 2.5 墙钟加速（3.3 节）

```
定义 3.7：c = 草稿模型跑一次的时间 / 目标模型跑一次的时间
定理 3.8：期望墙钟加速 = (1 − α^(γ+1)) / ( (1 − α)(γc + 1) )
推论 3.9：只要 α > c，就存在能加速的 γ，加速至少为 (1 + α)/(1 + c)（取 γ = 1）
```

推导：一轮耗时 `T·cγ + T`（γ 次草稿加 1 次目标前向），产出式 1 那么多 token。前提是有足够算力让 γ+1 个位置并行而不增加墙钟时间，并且生成足够长。α 是模型和任务的固有性质，c 取决于硬件和实现；论文实验里草稿比目标小两个数量级左右，c 一直小于 0.05。最优 γ 可以数值求得（图 3）。

### 2.6 算力代价（3.4 节）

目标模型并行跑 γ+1 个位置，接受时这部分并发是“免费”的，拒绝时计算就浪费了。

```
定义 3.10：ĉ = 草稿模型每 token 的算术运算量 / 目标模型每 token 的算术运算量
定理 3.11：总运算量的期望增长倍数 = (1 − α)(γĉ + γ + 1) / (1 − α^(γ+1))
```

α 低时运算量增加多，反之少。但访存可能反而减少：目标模型的权重和 KV Cache 每轮只读一次，读取次数按式 1 的倍数缩小。这正是在访存受限时能加速的原因。

### 2.7 草稿模型的选择（3.6 节）

- 任何草稿模型都保证输出分布不变。论文主要用现成的同架构小模型，比目标小约两个数量级时 α 和 c 平衡最好。
- **可忽略成本的草稿**（c ≈ 0）：加速为 `(1 − α^(γ+1))/(1 − α)`，上界 `1/(1 − α)`。n-gram 查表也能得到非零的 α；从上下文复制匹配前缀的启发式在摘要、反复改写的对话里可能 α 很高，且不需要参数。非自回归模型也可以当草稿。
- 如果能按预测的 β 动态调整 γ，论文估计加速最多还能提高约 60%（假设算力无限），留作未来工作。

## 3 关键实验结论

以下数字都是论文报告。

- **T5-XXL（11B）上的墙钟加速**（4.1 节、表 2）：英译德和 CNN/DM 摘要两个任务，草稿模型试了 T5-small（77M）、T5-base（250M）、T5-large（800M），单张 TPU-v4、batch 为 1。相比标准 T5X 实现快 2 到 3 倍，输出相同。T5-small 在 c 和 α 之间平衡最好，加速最高：翻译任务温度 0 时 3.4 倍、温度 1 时 2.6 倍；摘要任务分别为 3.1 倍和 2.3 倍。
- **草稿越大 α 越高，但加速不一定更高**（表 2），因为 c 也变大。温度 0 时 α 和加速更高：调整后的分布越尖锐，α 越高。
- **α 的经验值**（4.2 节、表 3）：在 GPT 式 97M、T5-XXL、LaMDA 137B 上测量，比目标小两个数量级左右的草稿 α 通常在 0.5 到 0.9 之间。极简草稿也有用：英译德上 bigram 的 α 约 0.2，因为 c ≈ 0，γ = 3 时也有 1.25 倍加速。
- **理论和实测基本吻合**（附录 A.3、表 4），差异来自实现优化的差别和 β 独立同分布的近似。

## 4 局限与后续工作

论文第 6 节自己承认的局限：用增加的并发换延迟，代价是算术运算量增加，所以在没有额外算力的配置下没有帮助。适用的是显存带宽成为瓶颈、有空闲算力的常见情况。

论文列出的后续方向：和束搜索兼容（附录 A.4 给了一个有性能损失的方案）；定制草稿模型（定制架构、用目标模型软标签蒸馏、直接优化 α）；草稿本身再用更快模型加速的分层版本；推理中动态调整草稿和 γ。附录 A.5 还提出“宽容度”参数 l：比较前把 q 乘以 l，接受率更高，但输出分布不再严格不变，只保证没有 token 的采样概率超过 `p(x)/l`；除这一节外论文都用严格版本。

后续工作，详见 [inference/03 第 5 节](../tracks/inference/03-speculative-decoding/README.md#5-草稿从哪来)：

| 方向 | 代表 |
|---|---|
| 不要独立草稿模型，在目标模型上加解码头，树形验证 | Medusa |
| 在特征层上预测，草稿更准 | EAGLE、EAGLE-3 |
| 训练时就有多 token 预测模块，推理时当草稿 | DeepSeek-V3 的 MTP |
| 从上下文复制（论文 3.6 节已提出） | n-gram / prompt 查找 |

大批量服务时 Decode 不再纯粹受带宽限制，“验证 γ+1 个位置和算 1 个一样快”的前提可能不成立，见 [inference/03 第 6 节](../tracks/inference/03-speculative-decoding/README.md#6-和大批量服务的冲突)。Agent 场景里输出常复述工具结果或代码，prompt 查找类草稿的 α 可能很高，见 [inference/03 第 7 节](../tracks/inference/03-speculative-decoding/README.md#7-agent-场景怎么看)。

## 5 面试常见追问

1. 为什么投机解码不改变输出分布？→ 接受概率取 `min(1, p/q)`，接受且输出 x 的概率是 `min(p, q)`；拒绝后从 `max(0, p − q)` 归一化后的分布采，拒绝且输出 x 的概率是 `p − min(p, q)`；两者相加正好是 p(x)。草稿高估的部分被拒掉，低估的部分由修正分布补上。
2. 为什么第一次拒绝后，后面的猜测都要丢？→ 后面的猜测是以被拒绝的 token 为前提生成的，前提换了，它们的条件分布就不对了。目标模型在那些位置算出的 p 也是以错误前缀为条件。
3. 加速比公式是什么？哪个变量最重要？→ `(1 − α^(γ+1)) / ((1 − α)(γc + 1))`。α 最重要，由草稿和目标的接近程度、任务决定；γ 加大收益递减，α 不高时多猜的大多被丢掉；c 变大直接吃掉收益。只要 α > c 就存在能加速的 γ。
4. 投机解码为什么能加速？它省了什么、多花了什么？→ Decode 访存受限，验证 γ+1 个位置和算 1 个位置读的权重和 KV 一样多，耗时接近；每轮目标模型只读一次权重，访存次数按期望产出的 token 数缩小。多花的是算术运算：拒绝的猜测白算了，总运算量按定理 3.11 增加。所以没有空闲算力时不划算。
5. 温度为 0 时规则变成什么？→ p 和 q 都是 one-hot。草稿 token 等于目标的 argmax 就接受，否则换成目标的 argmax 并停止。论文观察到温度 0 时 α 更高，因为分布越尖锐 α 越高。
6. 草稿模型怎么选？→ 同 tokenizer、同分布标准化，比目标小约两个数量级时 α 和 c 平衡最好；c 几乎为 0 的 n-gram 或上下文复制也能有可观的加速；更大的草稿 α 更高但 c 也高，不一定更快。
