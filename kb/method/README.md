# 面试方法

> 阅读材料，不出题。学习教练 skill 不会从这里组卷。

## 1 这部分讲什么

知识章节解决“知道什么”。这部分解决“怎么说出来”。

同样懂 PPO 的两个人，面试结果可能差很多。差距常在三处：

- 结论埋在第三分钟，面试官没听到；
- 只讲做法，不讲代价，追问一层就接不住；
- 讲项目时说不清哪部分是自己做的，数字说不出口径。

这几份材料把这些问题拆开讲，每份都给虚构的对比示例。

## 3 和知识章节的关系

| | 知识章节（`kb/core`、`kb/tracks`、`kb/design`） | 面试方法（本目录） |
|---|---|---|
| 内容 | 原理、做法、代价 | 表达结构、准备方法 |
| 有没有题 | 有 `questions.md`，可以闭卷练、打分 | 没有题，只读 |
| 怎么用 | 学完一章，用 skill 练题 | 读一遍，然后在练题时套用 |
| 示例来源 | 公开论文和资料 | 全部虚构 |

方法不能替代知识。追问到第三层时，靠的是原理，不是结构。

本目录引用的例题都来自知识章节，链接到所在的 `questions.md`。读的时候先自己答一遍，再看示例。

## 4 什么时候读

| 时间点 | 读哪份 | 为什么 |
|---|---|---|
| 刚开始准备，学完一两章 | 01 | 尽早养成结论先行的习惯，后面练题都用上 |
| 投简历前一到两周 | 02、03 | 项目稿和故事库要写、要改、要讲几遍，留出时间 |
| 第一次模拟面试前 | 04 | 知道模拟和日常练习的区别，以及复盘怎么记 |
| 每次真实面试后 | 04 第 4 节 | 面后 30 分钟内的动作，越早做记得越清楚 |

太早读 02 和 03 收益不大：项目和故事要结合目标岗位改。太晚读 01 代价大：已经练出的长篇铺垫习惯不好改。

## 5 常见误区

| 误区 | 实际情况 | 见哪份 |
|---|---|---|
| 准备一套标准答案背下来 | 面试官顺着你的话追问，背的内容接不住第二层 | 01 第 3 节 |
| 回答越长显得越懂 | 结论晚出现，面试官会打断或换题 | 01 第 2 节 |
| 项目数字越大越好 | 说不出口径的数字会被追问到失分 | 02 第 5 节 |
| 项目里的事都说成“我做的” | 追问细节接不住，会被判为夸大 | 02 第 6 节 |
| 行为题临场发挥就行 | 临场想到的故事常常不切题，或重复使用 | 03 第 5 节 |
| 经历不够就编一个 | 行为题追问细节最多，编的故事最容易露馅 | 03 第 6 节 |
| 刷题分数高就不用模拟 | 没有提示、连续追问时，分数常会掉一档 | 04 第 2 节 |
| 面完再说，过几天复盘 | 一两天后题目和追问会忘掉大半 | 04 第 4 节 |

## 6 推荐读法

1. 先通读 01，然后任选一道已学章节的题，按四段结构讲一遍。
2. 02 和 03 边读边写：读完一节，就在本地文件里写出自己的版本。
3. 04 读完后约一次模拟面试，用复盘模板记一次。
4. 之后每次练题、每次面试，回来对照自测清单。

## 7 隐私

这部分最容易写进个人信息。约定如下：

- 本目录所有示例都是虚构的，每个示例开头标有“以下为虚构示例”。
- 你自己的项目稿、故事库、复盘记录，放在本地，例如 `~/.agent-interview-kb/`，不要提交到仓库。
- 想把一道真实面试题贡献回来，去掉公司、轮次、面试官信息，按 [CONTRIBUTING.md](../../CONTRIBUTING.md) 的题目格式写。
