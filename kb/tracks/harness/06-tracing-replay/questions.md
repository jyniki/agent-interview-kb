# 题目：Trace、回放与成本统计

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## harness-trace-001 Agent 的一条轨迹记录要包含哪些字段
- level: 2
- tags: [harness, evaluation]

**一句话答案**：每个 Step 一条结构化事件：三级编号和父步骤、trace_id、起止时间、版本指纹、模型调用（模型、结束原因、分项 token、上下文引用）、工具调用（参数引用、状态、错误、重试、幂等键）、预算。

**要点**：
- 工具调用还要记有无副作用。
- 三级编号是 Task/Turn/Step；模型要分别记请求的和实际响应的。
- 三级编号加父步骤，才能把并行子 Agent 和重试排出顺序。
- 版本指纹包含 prompt、模型、工具集和 Harness 版本，用来区分“新版本的问题”和“一直存在的问题”。
- 记实际发给模型的上下文，不是消息历史。压缩、裁剪、检索注入之后两者不同。
- 大正文单独存，事件里只放引用，并按内容哈希去重，否则存储随步数近似平方增长。

**追问链**：
1. 为什么 `request_model` 和 `response_model` 要分开记？→ 请求里常是别名，响应里才是实际服务的版本；复现和归因要按后者。
2. 工具调用为什么要记有无副作用？→ 恢复和回放时要知道哪些动作已经生效。有副作用的动作在重放里只能走桩，在恢复时要先查结果再决定是否重做。
3. 只存消息历史行不行？→ 不行。看不到压缩后的摘要和注入的检索结果，就判断不了错因是模型还是上下文。

**易错点**：
- 只按 Turn 记日志。出错时只知道哪一轮错了，不知道是哪一步的工具返回导致的。
- 每步都存完整上下文原文、不去重。

## harness-trace-002 用 OpenTelemetry 给 Agent 打点，Span 树长什么样
- level: 2
- tags: [harness]

**一句话答案**：一次运行一个 Trace：根 Span 是 invoke_agent，下挂推理 Span（chat）和工具 Span（execute_tool），子 Agent 再嵌套一层；属性按 GenAI 约定。

**要点**：
- Span 类型：推理 Span 是 CLIENT，工具 Span 是 INTERNAL。
- 属性前缀是 `gen_ai.*`。
- Span 名带上对象：`invoke_agent {agent名}`、`chat {模型}`、`execute_tool {工具名}`。
- 推理 Span 记 `gen_ai.provider.name`、`gen_ai.request.model`、`gen_ai.response.model`、`gen_ai.response.finish_reasons` 和 `gen_ai.usage.*`。
- 工具 Span 记 `gen_ai.tool.name`、`gen_ai.tool.call.id`；失败时 Span 状态设 Error 并填 `error.type`。
- 输入输出消息、工具参数和结果都是 Opt-In，默认不采；可以用 `*_ref` 属性指向外部存储。
- GenAI 约定 2026-11 仍是 Development 状态，已移到单独仓库，属性名可能还会变。

**追问链**：
1. 工具在另一个服务里执行，Trace 怎么接上？→ 用 W3C TraceContext 的 `traceparent` 请求头传 trace ID 和父 Span ID，下游从这里继续。
2. 任务暂停等审批，几小时后恢复，还用同一个 Trace 吗？→ 常见做法是恢复时开新 Trace，用 Span Link 指回暂停前的 Span，Task ID 写在每个根 Span 的属性上。
3. 能把用户 ID 放进 Baggage 一路传下去吗？→ OTel 文档建议不要放凭据和个人信息，下游可能记日志或转发给不可信的服务。

**易错点**：
- 把 `gen_ai.agent.name` 设成框架默认名或类型名。它要求低基数且有意义，否则聚合时分组没有意义。
- 以为装了自动埋点就够了。自己写的工具调用要手动打 Span。

## harness-trace-003 线上 bad case 重跑复现不了，怎么办
- level: 3
- tags: [harness, inference]

**一句话答案**：不要靠重跑。先用记录做确定性重放：模型输出和工具结果都从日志注入，只重跑 Harness 代码，把问题定位到某一步的上下文；再从这一步起调真实模型多次，看错误率。

**要点**：
- 重跑不一样的来源：采样随机性、服务端数值不确定、推理批次变化、外部数据变化、上下文装配不同。
- Anthropic 文档写明 temperature 为 0 也不完全确定；OpenAI 的 `seed` 是 Beta，只承诺尽力确定，并让你用 `system_fingerprint` 观察后端变化。
- Thinking Machines 的分析：负载变化导致 batch size 变化，算子不是批次不变的，同一请求的数值就会变。
- 确定性重放要求模型、工具、时钟、随机数都经过可替换接口，记录时存，重放时注入。

**追问链**：
1. 自部署能做到完全可复现吗？→ vLLM 文档说默认不保证；离线可以关多进程或开批次不变，在线只能开批次不变；而且只在同一硬件、同一版本下成立。代价是吞吐。
2. 重放时工具调用怎么处理？→ 全部走桩，返回记录的结果。有副作用的工具绝不能真执行，否则重放本身就是一次事故。
3. 修复后怎么证明修好了？→ 把第 k 步的上下文快照和工具桩存成回归用例，从这一步起跑多次，看错误率是否下降；不能只看一次重跑通过。

**易错点**：
- 一次重跑结果正确，就认为问题“偶发、不用管”。
- 只记了用户输入，没记实际发给模型的上下文，导致无法重放。

## harness-trace-004 多家模型混用，token 和成本怎么统计才不算错
- level: 2
- tags: [harness, inference]

**一句话答案**：先在网关把各家 usage 归一成四项：未缓存输入、缓存读、缓存写、输出（总输入为前三项之和），再按带生效日期的价格表算钱；总量用指标统计，只取推理类 Span，避免重复计数。

**要点**：
- 口径不同：Anthropic 的 `input_tokens` 只是最后一个缓存断点之后的部分，总输入要加上缓存读和缓存写；OpenAI 的 `input_tokens` 已包含 `cached_tokens`。
- Anthropic 价格文档：5 分钟缓存写 1.25 倍、1 小时缓存写 2 倍、缓存读取 0.1 倍（查阅于 2026-11，以定价表为准）；Batch API 输入输出五折，可叠加。
- 服务端工具（如网页搜索）按次数另外计费，不在 token 里。
- 不同模型分词器不同，同一文本 token 数不同，换模型不能套用旧的 token 数。

**追问链**：
1. 为什么不能把所有 Span 的 `gen_ai.usage.*` 加起来？→ OTel 约定警告，同一批 token 可能同时出现在 Agent Span 和推理 Span 上，也可能被网关和推理服务各报一次。只取推理操作的 Span，按 `service.name` 分组。
2. 为什么总量用指标不用 Trace？→ Trace 会被采样，加总会少算；token 计数器指标不受采样影响。
3. 怎么比较两个功能的成本？→ 按“每个成功任务的成本”比，失败任务的花费也要计入。

**易错点**：
- 把 Anthropic 的 `input_tokens` 当作总输入，低估输入量和缓存命中率的分母。
- 用当前价格重算历史账单。

## harness-trace-005 Trace 里有用户数据，采样、保留和脱敏怎么设计
- level: 2
- tags: [harness]

**一句话答案**：结构化字段全量记、保留久；正文按比例采样，出错和超预算的用尾部采样全部留下；正文先脱敏、单独存、权限严、保留短，并能按用户删除。

**要点**：
- 头部采样简单高效，但保证不了“出错的都留下”；尾部采样能按错误、时延决定，但组件要有状态、缓存大量数据，运维难。
- OTel GenAI 约定里内容类属性默认不采；OpenAI Agents SDK 的 `trace_include_sensitive_data` 默认是 `True`。接入框架先查默认值。
- OpenAI Agents SDK 文档提醒：注册在导出器之前的脱敏处理器，脱敏失败时不能阻止导出器收到数据。脱敏失败要丢弃正文。
- Trace 的访问按审计日志的标准管。

**追问链**：
1. 为什么不全量存正文？→ 存储成本高，Trace 本身也成了敏感数据；大部分正常请求复盘用不到正文。
2. 被用户差评的请求怎么保证留下？→ 差评通常在请求结束后才到。可以先把正文写到短期存储，在保留窗口内收到差评再转入长期存储。
3. 删除请求怎么做？→ 正文按用户或会话 ID 建索引；Trace 里只放引用，删正文即可，结构化字段可以匿名化后保留。

**易错点**：
- 只做头部采样，出事时那条 Trace 恰好没采到。
- 把 API Key、用户手机号放进 Baggage 或 Span 属性。

## harness-trace-006 设计题：给一个多租户 Agent 平台设计 Trace 与成本系统
- level: 3
- tags: [harness, inference, evaluation]

**一句话答案**：Harness 和网关两处打点：Harness 按 OTel GenAI 约定出 Span 树，正文外存只留引用；网关归一 usage、按价格表算钱；上层做重放、按租户归因成本、坏样本转回归。

**要点**：
- 重放指确定性重放；成本还要按功能归因。
- 网关按归一后的 usage 出成本指标。
- 数据层：结构化事件（编号、版本指纹、分项 token、状态）进列存，正文按内容哈希去重进对象存储，Trace 后端存 Span。
- 采样：结构化字段全量；正文比例采样；出错、超预算、差评的尾部保留。
- 成本：网关归一口径，价格表带生效日期；租户、功能、Task、Agent 作为指标维度；预算超限的告警用指标，不靠 Trace。
- 回放：Harness 的模型、工具、时钟可替换；重放时有副作用的工具一律走桩。
- 安全：脱敏失败丢弃正文；按租户隔离 Trace 的访问；支持按用户删除。

**追问链**：
1. 怎么发现成本异常？→ 看每个成功任务的成本和缓存命中率。命中率突然下降，多半是有人改了 system prompt 或工具定义的顺序，破坏了稳定前缀。
2. 子 Agent 的成本怎么算到父任务上？→ 子 Agent 的 Span 挂在父 Task 下，Task ID 作为属性和指标维度；预算由一个服务端计数器统一扣减。
3. 平台接入了第三方框架，它自己也打 token 属性，怎么办？→ 统计只取推理类 Span 或网关指标，避免框架层和网关层重复计数。

**易错点**：
- 只设计存储，不设计回放和回归用例，Trace 只能看不能用。
- 成本统计依赖被采样的 Trace。

## harness-trace-007 怎样从一棵 Span 树算出模型、工具和 Harness 各占多少时间
- level: 2
- tags: [harness]

**一句话答案**：按类型加总 Span 时长得到模型和工具时间；自身耗时 = 时长减直接子 Span 区间并集长度，根 Span 的自身耗时是 Harness 开销，所有自身耗时之和等于根 Span 时长。

**要点**：
- Span 只记父 ID，后端按 parent span ID 拼树；孩子先结束、先上报，根 Span 最后到。
- 子 Span 串行时，自身耗时 = d(s) − Σ d(c)；并行时要用区间并集，直接相减会得负数。
- 每段时间只属于覆盖它的最深那个 Span，所以自身耗时加总恰好等于根 Span 时长。
- 想知道缩短哪段能让任务变快，看关键路径：并行子 Agent 里只有最慢的在关键路径上。

**追问链**：
1. 主 Agent 并行派出 3 个子 Agent，各跑 10 秒，父 Span 11 秒，自身耗时是多少？→ 子区间并集约 10 秒，自身耗时约 1 秒；直接减 30 秒得 −19 秒是错的。
2. Trace 里出现没有父亲的孤儿 Span，可能是什么原因？→ 跨进程没传 traceparent、线程池没带上 context，或父 Span 因进程崩溃没上报。
3. 为什么尾部采样要等根 Span 到了才做决定？→ 根 Span 最后结束，到了它才知道整个 Trace 的时长和有没有错误。

**易错点**：
- 把所有 Span 的时长加起来当总耗时，父子重叠的时间被重复计算。
- 并行子 Span 也用“父时长减子时长之和”算自身耗时。

## harness-trace-008 错误率 0.5%、头部采样 10%，一次有 k 条错误 Trace 的事故全部漏掉的概率是多少，尾部采样怎么改
- level: 2
- tags: [harness]

**一句话答案**：头部采样不看结果，每条错误留下的概率是 10%，全部漏掉为 0.9^k：k=1 时 90%，k=20 时约 12%；尾部采样把错误全留、其余低比例留，错误留存 100%，存储更少。

**要点**：
- 一致性头部采样按 trace ID 哈希决定，同一 Trace 在各服务上决定一致，留下的是完整 Trace。
- 尾部采样：错误 0.5% + 慢请求 1% + 其余 1%，约留 2.5%，是头部 10% 的四分之一左右。
- 尾部采样器内存约等于到达率 × decision_wait；Collector 默认 decision_wait 30 秒、num_traces 5 万。
- 用尾部采样留下的 Trace 算错误率会被放大（例子里约 20%，真实 0.5%），比例和总量要从指标算。

**追问链**：
1. 到达率 2000 条/秒时尾部采样器会怎样？→ 2000 × 30 = 6 万条，超过默认 num_traces 5 万；block_on_overflow 默认 false，最老的 Trace 被驱逐。
2. 一个任务跑 5 分钟，尾部采样会出什么问题？→ 30 秒后就做了决定，后面的 Span 晚到；decision_cache 默认大小为 0，晚到的 Span 拿不到之前的决定。要拆成多个 Trace 或调大缓存。
3. 用户差评在请求结束一小时后才到，怎么保证正文还在？→ 正文先写短期存储，保留窗口内收到差评再转长期；尾部采样器早已做完决定，靠不上。

**易错点**：
- 以为头部采样 10% 就能“抓住大部分错误”，单条 bad case 其实 90% 查不到。
- 直接用采样后的 Trace 算错误率或 token 总量。

## harness-trace-009 确定性回放要录制哪些东西，回放时怎样发现分叉
- level: 3
- tags: [harness, evaluation]

**一句话答案**：录制 Harness 和外界的每个接触点：模型完整响应、工具结果、时钟、随机数、配置版本，每个事件再记请求指纹；回放时按顺序注入结果，逐个比对调用类型和请求指纹，录制提前用完或没用完都算分叉。

**要点**：
- 前提是 Harness 是确定性函数，输入只有用户请求和外部调用的返回值。
- 请求指纹：把发给模型的上下文、工具名和参数规范化后取哈希，计算前去掉时间戳、随机 ID 这类易变字段。
- 改了代码后的分叉位置就是修复生效的位置；没改代码也分叉，说明有漏录的外部输入。
- 回放模式下默认不调任何真实工具，有副作用的工具绝不执行。

**追问链**：
1. 同一份录制、同一版代码，回放却分叉了，先查什么？→ diff 分叉那一步录制的请求和回放的请求，常见原因是直接调了 time、uuid、环境变量，或集合遍历顺序不稳定。
2. 想验证改 prompt 后工具调用是否不变，指纹怎么取？→ 只取工具名和参数，不取整段上下文，否则改了 prompt 第一次模型调用就分叉。
3. 从第 k 步重新执行怎么实现？→ 前 k 个事件走回放，第 k 步起模型调真实服务，工具仍走桩或沙箱，跑多次看错误率。

**易错点**：
- 只录模型输出，不录时钟和随机数，回放在超时判断或随机 ID 处分叉。
- 回放层只拦截模型，工具仍走真实实现，重放时二次退款。

## harness-trace-010 一次调用未缓存输入 1500、缓存读 14000、缓存写 500、输出 400，输入 3 美元、输出 15 美元每百万 token，缓存写 1.25 倍、读 0.1 倍，成本多少，前缀被改后变多少
- level: 2
- tags: [harness, inference]

**一句话答案**：1500×3 + 500×3×1.25 + 14000×3×0.1 + 400×15 = 16575，约 0.0166 美元；前缀被改后缓存读全变成缓存写，约 0.065 美元，约 3.9 倍。

**要点**：
- 四项口径：总输入 = 未缓存输入 + 缓存读 + 缓存写 = 16000，缓存命中率 = 14000 / 16000 = 87.5%。
- 价格表要带生效日期，按调用当天的价格算。
- 只写一次、不再读的缓存比不缓存更贵：写入按 1.25 倍计。
- 命中率突然下降，多半是 system prompt 开头加了可变内容或工具定义顺序变了。

**追问链**：
1. 同一 Trace 里 Agent Span、Harness 推理 Span、网关推理 Span 都报了 usage，直接加会怎样？→ 算成 3 倍。只取推理类 Span，按 service.name 分组，各组应能互相对账。
2. 功能 A 每任务 0.10 美元、成功率 90%，功能 B 每任务 0.08 美元、成功率 60%，哪个更省？→ 按每个成功任务算：A 约 0.111，B 约 0.133，A 更省。
3. Task ID 能不能做成本指标的标签？→ 不能，基数太高会让时序数据库序列数爆掉；Task ID 只放 Trace 和 Step 记录。

**易错点**：
- 把 Anthropic 的 input_tokens 当总输入，命中率分母算错。
- 用当前价格重算历史账单。
