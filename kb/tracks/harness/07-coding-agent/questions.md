## harness-code-001 Coding Agent 找代码上下文，为什么不能只靠向量库
- level: 2
- tags: [harness, core]

**一句话答案**：代码查询多是已知标识符、报错、调用关系，grep 和符号索引更准、不过期；向量检索只在知道功能不知道名字时补位，切块还破坏结构。常用组合：repo map、grep 和跳转定义、语义检索找入口。

**要点**：
- 目录树或 repo map 给全局视图，grep 和跳转定义做精确查找。
- grep：字面匹配，无需索引，永远最新；不懂语义。
- 符号索引（AST、LSP）：定义、引用、调用方；要按语言维护解析器。
- 向量检索：语义召回；要建索引、随代码变化过期；相似不等于相关。
- SWE-bench 论文发现，塞进更多检索文件会让效果下降，定位比召回更重要。

**追问链**：
1. 有可以引用的组合实践吗？→ Cursor 的文章比较了只用 grep 和 grep 加语义检索，结论是组合最好，大仓库收益更明显。Agentless 也把模型挑选的文件和向量检索结果合并。
2. 搜索结果太多怎么办？→ 限量返回。SWE-agent 的搜索命令最多返回 50 条，超过就不给结果，提示模型写更具体的查询。
3. 怎么给模型一个全局视图又不占太多 token？→ 目录树加文件骨架（只有类和函数签名），或 Aider 那样用 tree-sitter 建依赖图、按引用排序，在 token 预算内放最重要的符号。

**易错点**：
- 把整个文件全文塞进上下文。Agentless 的对比里，只给骨架比给完整文件效果更好。
- 忘了索引会过期：Agent 自己刚改了代码，向量索引里还是旧的。

## harness-code-002 仓库规则文件怎么进上下文，为什么写了规则 Agent 还会违反
- level: 2
- tags: [harness, core]

**一句话答案**：工具在启动时沿目录树发现 AGENTS.md 或 CLAUDE.md，从根往下拼接，越靠近工作目录的越后出现；它作为上下文送给模型，不是强制配置，所以必须遵守的规则要用 hook 或权限规则来拦。

**要点**：
- Claude Code：加载当前目录及上级目录的 CLAUDE.md，子目录的按需加载；全部拼接不覆盖；内容作为 system prompt 之后的用户消息送入。
- Codex：从项目根走到当前目录，每级最多一个文件，越靠近的越后出现从而覆盖前面；合并后默认上限 32 KiB；启动时组装一次。
- 规则文件越长遵守率越低；Claude Code 建议每个文件 200 行以内，只对部分目录有效的规则用按路径生效的规则文件。
- 规则互相矛盾时，模型可能随便挑一条。

**追问链**：
1. 上下文压缩后规则还在吗？→ Claude Code 文档写明项目根的 CLAUDE.md 会从磁盘重读；子目录文件和按路径生效的规则要再次匹配到才加载；只在对话里说过的规则可能丢。
2. 一条规则反复被忽略怎么办？→ Claude Code 最佳实践的判断：加强调也没用，说明它该变成 hook 或权限规则；只是偏好的 hook 反而该删掉。
3. 克隆了一个第三方仓库，里面的规则文件可信吗？→ 不可信。规则文件是仓库内容，可能带注入指令，要按不可信输入对待，权限仍由 Harness 控制。

**易错点**：
- 把规则文件当作权限系统。它只影响模型的倾向，挡不住动作。
- 以为子目录的规则文件启动时就生效了。

## harness-code-003 Coding Agent 的编辑工具怎么设计
- level: 2
- tags: [harness]

**一句话答案**：常用查找替换：原文片段必须唯一匹配，否则拒绝；路径要求绝对路径；编辑后跑 linter，语法错的修改退回。整文件重写浪费 token 且容易改坏；diff 要模型算对行数，容易出错。

**要点**：
- Anthropic 的编辑工具：`view`、`create`、`str_replace`、`insert`、`undo_edit`；`old_str` 必须恰好匹配一处。
- Anthropic 发现 Agent 离开根目录后会用错相对路径，改成必须传绝对路径后问题消失。
- SWE-agent：查看窗口最多 100 行；编辑后跑 linter，无效修改丢弃；只保留最近 5 次工具结果的全文。
- Anthropic 的建议：格式贴近模型在网上常见的文本，给模型足够的 token 先思考。

**追问链**：
1. 为什么不用 unified diff？→ 写 diff 要在 hunk 头里先写出改了几行，模型在写代码之前就得算对，容易错。
2. 按行号替换有什么问题？→ 文件改过一次，后面的行号就漂移了，连续多处修改容易改错位置。
3. “唯一匹配”失败了怎么办？→ 把失败原因写回，让模型带上更多上下文行重新给出原文片段；不要自动选第一个匹配。

**易错点**：
- 只花时间调 prompt，不调工具。Anthropic 的 SWE-bench Agent 在工具上花的时间比 prompt 多。

## harness-code-004 AI 生成的代码怎么验证、审查和回滚
- level: 2
- tags: [harness, evaluation]

**一句话答案**：先写或找到能复现问题的失败测试，改完跑静态检查、相关测试和回归测试；在看不到原对话的独立上下文里对照需求审查 diff；回滚靠小步提交和独立分支，会话检查点只管文件编辑，外部副作用只能事前审批。

**要点**：
- 复现先行：Agentless 只保留能在原代码上复现问题的测试，用它筛选补丁。
- 完成要有证据：运行过的命令和输出，而不是一句“测试都过了”；必须通过的检查可以做成 Stop hook。
- 审查范围要写清，例如只报影响正确性的问题；否则审查者总能找到点什么，全改了会引入多余抽象。
- Claude Code 的检查点不跟踪只经过 Bash 修改的文件，也不能替代版本控制。

**追问链**：
1. 为什么审查要独立上下文？→ 同一个上下文里，审查会被写代码时的推理说服。
2. 审查者也是模型，它总能挑出点问题，怎么办？→ 写清审查范围，例如只报影响正确性的问题，每条意见要附可复现的证据；范围外的意见不改。
3. 出了问题谁负责？→ 提交和合并的人。AI 可以生成，提交者必须理解、审查、验证。

**易错点**：
- 测试输出全量塞回上下文。测试脚本应只打几行摘要，详情写日志文件，错误行带 `ERROR` 方便 grep。

## harness-code-005 设计题：让多个 Coding Agent 并行改同一个仓库
- level: 3
- tags: [harness, core]

**一句话答案**：每个 Agent 一个隔离工作区（worktree 或容器）和独立分支，测试数据库和端口也各自独立；任务按模块切分，用锁文件或调度器领任务；完成后同步、跑测试再推送；合并主干由 CI 和人把关。

**要点**：
- CI 保证新提交不破坏已有功能。
- worktree 共享提交历史，各自有 `HEAD` 和 index；同一分支默认不能同时检出到两个 worktree。
- worktree 是全新检出，依赖要重装，被忽略的 `.env` 默认不会带过去（可用 `.worktreeinclude` 复制）；测试数据库、端口也要各自独立。
- Anthropic 并行写 C 编译器的做法：每个 Agent 一个容器，克隆共享上游；`current_tasks/` 下的锁文件领任务；合并冲突常见，由 Agent 自己处理；没有编排 Agent。
- 测试和对照答案（如用已知正确的编译器对比）是并行能成立的前提，验证器不准，Agent 会解决错的问题。

**追问链**：
1. 两个 Agent 必须改同一个文件怎么办？→ 先看能不能按函数或模块拆开；拆不开就串行，或者指定一个 Agent 负责这个文件，另一个通过它提需求。
2. 任务拆不开时怎么并行？→ 找一个可以逐项对照的基准，把大任务拆成独立的小失败。那篇文章编译 Linux 内核时，用 GCC 当对照，让各 Agent 修不同文件里的不同 bug。
3. Agent 崩了，锁一直不释放怎么办？→ 锁带上持有者和时间戳，设租约；超时后由其他 Agent 或调度器检查分支状态再回收。

**易错点**：
- 多个 Agent 共用一个工作目录，只靠提示词约定“别动别人的文件”。
- 只隔离代码，不隔离数据库和端口，测试互相污染。

## harness-code-006 Computer-Use Agent 用截图、DOM 还是无障碍树
- level: 2
- tags: [harness]

**一句话答案**：网页优先读无障碍树，用元素引用操作，它短、语义清楚、不怕布局变化；树里没有的内容（Canvas、视频、远程桌面）和视觉状态用截图加坐标；不给原始 DOM，免得隐藏文本带进注入。

**要点**：
- 树里看不到的还有跨域 iframe。
- 截图最通用，但要点得准；OSWorld 里只看截图时，失败样例超过 75% 有点击不准的问题。
- 原始无障碍树可达上百万 token，要过滤到标签、名字、文本、位置、大小；过滤后单次界面读取仍要约 6,000 token 才覆盖约 90% 的情况。
- 截图加编号标记省去算坐标，但元素多、需要坐标级操作时不占优。
- Anthropic 浏览器工具文档：典型页面读树的 token 通常比截图少，建议先读树再截图。

**追问链**：
1. 截图缩小后坐标怎么办？→ Anthropic 和 OpenAI 的文档都要求把模型返回的坐标按缩放比例换算回真实屏幕；macOS Retina 屏截图是逻辑分辨率的两倍，要么缩图一半，要么坐标减半。
2. 元素引用失效了怎么办？→ 页面导航或 DOM 大改后引用失效。执行器返回明确的错误，让模型重新读页面；不要重新编号已经发出去的引用。
3. 下拉框、滚动条点不准？→ Anthropic 文档建议改用键盘快捷键。

**易错点**：
- 把原始 DOM 整个给模型：太长，而且隐藏元素里的文字可能是注入。

## harness-code-007 设计题：GUI Agent 怎么确认动作生效、处理不可逆操作和续跑
- level: 3
- tags: [harness, evaluation]

**一句话答案**：每个动作后由执行器比对前后状态，结束时独立查真实结果；批量动作遇错即停；不可逆操作在执行器里逐个动作前让人确认，页面文字不能授权；续跑从 Checkpoint 恢复、重新看界面，结果未知的先查再决定。

**要点**：
- 批量动作按序执行。
- 模型自查：每步截图并用一句话说明是否成功（Anthropic 文档的提示词）。但文档也写明模型有时不检查就当作成功了，所以要加执行器检查。
- 执行器检查：URL、焦点、目标元素的值、无障碍树差异；动作后等页面稳定再读取界面。
- 终态检查：OpenAI 文档要求保存后检查结果再报告成功；OSWorld 用脚本检查机器最终状态。
- 确认范围：购买、数据传输（包括往表单里填敏感信息）、破坏性修改、接受条款、接受 Cookie。确认要在每个动作执行前做，因为一次响应可能带多个动作。
- 环境：专用虚拟机或容器、最小权限、无凭据的全新浏览器配置、网络层的域名白名单。

**追问链**：
1. 重试多少次？→ 有上限。同一动作失败后换方式（键盘代替鼠标、引用代替坐标），再失败就停下报告，不无限重试。
2. 续接一次 API 响应能恢复浏览器状态吗？→ 不能。OpenAI 文档写明它不会恢复浏览器会话、登录状态和运行时变量，要自己重建并重新读取界面。
3. “提交订单”点了之后进程崩了，恢复时怎么办？→ 先查订单页或接口确认是否已提交；确认已提交就记录结果继续，没有就交给人决定，不自动重点。

**易错点**：
- 只信模型最后一句“已完成”。
- 把确认做在模型层（让模型自己问用户），而不是在执行器里强制拦截。

## harness-code-008 SWE-agent 提出的 Agent-Computer Interface 有哪些设计原则
- level: 2
- tags: [harness]

**一句话答案**：动作简单好懂；动作紧凑，一步完成一个高层操作；反馈有信息量但简洁；用护栏防止错误扩散、加快恢复。核心是接口为模型设计，不照搬给人用的 shell。

**要点**：
- ACI 规定模型能用哪些命令、环境状态怎么告诉模型，还管理历史怎么拼进输入。
- 落地：限量搜索（超过 50 条不返回，提示写更具体的查询）；100 行窗口的文件查看器，带路径、总行数、行号；编辑后自动显示新内容。
- 护栏：编辑后跑 linter，有语法错误就回退，把错误、改后样子和原文一起给模型。
- 空输出时返回固定的“命令成功但没有输出”提示；最近 5 次之前的工具结果折叠成一行。

**追问链**：
1. 护栏有什么代价？→ 会妨碍模型惯用的做法，例如删参数时 linter 因函数体里还有引用而回退，模型必须一次改完或换顺序；搜索超限会多一次模型调用。要权衡减少的错误和增加的限制。
2. 为什么不直接给 shell？→ grep、find 结果太多占满上下文，选项多、输出格式不统一；一层层 ls、cat 很多轮也找不到东西。
3. 折叠旧工具结果有什么好处和代价？→ 上下文增长斜率从 o 降到折叠后的长度 c，过期的文件内容不再出现；代价是要再看旧内容得重新执行命令。

**易错点**：
- 把 ACI 理解成换一个 prompt。它改的是工具和反馈的形状，模型不变。

## harness-code-009 用测试判断 Coding Agent 改对了，测试不全时会出什么问题
- level: 2
- tags: [harness, evaluation, training]

**一句话答案**：两个方向都会错：测试太宽，凑答案的补丁也能过；测试太窄，换种写法的正确补丁被拒。测试和代码在同一可写工作区时，Agent 还能改测试拿分。评分用的测试要放在它改不到的地方。

**要点**：
- SWE-bench Verified 停报的原因就是测试太窄或太宽，见 evaluation/04。
- SWE-bench 的判法：清掉改动，在原代码上打测试补丁再打模型补丁，模型改测试影响不了判定。
- RL 里改测试、跳过测试、提前退出一旦能拿奖励，会被强化扩散（training/05）。
- 补充信号：对照实现、属性测试、跑真实入口；审查时单独标出测试文件和测试配置的改动。

**追问链**：
1. 怎么发现 Agent 改了测试？→ 看 diff 里测试文件、skip 标记、测试配置的改动；用 Agent 看不到的隐藏测试再跑一遍。
2. 线上没有现成测试怎么办？→ 先让 Agent 写能在原代码上复现问题的测试（Agentless 的做法），再补回归测试；人审查测试本身。

**易错点**：
- 把“测试全绿”直接当成“问题已修好”。

## harness-code-010 只允许 Coding Agent 运行测试命令，为什么还不安全
- level: 3
- tags: [harness, core]

**一句话答案**：测试命令会执行仓库里的代码（如 pytest 加载 conftest.py），而 Agent 能写这些文件，所以能跑测试加能写文件约等于能执行任意代码。边界要放在沙箱的文件、网络、凭据上。

**要点**：
- 命令规则匹配的是命令文本，文本可信也不代表执行内容可信，执行内容由工作区决定。
- 沙箱：可写范围只到工作区；凭据不挂载；网络默认关闭，装依赖时只放行包仓库域名，在网络层强制。
- 每个任务一个容器或微虚拟机，结束后销毁；读过 issue 等不可信内容后收紧权限。
- 命令规则用来减少误操作和确认次数，不当安全边界。

**追问链**：
1. 交互式使用和无人值守批量任务怎么区分？→ 交互式靠人逐条确认或按规则放行；批量任务跑在网络关闭、没有凭据的容器里，命令基本全放行。安全性来源不同。
2. Agent 需要推送代码怎么办？→ 用短期、只限这个仓库的令牌，只能推自己的分支，合并由分支保护、CI 和人把关。

**易错点**：
- 以为白名单里只有 `pytest` 就不会外泄。

## harness-code-011 屏幕 1512×982、截图限制长边 1568 像素和总像素约 115 万时，截图缩放比例和点击坐标怎么算
- level: 2
- tags: [harness]

**一句话答案**：缩放比例取 1、长边上限除以长边、总像素上限除以屏幕像素再开方三者的最小值。模型按截图坐标返回，执行时乘以屏幕宽除以截图宽。Retina 屏还要处理 2 倍设备像素比。

**要点**：
- Anthropic 文档：API 不替你缩放，超限的图直接报错；模型按收到的图的像素坐标返回，要保存缩放比例。
- 文档示例用早期模型限制：长边 1,568 像素、总像素约 115 万；1512×982 的屏幕缩到 1330×864（总像素那一项起作用）。
- 用 W/w 而不是 1/s：取整误差小于 1/s 个屏幕像素，不到截图上一个像素。
- Retina 截图是逻辑分辨率的两倍：要么截图缩一半，要么坐标减半。

**追问链**：
1. 忘了换算会怎样？→ 偏差和坐标成正比，左上角能点中，越往右下偏得越多。
2. 怎么排查？→ 在屏幕四角放已知位置的目标，比较模型坐标和真实坐标的比例。
3. 能完全避开这个问题吗？→ 有无障碍树时用元素引用或元素中心坐标，没有缩放误差；树里没有的内容才用截图坐标。

**易错点**：
- 以为 API 会自动缩放截图并替你换算坐标。
