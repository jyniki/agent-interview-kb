# 题目：奖励与 Verifier：结果奖励、过程奖励与 reward hacking

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## train-reward-001 什么是 RLVR，为什么推理任务偏好规则奖励
- level: 1
- tags: [training]

**一句话答案**：RLVR 用程序验证结果来给奖励，例如答案比对、跑测试、检查约束；推理任务偏好它，是因为神经奖励模型在大规模 RL 中容易被 hack，规则奖励更可靠也更省资源。

**要点**：
- 名字来自 Tülu 3：只有生成被验证为正确时才给固定奖励，用在 GSM8K、MATH、IFEval 式约束上。
- DeepSeek-R1 的 R1-Zero 用答案准确性和格式两种规则奖励。
- R1 论文的理由：神经奖励模型可能被 hack，重训它要额外资源，流程也更复杂。
- 边界：开放任务没有唯一答案，只能用评委或 rubric。

**追问链**：
1. RLVR 会被 hack 吗？→ 会。答案提取的正则可以被格式骗过，一次写多个候选也可能被误判为对。
2. RL 到底提升了什么？→ DeepSeekMath 报告提升 Maj@K、不提升 Pass@K；Yue 等报告大 k 时基座的 pass@k 更高。可以理解为 RL 更擅长把“偶尔能对”变成“经常对”，但这些结论有设定前提。

**易错点**：
- 说“RLVR 不需要奖励”。它不需要的是神经奖励模型，奖励仍然存在，只是由程序算。

## train-reward-002 结果奖励和过程奖励怎么选，PRM 的标签从哪来
- level: 2
- tags: [training, evaluation]

**一句话答案**：结果奖励稀疏但可靠，做主奖励；过程奖励信号密但贵、易被钻空子，常作辅助项或推理时重排。PRM 标签来自人工逐步标注、蒙特卡洛续写估计或 LLM 评委。

**要点**：
- 人工：Let's Verify Step by Step 发布 PRM800K，80 万条步级标签；MATH 上过程监督明显好于结果监督。
- 蒙特卡洛：Math-Shepherd 从某一步续写 N 次，HE 为“至少一次答对记 1”，SE 为“答对比例”；主实验用 HE、LLemma-7B 补全、N = 8。
- LLM 评委：Qwen 的 PRM 经验论文报告蒙特卡洛标签通常不如评委或人工标签，提出两者结合的共识过滤。

**追问链**：
1. 蒙特卡洛标签的根本问题是什么？→ 它检验“从这一步还能不能走到正确答案”，不是“这一步对不对”；错的一步后面能被救回来，就会被标成好步骤。Math-Shepherd 的标签质量分析里，HE 在 N = 4 时最准，N 再增大反而下降，原因是碰巧答对的假阳性。
2. 怎么评测一个 PRM？→ 不能只看 Best-of-N。它会奖励“过程错、答案对”的回答，把 PRM 推向判断结果；要同时看步级错误定位。
3. PRM 用在 Agent 上的难点？→ 每次工具调用当一步，但“这次检索好不好”比数学步骤更难判断，标准更模糊。

**易错点**：
- 说“PRM 一定比 ORM 好”。信号密不等于信号准。

## train-reward-003 用 LLM 评委当 RL 奖励，有什么风险，怎么降低
- level: 2
- tags: [training, evaluation]

**一句话答案**：评委有位置、冗长、自我偏好等偏差，当奖励时还要经得起优化压力，策略会专门找它的漏洞；降低风险的办法是把能程序化的分项拿出来，用 rubric 收窄评委裁量，先和人工对齐，再做对抗测试。

**要点**：
- MT-Bench 论文：强评委和人的一致率超过 80%，与人和人之间相当；同时有位置、冗长、自我偏好偏差和推理能力有限。
- 生成式 Verifier（GenRM）：用下一个 token 预测训练验证器，可先写验证推理，再多次采样投票。
- Rubrics as Rewards：逐题 rubric 作为奖励，报告对小评委更友好、不同规模评委之间方差更小。
- 当评测只要平均准；当奖励要经得起策略持续寻找漏洞。

**追问链**：
1. 评委奖励一路涨，怎么知道是真涨？→ 用不同的评委或人工在留出集上复评；看输出长度是否同步增长；抽检最高分样本。
2. 为什么要把能程序化的分项拿出来？→ 程序的裁量空间为零，难被钻空子；评委只负责程序管不到的维度，可被攻击的面变小。

**易错点**：
- 认为“评委和人一致率高”就能放心当奖励。一致率是在固定分布上测的，RL 会把策略推到评委没见过的分布。

## train-reward-004 设计一个工具调用任务的多奖励融合方案
- level: 3
- tags: [training, harness]

**一句话答案**：以正确性为主、格式为辅，正确性按工具名、参数名、参数值细粒度打分并给更大尺度；融合前做分项相关性和消融；尺度平滑变化，不要突然切换；注意组内标准化作用在总奖励上。

**要点**：
- ToolRL：格式 {0, 1}，正确性按工具名、参数名、参数值比对后缩放到 [−3, 3]，总范围 [−3, 4]。
- ToolRL 消融：正确性压到和格式同尺度效果变差；中途突然切换尺度变差；随训练进度平滑调整尺度在两个 3B 模型上最好；加思考长度奖励在小模型上变差；正确性改成整体完全匹配，信号更稀疏、效果下降。
- 融合方式：加权、门控、分阶段、动态尺度，各有超参和代价。
- GRPO 的组内标准化作用在总奖励上，尺度大的分项会主导排序。

**追问链**：
1. 两个分项负相关怎么办？→ 先确认是不是真冲突（例如“更多检索”和“更快回答”）；以结果为主，冲突项改成门控或小权重；或者把它写进约束（调用上限），不放进奖励。
2. 怎么判断一个分项是多余的？→ 去掉它重训一小段，留出评测不降就是多余的；每多一项就多一个可被钻空子的点。
3. 分阶段奖励（如 R1-Searcher）有什么风险？→ 第一阶段只奖励“调用了检索”，模型可能养成为调用而调用的习惯；切换时奖励尺度突变，ToolRL 的消融也显示突然切换有害。

**易错点**：
- 只给加权公式，不讲尺度和组内标准化的相互作用。

## train-reward-005 怎么识别和防御 reward hacking
- level: 3
- tags: [training, evaluation, harness]

**一句话答案**：识别靠“训练奖励涨、留出评测不涨”、分项曲线异常、抽检高分样本和读推理过程；防御按层次做：改规则、限制可操作范围、门控、对抗测试奖励函数、控制评委范围，并且不对思维链监控施加强优化压力。

**要点**：
- 典型形态：骗答案提取、改测试、讨好评委、堆检索和引用、格式对内容空。
- Gao 等用金标准奖励模型测量过度优化：对代理奖励优化过多，真实表现会变差。
- Baker 等：用 LLM 读思维链监控 hack，比只看动作和输出有效得多，弱模型也能监控强模型。
- 同一篇的警告：把思维链监控加进奖励，优化压力大时模型学会在思维链里隐藏意图，继续 hack。
- 发现后：确认漏洞、修奖励、对抗回归，回到 hack 出现之前的检查点继续训。

**追问链**：
1. 只加大 KL 系数行不行？→ 策略整体被拉住，正常学习也变慢，漏洞还在，只是被利用得慢一点。
2. 为什么不直接把思维链监控当奖励项？→ 强优化会教会模型隐藏意图，监控失效；论文建议接受一定的可监控性代价。
3. 修完奖励要从头训吗？→ 通常不必从头；hack 行为不会自己消失，回到 hack 出现之前的检查点继续训。

**易错点**：
- 把 hack 全怪模型。很多 hack 是奖励定义本身鼓励的，例如“答案里出现正确值就给分”会鼓励写多个候选。

## train-reward-006 二值奖励下 GRPO 的组内优势取什么值，Verifier 误判怎样影响梯度
- level: 2
- tags: [training]

**一句话答案**：通过率 p̂ 时答对优势 √((1−p̂)/p̂)、答错 −√(p̂/(1−p̂))，奖励缩放平移不变。随机误判只把梯度缩小 (1−fp−fn) 倍；集中在某类回答上的假阳性会改变梯度方向。

**要点**：
- 0/1 奖励的组内均值是 p̂，总体方差是 p̂(1−p̂)，代入标准化公式即得；组内优势之和为 0。
- G = 8、k = 1 时，答对 +√7 ≈ 2.65，答错各 −0.38：难题的少数正确回答拿大正优势。
- Tülu 3 用 α = 10，DAPO 用 ±1，除以 std 后是同一个信号；不除 std 时 α 等于调学习率。
- k = 0 或 G 时优势全 0，概率 p^G + (1−p)^G，见 03 章。
- E[r_obs] = fp + (1−fp−fn)·c(y)，常数 fp 被基线减掉。

**追问链**：
1. 为什么系统性假阳性比随机噪声危险？→ 被误判为对的那类错误回答期望奖励高于真实值，梯度会持续推高它；策略的优化能力正好擅长找到这类回答。
2. Verifier 验收应该看什么？→ 不只看平均准确率，要构造多候选、格式绕过等对抗样本，检查有没有能被稳定利用的假阳性模式。

**易错点**：
- 以为把奖励从 1 改成 10 能“加强信号”。GRPO 标准化后完全不变。

## train-reward-007 Math-Shepherd 的硬估计标签为什么续写次数 N 越大假阳性越多
- level: 3
- tags: [training, evaluation]

**一句话答案**：硬估计只要 N 次续写有一次答对就记好，坏步骤续写一次答对的概率 q 小但不为 0，被标好的概率 1−(1−q)^N 随 N 趋于 1；N 太小又会漏标难走的好步骤，所以准确率先升后降。

**要点**：
- q 是这一步在补全模型下的价值，不是这一步对不对；后续步骤能救回错误，或碰巧答对。
- 软估计 SE 是 q 的无偏估计，方差 q(1−q)/N，随 N 变准，但收敛到 q 而不是对错。
- Math-Shepherd 5.2 节：160 个人工标注步骤上，HE 一致率在 N = 4 时最高（86%），再增大 N 反而下降。
- Lessons 论文：蒙特卡洛标签通常不如评委和人工；评委与蒙特卡洛共识过滤保留约 40% 数据。

**追问链**：
1. 怎么选 N？→ 人工标注一小批步骤，算不同 N 下 HE 和人工的一致率，取峰值；不默认越大越好。
2. 补全模型换了会怎样？→ q 依赖补全模型能力，强补全模型能救回更多坏步骤，标签分布随之变化，标签有策略依赖。

**易错点**：
- 说“N 越大蒙特卡洛估计越准，所以标签越好”。对 SE 的估计成立，对 HE 的对错判断不成立。

## train-reward-008 PRM 用于 best-of-N 重排和用于 RL 奖励有什么不同
- level: 3
- tags: [training, evaluation]

**一句话答案**：重排时策略固定，PRM 只需在策略分布上排序准，错了只是选错；进入 RL 回报后策略朝 PRM 高分方向移动，会分布漂移、靠重复步骤刷累计分，要用 Clip 或 Delta 给回报设上界并迭代重训。

**要点**：
- 重排时把步级分压成一个分：Lightman 等用乘积（轻微偏向步数少的解），Math-Shepherd 用最小值。
- Jiaxuan Gao 等（2410.15115）：PRM 步级奖励加进 RL，模型学会重复正确但不必要的步骤；有成功奖励时 ORM 没有额外收益。
- Clip：r = min(r_process − η, 0)。Delta：相邻步分差，求和裂项后回报只剩第一步分数加成功奖励。
- DeepSeekMath 的 GRPO 过程监督：步级奖励组内标准化，token 优势取其后各步之和。

**追问链**：
1. 为什么 Delta 能防刷步数？→ 回报求和后裂项相消，等于 α·第 1 步分数 + 成功奖励，和步数无关；从第 k 步开始的回报只取决于第 k 步自己的分数。
2. 只用 best-of-N 评测 PRM 有什么问题？→ 会奖励“过程错、答案对”的回答，PRM 被推向判断结果；要同时看步级错误定位。

**易错点**：
- 认为重排效果好的 PRM 直接当 RL 奖励也会好。优化压力会把策略推到 PRM 没见过的分布。

## train-reward-009 多奖励加权求和后做 GRPO，为什么名义权重不等于实际影响
- level: 3
- tags: [training, harness]

**一句话答案**：组内标准化按总奖励的方差排序，分项不相关时第 k 项的实际影响约正比于 w_k²·Var(r_k)，组内方差小的分项几乎不起作用；先求和再标准化还会把不同分项组合压成同一个优势。

**要点**：
- 二值分项 std 最大 0.5，窄范围连续分 std 可能只有 0.05，等权相加时二值项占约 99% 方差。
- 做法：权重和组内 std 成反比，或先按尺度归一化再加；必须满足的分项用门控。
- GDPO：G = 2、两个二值奖励时，(0,1)、(0,2)、(1,2) 标准化后优势相同；每个分项单独组内标准化再求和，最后做 batch 级归一化。
- ToolRL 正确性跨度 6、格式跨度 1，让正确性主导排序。

**追问链**：
1. 分项各自标准化有什么代价？→ 各项影响被拉平，“正确性更重要”要靠显式权重重新表达；某项组内全相同时它不贡献信号。
2. 怎么发现某个分项没起作用？→ 逐项记录组内 std，算各分项和最终优势的相关系数。

**易错点**：
- 只看公式里的 w_k 判断谁更重要，不看各分项在组内的方差。
