# 题目：Agentic RL：多轮 rollout 与工具返回 mask

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。“GRPO 用在多轮工具调用要改哪里”的概括题见 [03 章 train-grpo-005](../03-grpo-family/questions.md)，这里不重复。

## train-arl-001 Search-R1 怎么把搜索放进 RL rollout，哪几个设计选择最关键，为什么
- level: 2
- tags: [training, harness]

**一句话答案**：模型写查询，系统把检索结果接回序列再继续生成。关键选择：检索 token 不计梯度，否则效果明显下降；奖励只用答案 EM，少一个可钻的口子；默认用 PPO，GRPO 收敛快但会崩。

**要点**：
- 标签：`<think>`、`<search>`、`<answer>` 由模型写，`<information>` 由系统写；rollout 里的动作次数有上限。
- 检索：E5 加 2018 年维基百科，每次 top-3；训练数据是 NQ 加 HotpotQA。
- 奖励：只有 EM，没有格式奖励，没有神经奖励模型。
- mask 消融：7B Base 平均 EM 屏蔽时 0.431，不屏蔽 0.343。
- top-k 消融：top-1、3、5 分别为 0.375、0.431、0.400。
- PPO 对 GRPO：GRPO 收敛快，但长时间训练后奖励崩溃；PPO 更稳。

**追问链**：
1. 为什么不加格式奖励？→ 论文说训练后的模型已经能很好地遵守结构；结构不对拿不到答案，自然得 0 分，额外的格式奖励只多一个可被钻的口子。
2. 为什么 GAE 取 λ = 1、γ = 1？→ 奖励只在末端给出，不打折，优势就是最终回报减去 critic 估值。
3. 把它迁到开放问答，第一个要改的是什么？→ 奖励。EM 只适合短事实答案，开放问答要换成 F1、评委或 rubric，并承担被钻空子的风险。

**易错点**：
- 说 Search-R1 用的是 GRPO。默认是 PPO。

## train-arl-002 工具返回 mask 在实现上有哪些坑
- level: 3
- tags: [training, harness]

**一句话答案**：mask 必须在 token 序列上做并和分词边界对齐；新旧策略 log 概率、重要性比率、KL 要共用同一个 mask；聚合时分母只数策略 token；最后抽样解码检查。

**要点**：
- 分词边界：工具返回的起止标签可能和相邻文本合成一个 token，按字符位置切会错位。
- 一致性：策略 loss、比率、KL、熵正则都用同一个 mask，漏掉一项就会有梯度落在工具 token 上。
- 分母：只数 mask 为 1 的 token；分母里混进工具 token，长返回会把策略 token 的权重压小。
- 概率来源：推理引擎和训练引擎的概率不完全一致，常用训练引擎重算旧策略 log 概率。
- 检查方法：抽样把 mask 为 1 的 token 解码出来，确认里面没有工具返回内容。

**追问链**：
1. mask 错位的症状是什么？→ 模型开始输出工具返回的片段、伪造 `<information>` 内容，或在工具标签附近格式错乱；Search-R1 的消融显示不屏蔽检索 token 效果明显下降。
2. 用户模拟器生成的话要不要 mask？→ 要。它和工具返回一样不是策略生成的，用户模拟器见 [06 章](../06-environments/README.md)。
3. 部分 rollout 跨迭代拼接时 mask 有什么要注意？→ 拼接后每段记下生成它的策略版本；旧策略片段要么不计 loss，要么按重要性比率修正，要事先定好。

**易错点**：
- 只 mask 策略梯度，忘了 KL 项。Search-R1 用 GRPO 时 KL 也同样屏蔽。

## train-arl-003 多轮 Agent RL 的信用分配怎么做
- level: 3
- tags: [training]

**一句话答案**：默认是整条轨迹共享一个优势，粗但简单；更细的做法有带 critic 的 PPO、轮级中间奖励、效率惩罚和过程奖励模型，每一种都在“信号更细”和“更难定义、更易被钻空子”之间取舍。

**要点**：
- 组内比较只分得出对错，分不出同样答对时谁更省。
- PPO 加 critic 能逐 token 估值，代价是训 critic，稀疏奖励下 critic 不一定准。
- 轮级奖励：例如检索是否命中相关文档，定义难、易被钻空子。
- 效率项：调用次数的小惩罚，会和“多搜才能答对”冲突。
- 样本够多时，无用动作在对错轨迹里都会出现，正负优势部分抵消，所以粗分配主要是学得慢。

**追问链**：
1. 训练后平均调用次数一直涨，是好事吗？→ 不一定。Search-R1 观察到有效检索次数持续增长，但没分析多少是必要的；要拆开看“调用次数”和“成功率”，必要时加效率项或做反事实抽检。
2. 反事实分析为什么只能离线做？→ 每屏蔽一次调用就要重跑一条轨迹，成本和调用次数成正比。
3. 过程奖励能直接用于 Agent 吗？→ 可以把每次工具调用当一步，但“这一步好不好”比数学步骤更难判断，见 [05 章](../05-reward-verifier/README.md)。

**易错点**：
- 说“信用分配差所以多轮 RL 学不到”。它学得慢、方差大，但仍能学到只在成功轨迹里出现的动作。

## train-arl-004 多轮训练突然奖励下降、方差变大，怎么排查
- level: 3
- tags: [training, harness, evaluation]

**一句话答案**：先排除环境，再看 mask 和截断，最后看算法：查工具超时率和截断原因，抽样检查 mask，再看熵、clip 比例、KL 和梯度范数，判断是不是熵塌缩或类似 Echo Trap 的崩溃。

**要点**：
- 环境：工具超时率、错误率、离线检索库缺文档，在曲线上都像“奖励掉、方差大”。
- 截断：区分长度上限截断和工具超时截断；后者应丢弃或重跑，不给负奖励。
- mask：抽样解码 mask 为 1 的 token。
- 算法信号：熵持续下降说明套路固化；RAGEN 描述的 Echo Trap 表现为奖励方差突然掉下去、梯度出现尖峰。
- 异步：滞后过大时 clip 比例和 KL 上升。

**追问链**：
1. RAGEN 怎么缓解 Echo Trap？→ StarPO-S 加了轨迹过滤、引入 critic、梯度稳定三项。
2. 只把学习率和 clip 范围调小行不行？→ 曲线会变平滑，但每步几乎不动，同样的算力学得更少；问题被推后，没有解决。

**易错点**：
- 一上来就改算法超参。多轮训练的很多“崩溃”是环境问题。

## train-arl-005 同步 rollout 的长尾问题怎么解决，代价是什么
- level: 2
- tags: [training, inference]

**一句话答案**：同步训练要等最慢的轨迹，GPU 空转；部分 rollout 把长轨迹切到多个迭代写完，完全异步让采样和训练解耦。代价都是样本有一部分来自旧策略，要控制滞后并修正目标。

**要点**：
- Kimi k1.5：超出 token 预算的轨迹，未完成部分存入回放缓冲，下轮接着写；只有当前片段需要在线计算。
- AReaL：生成和训练完全解耦；平衡两端负载让滞后有界，用针对过时样本修改的 PPO；论文报告相同 GPU 下最多 2.77 倍加速，效果持平或更好。
- 监控：clip 比例和 KL 随滞后上升。
- 工具侧：沙箱做成异步任务池，慢执行不拖住整体（ReTool 的做法）。

**追问链**：
1. 滞后几步可以接受？→ 没有通用数字，看 clip 比例和效果；先从一步滞后开始，逐步放宽并对比曲线。
2. 异步会影响组内优势吗？→ 同组轨迹如果跨了策略版本，组内比较就混进了版本差异；一种处理是让同组轨迹由同一版本的策略生成，或至少记录每条轨迹的策略版本，便于分析。

**易错点**：
- 认为异步“只是工程优化”。它改变了数据的策略分布，目标函数也要跟着处理。

## train-arl-006 Coding Agent 的 RL 奖励怎么设计，有哪些坑
- level: 2
- tags: [training, harness]

**一句话答案**：常见三种：测试通过、补丁相似度（SWE-RL）、解释器下的最终答案（ReTool）；主要坑是测试不全、模型改测试、相似度奖励不认功能等价的写法，以及环境成本高、早期奖励稀疏。

**要点**：
- SWE-RL：格式错误 −1，否则用 `difflib.SequenceMatcher` 算和真实补丁的相似度，范围 0 到 1；离散的完全匹配奖励因为几乎总是 0，效果更差。
- SWE-RL 数据来自 GitHub 合并的 PR，排除了 SWE-bench 仓库防止污染。
- ReTool：最终答案对 +1、错 −1，不奖励“代码能跑”；解释器输出从 loss 中排除。
- 防改测试：测试文件只读，或在隔离副本里跑。
- 冷启动：复杂任务早期几乎全错，先做 SFT 或蒸馏，再按通过率筛题。

**追问链**：
1. 为什么 ReTool 不给“代码可执行”奖励？→ 论文说是为了减少奖励被钻空子、鼓励更多样的解法，只依赖结果反馈。
2. 相似度奖励的根本缺陷是什么？→ 只看文本不看语义，功能正确但写法不同的修复得分低；有测试时应以测试为主。

**易错点**：
- 只说“跑测试就行”，不提测试覆盖不全和模型修改测试这两种钻空子方式。

## train-arl-007 为什么工具结果的 token 不 mask 时梯度不会在期望里抵消，答对和答错的轨迹各把模型推向哪里
- level: 3
- tags: [training]

**一句话答案**：得分函数期望为 0 只对策略自己采的 token 成立；工具 token 服从环境分布 q，期望是 q − π 不为 0。答对时模型学着自己写工具结果，答错时压低文档内容，策略 token 还被稀释。

**要点**：
- 轨迹概率分解成策略因子和环境因子，后者和 θ 无关，所以真梯度只含策略 token；mask 就是这个结论。
- softmax 输出层上 ∇_z log π(y) = onehot(y) − π；E_{y~π}[·] = 0，E_{y~q}[·] = q − π。
- 正优势：对检索文本做语言建模，推高 `<information>` 这类标签，模型开始伪造工具结果。
- 负优势：压低文档里的实体和措辞，即使文档是对的。
- 稀释：token 级聚合下策略 token 权重从 1/Σm 变成 1/T；策略 400、工具 1500 时缩小到约 0.21 倍。
- KL 也要 mask：k3 无偏的前提是样本来自 π_θ，在工具 token 上估的不是 KL。

**追问链**：
1. 工具结果还在上下文里，梯度会不会流过它？→ 会，通过注意力影响后续策略 token 的条件概率；被去掉的只是工具 token 自己的 log π 项。
2. KL 漏 mask 的症状？→ KL 曲线随 top-k 或日志长度平移；令 π_θ = π_ref 时 KL 不为 0。
3. 系统插入的“重新思考”提示要不要 mask？→ 要，它不是策略采样的，按 mask 的定义记 0。

**易错点**：
- 说“工具 token 只是噪声，平均下来没影响”。它的期望梯度有方向。

## train-arl-008 多轮轨迹存成整段文本、训练前再分词，会出哪些错，怎么构造 mask 才对
- level: 3
- tags: [training, harness]

**一句话答案**：标签和相邻字符会合成跨段 token，mask 标不了；训练端算的是没采过的 token，old_logp 错位。应按段存，策略段用采到的 id，工具段单独分词再拼，loss mask 随移位对齐。

**要点**：
- 轨迹存成段列表：每段记角色、token id、采样 log 概率、策略版本。
- 拼成 ids、mask、old_logp、version 四个 (T,) 数组。
- 位置 t 的 logits 预测 y_{t+1}，按输入位置存 loss 时 mask 取 mask[1:]；错一位会把“预测工具首 token”算进 loss。
- 停止串：vLLM 的 `stop` 默认不出现在返回文本里，控制器自己补标签会引入重新分词的 token；以 token id 为准。
- 单元测试：mask 为 1 的 token 解码后不含任何工具文本；π_θ = π_old 时比率全为 1。

**追问链**：
1. mask 错位的线上现象？→ 工具标签附近格式乱，标签和换行粘连；第一步更新前比率就不等于 1，clip 比例不为 0。
2. 为什么不能按字符位置切 mask？→ 一个 token 可能一半属于策略一半属于工具，标 0 标 1 都错。

**易错点**：
- 只检查解码后的文本一致。文本一样，token 序列可以不一样。

## train-arl-009 只有结果奖励时，一个不影响成败的多余工具调用得到的期望梯度是多少，效率惩罚和轮级奖励分别改变了什么
- level: 3
- tags: [training]

**一句话答案**：期望为 0：奖励和该动作独立，期望拆开后得分函数项为 0，但方差不为 0，所以学得慢。效率惩罚让它变负，过大会压制必要调用；奖励“调用了”的轮级信号会推高它。

**要点**：
- 推导：E[(R−b)∇log π] = E[R−b]·E[∇log π] = 0，第一步用独立性，第二步用得分函数恒等式。
- 单组估计里这一维的信噪比接近 0，方差和有用动作同一量级。
- 效率项 c：c 小于必要调用带来的成功率增益时，必要调用梯度仍为正；超过后反向。
- 轮级奖励只加在真正有用的动作上，会增强该动作的梯度；加在“调用了”上就推高多余调用。
- 有 critic 时，已经拿到答案后 V(s_t) 很高，后面多余调用的优势接近 0，方差更小。

**追问链**：
1. 训练后调用次数一直涨，说明什么？→ 不一定是好事；多余调用不被惩罚会随噪声漂移，要拆开看调用次数和成功率，做反事实抽检。
2. R1-Searcher 第一阶段奖励“调用了检索”，为什么第二阶段去掉？→ 这种奖励不看有没有用，会推高多余调用；引导完调用行为后要换回结果奖励。

**易错点**：
- 说“答对轨迹里的多余调用会被强化”。它在答错轨迹里一样常见，期望里正负抵消。

## train-arl-010 异步 rollout 的样本来自旧策略，怎么修正，AReaL 为什么要把 clip 中心从行为策略换成近端策略
- level: 3
- tags: [training, inference]

**一句话答案**：乘重要性比率修正，整条轨迹比率无偏但方差大。以旧策略为 clip 中心，比率早已远离 1，大量 token 被截断；AReaL 以更新前参数为中心，另乘一个比率修正采样分布。

**要点**：
- 直接把旧样本当 on-policy：期望是 Σ π_behav R ∇log π_θ，有偏，玩具例子里方向可以反。
- 整条轨迹比率 ρ(τ) = Π π_θ/π_behav 精确无偏；PPO 用 token 级比率加 clip 近似，有偏但方差小。
- 整条轨迹比率只在策略 token 上连乘，环境概率在分子分母里消掉。
- 比率方差随滞后快速增大；监控 clip 比例、log 比率分位数、有效样本量。
- AReaL：提交请求前要求 ⌊(N_r−1)/B⌋ ≤ i + η，η = 0 即同步；默认代码 4、数学 8。
- 解耦目标（论文式 5）：(π_prox/π_behav) · min(u·Â, clip(u)·Â)，u = π_θ/π_prox。
- 跨版本写成的轨迹等价于从一个行为策略采样，逐 token 记采样 log 概率即可。

**追问链**：
1. η 限制住了，样本滞后就一定不超过 η 吗？→ 不一定；它限制的是提交速度，慢轨迹完成晚，实际滞后可能超过 η，组批时要记录并检查版本。
2. 同步训练的长尾损失有多大？→ n 条轨迹耗时独立指数分布时占用率约 1/H_n，n = 64 约 21%；重尾分布更低。
3. Kimi k1.5 的部分 rollout 和 AReaL 的区别？→ k1.5 是迭代式同步，超预算的轨迹下一迭代续写；AReaL 完全解耦，新权重到达时中断生成、重算 KV 后继续。

**易错点**：
- 认为异步只是工程优化，不改目标函数。
