# 题目：轨迹数据：合成、蒸馏、配比与中训练

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## train-data-001 Agent 轨迹数据和普通 SFT 数据有什么区别
- level: 1
- tags: [training, harness]

**一句话答案**：轨迹是模型输出和环境返回交替的多轮序列，更长、和环境版本耦合，正确性既看结果也看过程，多数要在环境里跑出来，不能只靠人写。

**要点**：
- 结构：思考、工具调用、工具返回、再思考，交替多轮。
- 长度：工具返回很长，常见上万 token。
- 正确性：除了答案，还要看调用是否合法、有没有多余步骤、有没有编造工具结果。
- 格式：工具定义位置、调用标记、参数序列化必须和线上推理一致。
- 时效：工具接口变化后旧轨迹会失效，需要记录环境版本。

**追问链**：
1. 为什么要在训练数据里放失败和纠错的轨迹？→ 模型没见过工具报错、检索为空，上线遇到就容易原地重复调用；放进去后，失败调用不计 loss，只学后面的纠错。
2. 训练格式和推理格式不一致会怎样？→ 模型按训练时的格式输出工具调用，线上解析失败，表现为调用格式错误率升高。

**易错点**：
- 只说“多轮对话”，没说出过程正确性和环境耦合这两点，答案停留在普通 SFT 层面。

## train-data-002 拒绝采样、STaR、ReST-EM 有什么区别
- level: 2
- tags: [training]

**一句话答案**：三者都是“模型采样、按正确性过滤、再微调”；STaR 额外对答错的题给出正确答案让模型反推推理链；ReST-EM 每轮从基座重新微调以减少过拟合。

**要点**：
- 拒绝采样微调：每题采多个，留答对的做 SFT，相当于只用正样本、权重全为 1 的离线 RL。
- STaR（arXiv 2203.14465）：答错的题提示正确答案后让模型重新生成推理链（rationalization），让模型也能从自己做不出的题上学习。
- ReST（arXiv 2308.08998）：Grow 阶段采样建数据集，Improve 阶段在这份数据上做离线 RL，数据可复用。
- ReST-EM（arXiv 2312.06585）：每轮从基座模型重新微调；论文报告这样任务内分数相近、迁移更好。
- DeepSeekMath 5.2 节：在线采样的 Online RFT 后期好于离线 RFT；GRPO 能惩罚错误回答，好于 Online RFT。

**追问链**：
1. 迭代轮数越多越好吗？→ 不是。ReST-EM 在 APPS 上大部分收益来自第一轮，继续迭代在 APPS 和 HumanEval 上都退步，论文归因于在少量训练题上过拟合。
2. STaR 的 rationalization 有什么风险？→ 给了答案再反推，推理链可能是“凑答案”的，过程不可靠；需要验证器检查过程，或降低这部分样本的权重。
3. 拒绝采样和 RL 怎么配合？→ RL 找到好行为，拒绝采样把它固化成 SFT 数据，再进下一轮 RL；DeepSeek-R1 就是这样交替的。

**易错点**：
- 把 RFT 说成 RL。它和 RL 共享“数据来自模型自己”，但没有负样本，也不按奖励大小加权。

## train-data-003 设计一套合成 Agent 轨迹的质量控制流程
- level: 3
- tags: [training, harness, evaluation]

**一句话答案**：按成本从低到高依次做结构校验、结果校验、过程校验、去重、难度分层和去污染，每条样本记录来源，评委过滤要先和人工对齐。

**要点**：
- 生成骨架可参考 Kimi K2 报告：真实加合成工具，组合出不同 Agent 和带 rubric 的任务，用户模拟加工具模拟器跑多轮轨迹，LLM 评委按 rubric 过滤；编码类用真实沙箱。
- 结构校验：工具名存在、参数可解析、标签成对。
- 结果校验：能程序判就程序判，不能的用评委加人工抽检。
- 过程校验：重复调用、引用了工具没返回的内容、步数异常。
- 去重：MinHash 近重复加 embedding 语义去重；同一题保留几条不同解法。
- 难度分层：当前模型每题采 N 次按通过率分档，中等难度给最多配额。
- 去污染：n-gram 挡字面复制，embedding 检索加 LLM 判定挡改写题。

**追问链**：
1. 模拟工具有什么风险？→ 行为比真实工具“干净”，模型可能学会依赖模拟器；Kimi K2 加受控随机性模拟部分失败，并在编码任务上用真实沙箱。
2. 评委过滤会引入什么偏差？→ 偏爱更长、更客气的回答（MT-Bench 论文列出位置、冗长、自我偏好等偏差）；要抽样和人工打分比一致率，按分项校准。
3. 结果对、过程差的轨迹怎么办？→ 截掉多余步骤后重新验证；或作为偏好对里的负样本，和同题干净轨迹配对。

**易错点**：
- 只做结果过滤。这样数据里会堆满“碰对答案但调用冗余”的轨迹，模型平均步数反而上升。

## train-data-004 Agent 轨迹和通用数据怎么配比
- level: 2
- tags: [training]

**一句话答案**：必须混通用数据防止通用能力退化；配比按“任务类型 × 难度”分格定配额，具体比例用小模型消融扫出来，看分项指标而不是总分。

**要点**：
- AgentTuning（arXiv 2310.12823）把 AgentInstruct 和通用指令数据混合训练，目标是加 Agent 能力而不伤通用能力。
- 分格配额：加量只补缺的格子，避免放大已经过多的类型。
- 消融：一次只改一类数据比例，看任务成功率、通用能力、格式错误率。
- 有效 scaling 是增加工具和任务种类、难题和失败恢复比例，不是同模板加条数。

**追问链**：
1. 加了一倍轨迹，Agent 指标没涨，可能是什么原因？→ 新增数据是同模板变体，没有新信息；或难度集中在模型已会的题；或通用数据比例被挤掉导致指令遵循变差，抵消了收益。
2. 小模型上扫出的比例能直接用到大模型吗？→ 不一定。大模型学得更快、更容易过拟合少量数据，要在目标模型上验证少数候选。

**易错点**：
- 给出一个“标准比例”。配比没有通用答案，没有出处的比例不要说。

## train-data-005 中训练和后训练怎么分工
- level: 3
- tags: [training]

**一句话答案**：中训练在预训练末期用针对性数据加学习率退火补知识和能力底子；后训练教行为方式。缺能力放中训练，缺行为放后训练。

**要点**：
- OLMo 2（arXiv 2501.00656）：中训练占约 5% 到 10% 训练 FLOPs，学习率线性降到 0，数据是 Dolmino Mix 1124（高质量网页、学术文本、问答、以合成为主的数学数据）。
- OLMo 2 用不同数据顺序跑几次退火再平均权重；数学数据源用小规模短退火实验逐个评估。
- 中训练数据整段计 loss，量是几十到几百 B token；后训练只对助手部分计 loss，量是几万到几百万条。
- 判断方法：SFT 后每题采多次，大量 0/N 说明能力底子不够，加 SFT 轮次难补。

**追问链**：
1. 为什么中训练要配合学习率退火？→ OLMo 2 的做法是把高质量和目标领域数据放在学习率线性降到 0 的阶段，并用短退火实验逐个评估数据源。常见的解释是退火期的数据对最终权重影响大，用少量 token 就能看出一个数据源有没有用。这条解释是经验性的，回答时说清楚。
2. Agent 轨迹该放中训练还是 SFT？→ 都可以。中训练放大量轨迹教工具调用的基本形态，SFT 放精选轨迹教具体行为和格式；中训练里的轨迹同样要考虑工具返回是否计 loss。
3. 中训练会伤基础能力吗？→ 配比失衡时可能伤。OLMo 2 的中训练数据池里，高质量部分以网页为主，数学数据是单独的一小份，目标领域数据没有挤掉通用数据。

**易错点**：
- 把中训练说成“又一轮 SFT”。它的数据形态、规模和学习率策略都更接近预训练。

## train-data-006 Agent SFT 的 loss mask 有哪些例外，失败调用怎么处理
- level: 2
- tags: [training, harness]

**一句话答案**：失败调用留作上下文、本身不计 loss，只对后面的纠错动作计 loss。例外：训练工具模拟器时工具返回就是目标，要计 loss；要注入领域知识就另做中训练文档，不放开轨迹里的 mask。

**要点**：
- 基本规则：只对 assistant 的思考、工具调用和回答计 loss；system、user、工具返回都不计。
- 工具返回不计 loss：不是模型行为，计入会让模型学着编造工具结果，长返回还会稀释梯度。
- 工具返回仍在上下文里，后续 assistant token 的 loss 是在“看到返回”的条件下算的，所以模型能学会用它。
- 实现：标签设成忽略值（很多框架用 −100）。mask 不省前向的显存和计算。
- 例外：训练工具模拟器时计工具返回；想注入领域知识，就单独做成中训练文档，不在轨迹里放开 mask。

**追问链**：
1. 上线后模型开始自己编工具返回，先查什么？→ 训练数据的 mask 是否放开了工具返回；推理时是否在调用后正确停止生成并插入真实返回。
2. 长短轨迹混训，loss 怎么聚合？→ 按样本平均会压低长轨迹里每个 token 的权重，按 token 平均会让长轨迹整体权重变大；要按目标选，和 GRPO 的长度偏差是同一类问题。

**易错点**：
- 只对最后一轮 assistant 计 loss。这样模型学会了总结，没学会中间怎么调工具。

## train-data-007 拒绝采样微调为什么能自举提升，又为什么会饱和
- level: 3
- tags: [training]

**一句话答案**：在过滤样本上做 SFT，第一步的期望梯度等于 0/1 奖励的策略梯度 N·∇p(x)，所以通过率会上升；p(x)=0 的题采不到正样本、梯度恒为 0，迭代多少轮都学不会。

**要点**：
- 推导：E[Σ r·∇log π] = N·Σ π·r·∇log π = N·∇Σ π·r = N·∇p(x)，在 θ = θ_old 处成立。
- 和 RL 的差别：数据来自旧策略且不做重要性修正，是离线的；答错样本梯度为 0，没有负样本。
- 题间权重：按样本求和时正比于 ∇p，简单题权重大；每题先平均则变成 ∇log p。ReST-EM 每题最多留 10 条正确解。
- ReST-EM 的 EM 视角：E 步按奖励给模型样本加权，M 步做加权 NLL，ELBO 单调不降。
- 饱和：一道题 N 次全错的概率是 (1−p)^N；固定错误模式的题需要教师、STaR 的答案提示或中训练补底子。

**追问链**：
1. ELBO 单调不降，为什么 ReST-EM 多轮后测试集会退步？→ 单调的是训练题上的下界，不是测试表现；在少量训练题上过拟合，APPS 第二轮就退步，论文的处理是每轮从基座重训、扩大题目池。
2. p = 0.1 的题想让 0/N 的概率低于 10%，要采几次？→ (0.9)^N < 0.1，N > log0.1/log0.9 ≈ 22；采样预算应按难度分配。
3. STaR 的 rationalization 解决了什么、引入了什么？→ 给 0/N 的题造出样本，突破上限；但样本来自“看过答案”的分布，推理链可能是凑答案，要检查过程。

**易错点**：
- 说“RFT 就是 RL”。它只在第一步等价于无基线的策略梯度，之后是离线的，而且不惩罚错误回答。

## train-data-008 off-policy 蒸馏的分布偏移是什么，GKD 怎么解决
- level: 3
- tags: [training]

**一句话答案**：off-policy 蒸馏只在教师走过的前缀上训练，学生一旦出错就进入没监督过的状态，误差随长度按 T² 累积；GKD 让学生自己采样、教师在学生前缀上给 token 分布，训练和推理的状态分布一致。

**要点**：
- 推导：每步出错率 ε，前 t 步至少错一次的概率 ≤ tε，出错后最坏每步都错，总错误 ≤ Σ tε ≈ T²ε/2；Ross 等定理 2.1 给出 T²ε 上界。
- on-policy 数据覆盖学生自己会访问的状态，DAgger 类方法的界和 T 线性相关。
- GKD 目标：(1−λ)·监督数据上的散度 + λ·学生样本上的散度；λ 是学生数据比例，λ=0 且前向 KL 就是普通 KD。
- 散度可选前向 KL、反向 KL、JSD(β)；论文报告温度采样评测时 mode-seeking 散度更好，贪心解码时差别不大。
- 梯度不穿过学生采样；需要教师的逐 token 分布，通常要白盒教师、共用分词器。

**追问链**：
1. Agent 场景里“没见过的状态”具体是什么？→ 参数错误后的报错、检索为空、调错工具之后；教师很少走到这里，数据里没有恢复示范，学生就会重复同一个错误调用。
2. 只有 API 教师、拿不到 logits，怎么缓解偏移？→ 让学生跑轨迹，把出错的前缀交给教师续写正确动作（DAgger 式），再做 SFT；或在数据里加失败加纠错的轨迹。
3. on-policy 蒸馏比 SFT 贵在哪？→ 每步都要学生在线采样（Agent 还要跑环境）和教师前向，工程形态接近 RL。

**易错点**：
- 以为 off-policy 学生在验证集上 loss 低就没问题。验证集通常也是教师分布，测不出学生自己分布上的误差。

## train-data-009 APIGen 的三层校验各查什么，为什么工具调用数据能这样验证
- level: 2
- tags: [training, harness]

**一句话答案**：格式检查查 JSON 能否解析、函数和参数是否存在；执行检查真正调用并过滤失败；语义检查由 LLM 判断结果是否符合意图。工具调用能被执行，所以正确性能被程序检查，这是它和对话数据的区别。

**要点**：
- 第 1 层丢掉格式错误、调用不存在的函数或参数（幻觉）。
- 第 2 层 Python 函数在子进程执行、REST API 真请求，记录类型错、缺参数、超时等细粒度错误。
- 第 3 层看调用是否匹配意图、函数选得对不对、调用次数是否对、结果是否相关。
- 论文报告前两层过滤掉大部分低质量数据；把被过滤数据加回训练会变差，小模型更明显。
- 对照 ToolACE：规则层不执行，用正则查参数格式；模型层拆成编造参数、一致性、工具返回三个子问题。

**追问链**：
1. 为什么按这个顺序？→ 便宜的先做，每层只处理上一层留下的数据，最贵的 LLM 判断跑得最少。
2. 真实执行和规则检查怎么取舍？→ 真执行能抓到参数取值不合理、执行会失败的调用，但需要可访问的 API；规则检查便宜、可覆盖大量合成 API，但查不出这些问题。

**易错点**：
- 只做第 3 层的 LLM 判断。成本高，还会漏掉格式和执行层面一查就能发现的错误。

## train-data-010 用 MinHash 去重时，签名分成 b 段每段 r 个值，相似度为 s 的样本对成为候选的概率是多少
- level: 2
- tags: [training]

**一句话答案**：一段完全相同的概率是 s^r，至少一段相同的概率是 1 − (1 − s^r)^b，是一条阈值约在 (1/b)^(1/r) 的 S 形曲线。

**要点**：
- MinHash 原理：随机哈希下两集合最小值相同的概率等于 Jaccard 相似度，K 个哈希的相等比例是无偏估计，标准差约 sqrt(J(1−J)/K)。
- 调 b 和 r 控制阈值：r 越大曲线越陡、阈值越高；b 越大召回越高。
- 例：b=32、r=4 时阈值约 0.42，s=0.7 几乎必成候选，s=0.2 约 5%。
- Lee 等 2021 用 5-gram、长度 9000 的签名、每段 20 个哈希共 450 段，候选再用编辑相似度 > 0.8 确认。

**追问链**：
1. 对 Agent 轨迹去重，shingle 从哪些段取？→ 主要取用户请求和 assistant 段；工具返回的固定字段会让不同任务看起来很像，要单独处理。
2. 同一题的几条正确轨迹要不要去重？→ 思路不同的要保留，增加多样性；只换实体、思路相同的才去掉。

**易错点**：
- 把候选概率写成 s^(rb) 或 b·s^r。前者是所有段都相同，后者在 s 大时超过 1。
