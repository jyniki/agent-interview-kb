# 题目：DPO 及其变体

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。DPO 推导和“chosen 概率下降”见 [core/11](../../../core/11-post-training-basics/questions.md) 的 core-post-005、core-post-006，这里不重复。

## train-pref-001 DPO 训练后回答越来越长，原因是什么，怎么治
- level: 2
- tags: [training, evaluation]

**一句话答案**：一是偏好数据本身偏爱长回答，二是隐式奖励按 token 求和，在策略自己的分布外把这点偏好外推放大；治法有 R-DPO 的长度项、SimPO 的长度平均奖励、数据侧控长度差和评测侧长度控制胜率。

**要点**：
- Park 等（arXiv 2403.19159）：离线数据上隐式奖励和长度弱相关；策略采样的回答上长度能解释 30%–46% 的奖励方差，称为 out-of-distribution bootstrapping。
- R-DPO：在 sigmoid 里加 `α|y_w| − α|y_l|`，削弱“变长拉开 margin”的收益。
- SimPO：奖励改成 `(β/|y|)·log π_θ(y|x)`。
- 数据侧：控制 chosen 和 rejected 的长度差，加入“短而好胜过长而差”的样本。
- 评测侧：Length-Controlled AlpacaEval 用 GLM 把长度差项置零。

**追问链**：
1. R-DPO 的 α 太大会怎样？→ 惩罚长度过头，需要展开的回答被压短，要看这类任务有没有掉点。
2. 这和 GRPO 的长度偏差是一回事吗？→ 结果相似，机制不同。GRPO 来自 loss 里按回答长度平均（见 [03 章 Dr. GRPO](../03-grpo-family/README.md#3-dr-grpo去掉两处归一化)）；DPO 来自数据偏好和求和形式的隐式奖励外推。
3. 长度控制会不会过头？→ 会。目标是长度不影响偏好，不是越短越好，要看需要展开的任务有没有掉点。

**易错点**：
- 只说“数据偏长”。离线数据上相关性很弱，问题主要出在策略分布外的外推。

## train-pref-002 IPO 解决了 DPO 的什么问题，loss 长什么样
- level: 3
- tags: [training]

**一句话答案**：偏好接近确定时，Bradley-Terry 要求奖励差趋于无穷，DPO 把被拒回答的概率推到 0、KL 约束失效；IPO 改成把两个对数比之差回归到有限目标 1/(2τ)。

**要点**：
- 论文例子：p(y ≻ y') = 1 时，无论 τ 多大，最优策略都让 π(y') = 0。
- 有限数据下，真实偏好 0.8 也可能被估成 1，过拟合更常见。
- 论文认为经典 RLHF 的奖励模型“欠拟合”反而起正则作用，DPO 跳过奖励模型也丢了这层保护。
- `h_π = log(π(y_w)π_ref(y_l) / (π(y_l)π_ref(y_w)))`，`L_IPO = E[(h_π − 1/(2τ))²]`。

**追问链**：
1. τ 变小会怎样？→ 目标 margin 1/(2τ) 变大，允许偏离参考模型更多。
2. DPO 里有没有办法缓解同样问题？→ IPO 论文提到早停可以作为额外正则；IPO 的思路是从目标函数上保证有界。
3. IPO 的代价？→ 所有偏好对回归到同一个 margin，不区分很确定和勉强的偏好。

**易错点**：
- 说 IPO 是“加了 L2 正则的 DPO”。它是把 sigmoid 交叉熵整个换成平方回归。

## train-pref-003 KTO 和 DPO 有什么区别，什么时候用
- level: 2
- tags: [training]

**一句话答案**：KTO 不需要成对数据，只要每条回答“好或坏”的单点标签；它用前景理论的价值函数，让好回答的对数比高于参考点 z_0、坏回答低于 z_0，适合只有点赞点踩的数据。

**要点**：
- `r_θ = log(π_θ/π_ref)`；好回答 `λ_D·σ(β(r_θ − z_0))`，坏回答 `λ_U·σ(β(z_0 − r_θ))`；`L = E[λ_y − v]`。
- z_0 用 microbatch 内错位配对估计 KL，截到不小于 0，不回传梯度。
- 默认 β = 0.1，λ_D = λ_U = 1。
- 不平衡时让 `λ_D·n_D / (λ_U·n_U)` 落在 [1, 3/2]。

**追问链**：
1. 好坏样本比例 1:10，KTO 建议让 `λ_D·n_D / (λ_U·n_U)` 落在 [1, 3/2]，λ 怎么设？→ λ_U = 1，λ_D 取 10 到 15，让加权后的好样本略多于坏样本。
2. 为什么 z_0 用错位配对？→ 从 π_θ 采样太慢；论文说匹配的 (x, y) 奖励幅度偏大、不具代表性，用错位的 (x_i, y_j) 估计参考点。
3. KTO 的信号为什么比 DPO 弱？→ 少了同一 prompt 下两条回答的直接比较，模型只知道“这条好不好”。

**易错点**：
- 以为 KTO 不需要参考模型。它仍然需要 π_ref。

## train-pref-004 SimPO 和 ORPO 都去掉了参考模型，各自怎么做，代价是什么
- level: 3
- tags: [training]

**一句话答案**：SimPO 用长度平均的对数概率当奖励，再减一个目标 margin γ；ORPO 在 chosen 的 SFT loss 上加几率比偏好项，一个阶段完成 SFT 和对齐；两者都失去了参考模型的锚定。

**要点**：
- SimPO：`L = −log σ((β/|y_w|)log π(y_w) − (β/|y_l|)log π(y_l) − γ)`，论文建议 β 2.0–2.5、γ 0.5–1.5。
- SimPO 去掉长度归一化在消融里伤害最大；相比 DPO 运行时间约少 20%、峰值显存约少 10%。
- ORPO：`odds = P/(1−P)`，P 是长度平均似然；`L = L_SFT + λ·(−log σ(log(odds_w/odds_l)))`，论文 λ 取 0.1 到 0.25。
- ORPO 每个 batch 的前向次数是 DPO 的一半。

**追问链**：
1. SimPO 的 β 为什么比 DPO 大一个数量级？→ 奖励是每 token 平均对数概率，数值小，需要更大的缩放；DPO 的 β 乘的是整句对数比。
2. γ 太大会怎样？→ 论文观察到奖励准确率上升，但胜率先升后降，奖励分布变平，可能退化。
3. 没有参考模型，靠什么防止跑偏？→ 论文认为小学习率和多样数据让 KL 保持很低，但也承认可能导致 reward hacking；要监控和参考模型的 KL。

**易错点**：
- 把 DPO 的 β = 0.1 照搬到 SimPO。
- 说 ORPO 不需要 SFT。它把 SFT loss 包进了目标里。

## train-pref-005 离线 DPO、迭代 DPO、在线 DPO 有什么区别
- level: 2
- tags: [training, evaluation]

**一句话答案**：离线 DPO 用一份固定数据训到底；迭代 DPO 每轮用当前模型重新采样打分再训一轮；在线 DPO 每个训练步都从当前模型采样并由评委实时标偏好。越往后越 on-policy，评委偏差也越直接进梯度。

**要点**：
- 两组概念：离线 / 在线看反馈何时收集；off-policy / on-policy 看回答是谁采的（Guo 等，arXiv 2402.04792）。
- OAIF：每步采两条回答，LLM 评委选优，立刻做 DPO 更新。
- Self-Rewarding：每 prompt 采 4 条，自己当评委按 5 分量表打 3 次取平均，最高最低成对，同分丢弃，迭代三轮。
- Iterative RPO：推理题按答案对错组对，loss 是 DPO 加 chosen 上的 NLL。

**追问链**：
1. 迭代 DPO 是不是等于在线 RL？→ 不是。每一轮内数据固定，还是批量离线训练；在线 RL 每步都用当前策略采样。
2. 用自己当评委有什么风险？→ 偏差自我强化；策略学会迎合评委，和 reward hacking 同类。要留一份人工或独立评委的评测集。
3. 迭代几轮停？→ 看每轮在独立评测上的增益，增益变小或评委与独立评测开始背离就停。

**易错点**：
- 把“在线”和“on-policy”当成同一个概念。

## train-pref-006 为什么说 DPO 的最优解集合比 PPO 大，这对什么时候换到 RL 有什么启示
- level: 3
- tags: [training, evaluation]

**一句话答案**：PPO 可达的策略是 DPO 最优解集合的真子集，DPO 可能把概率放到数据没覆盖的回答上；奖励可验证、要多轮交互、或离线 DPO 到平台且输出偏离数据分布时，换在线 RL。

**要点**：
- Xu 等（arXiv 2404.10719）：PPO 可达的策略是 DPO loss 最小解集合的真子集。
- 反例：参考策略给 y3 概率 0，数据只比较 y1、y2；DPO 只要 y2 概率为 0 就最优，把 0.9 放在 y3 上也行；PPO 的 KL 排除这种解。
- 迭代 DPO 好于静态 DPO，但在代码竞赛类任务上仍明显落后 PPO。
- PPO 的关键因素：优势归一化、大 batch、参考模型 EMA 更新。

**追问链**：
1. 不想上 PPO 的全套，有什么中间路线？→ 迭代 DPO 或 OAIF；有可验证奖励时用 GRPO 一类省掉 critic 的方法，见 [03 章](../03-grpo-family/README.md)。
2. Agent 多轮任务为什么更倾向 RL？→ 轨迹空间大，固定偏好对覆盖不了；工具结果依赖前面的动作，离线对很快过时。见 [04 章](../04-agentic-rl/README.md)。

**易错点**：
- 只说“RL 效果更好”。要说出机制：分布外回答、on-policy 数据、可验证奖励。

## train-pref-007 偏好数据里 chosen 只比 rejected 略长，DPO 为什么能把生成长度推到数据范围之外
- level: 3
- tags: [training]

**一句话答案**：隐式奖励是 token 对数比之和，是长度的线性函数；DPO 只约束数据里两条回答的差，最省力的办法是改 EOS 这类对所有回答生效的全局参数，奖励在没见过的长度上无约束地外推。

**要点**：
- log π(y|x) = Σ_t log π(y_t|…)，奖励和梯度都随长度线性放大；同一对里每个 token 的梯度系数相同。
- 玩具推导：每步以概率 q 停止，数据只有长 12 和长 8、60% 长者胜；h = ΔL·log((1−q)/(1−q_ref))，最优 σ(βh) = 0.6。β = 1 时平均长度从 9 到约 250；β = 0.1 时拟合不到，长度无界。
- Park 等（arXiv 2403.19159）：训练分布内隐式奖励和长度弱相关，策略采样上长度解释 30%–46% 的奖励方差。
- R-DPO 的 α(|y_w| − |y_l|) 把长度能解释的偏好交给长度项，玩具里 α = logit(0.6)/4 时长度不动。

**追问链**：
1. β 越小长度为什么涨得越凶？→ KL 约束弱，同样的偏好要靠更大的对数比去拟合，全局参数被推得更远。
2. 怎么在训练中早发现？→ 在策略采样上画隐式奖励对长度的散点并算 R²，和训练集上的同一张图对比。
3. SimPO 能彻底解决吗？→ 去掉了线性放大，但平均 log 概率里 EOS 项随 1/L 衰减仍和长度有关，且没有参考模型约束，仍要控数据和监控长度。

**易错点**：
- 以为长度偏差只来自“数据偏长”。数据偏好很弱，问题在求和形式加分布外外推。

## train-pref-008 偏好确定时（p̂ = 1），DPO 和 IPO 的最优 margin 各是多少
- level: 3
- tags: [training]

**一句话答案**：DPO 最优 h = logit(p̂)/β，p̂ = 1 时为无穷，输家概率趋于 0，β 只影响快慢；IPO 最优 h = (2p̂ − 1)/(2τ)，p̂ = 1 时停在 1/(2τ)。

**要点**：
- h 是两个对数比之差；DPO 总体 loss 对 h 求导得 β(σ(βh) − p̂)，令其为 0。
- IPO 每对数据贡献 (h − 1/(2τ))² 和 (−h − 1/(2τ))² 两项，按 p̂ 加权后求导得 h* = (2p̂ − 1)/(2τ)。
- IPO 论文 5.3.1 节：两回答、π_ref 均匀、p* = 1 时最优 π(y1) = σ(0.5/τ)。
- 大回答空间里多数回答对只出现一次，p̂ 几乎都是 0 或 1，所以这不是边角情况。

**追问链**：
1. 梯度上的差别是什么？→ DPO 对 h 的梯度 −βσ(−βh) 永远不为 0，只会变小；IPO 的梯度 2(h − 1/(2τ)) 超过目标后变号往回拉。
2. 为什么经典 RLHF 没这么严重？→ 奖励模型被正则和早停，是欠拟合的，起了把策略留在 π_ref 附近的作用；DPO 跳过奖励模型也丢了这层保护。
3. 一个回答在数据里从没赢过会怎样？→ DPO 无论 β 多大都把它压到 0；IPO 让它的概率随 τ 平滑变化。

**易错点**：
- 以为调大 β 就能防止 DPO 把输家压到 0。β 只改变趋近 0 的速度，不改变极限。

## train-pref-009 KTO 的参考点 z_0 是什么，实践中怎么估
- level: 2
- tags: [training]

**一句话答案**：z_0 是策略相对参考模型的 KL，即所有可能回答的平均对数比；实践中在 microbatch 内错位配对 (x_i, y_{i+1}) 求平均对数比，截到不小于 0，不回传梯度。

**要点**：
- KTO 价值函数：好样本 λ_D·σ(β(r_θ − z_0))，坏样本 λ_U·σ(β(z_0 − r_θ))，r_θ = log(π_θ/π_ref)。
- 用错位的 y_j：配对的回答常被刻意挑成好或坏，奖励幅度偏大。
- 估计有偏，截断又加一点向上偏差但降低方差；多一次前向；microbatch 至少 2。
- 若 π_ref 是在同一批好样本上 SFT 出来的，KL 很快接近 0，可直接设 z_0 = 0。
- 梯度含 σ(βz)(1−σ(βz))，离参考点很远的样本几乎不贡献梯度。

**追问链**：
1. 为什么要参考点，而不是只看 r_θ 的正负？→ 模型粗暴地抬高所有回答的概率时，z_0 跟着涨，r_θ − z_0 不变，loss 不降，逼模型学“好在哪”。
2. 好坏样本的隐式奖励一起下降说明什么？→ 学习率太大；正常只有坏样本的奖励下降。
3. 梯度饱和有什么利弊？→ 利：被错标的样本奖励很极端，会被自动忽略；弊：难而必要的样本也被忽略。

**易错点**：
- 说 z_0 是一个固定超参，或者让梯度流过 z_0。
