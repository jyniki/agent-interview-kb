# 题目：GRPO 及其变体

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## train-grpo-001 GRPO 和 PPO 的核心区别是什么
- level: 1
- tags: [training]

**一句话答案**：GRPO 去掉价值模型，用同一问题 G 个回答的组内平均奖励做基线，并把 KL 直接加进 loss 而不是奖励。

**要点**：
- 优势：`Â_i = (r_i − mean(r)) / std(r)`，同一回答的所有 token 共享。
- 省掉一个和策略同规模的价值模型及其优化器状态，显存压力明显下降。
- KL 用非负无偏估计 `π_ref/π_θ − log(π_ref/π_θ) − 1`，DeepSeekMath 里 β = 0.04。
- 代价：每个问题采 G 个样本，rollout 开销大；组内奖励全相同时没有梯度。

**追问链**：
1. 去掉 critic 后，token 级的信用分配怎么办？→ 结果监督下每个 token 拿到同样的优势，没有细粒度分配。需要细粒度时可以用过程奖励，DeepSeekMath 也给了过程监督的版本。
2. G 取多大？→ 取决于任务难度和算力：太小基线方差大、零优势组多；太大 rollout 太贵。常见在 8 到 64 之间，最好看零优势组比例来调。
3. 为什么 KL 放 loss 里？→ 放进奖励会和优势计算耦合，放在 loss 里更简单；论文的说法是避免让 Â 的计算变复杂。

**易错点**：
- 说 GRPO “不需要奖励模型”。它不需要的是价值模型，奖励仍然需要（可以是规则奖励）。

## train-grpo-002 GRPO 的长度偏差从哪来，Dr. GRPO 怎么改
- level: 2
- tags: [training]

**一句话答案**：来自每个回答的 loss 除以自身长度 1/|o_i|：错误回答越长，每个 token 的惩罚越小，训练中错误回答会越变越长；Dr. GRPO 去掉这一项，并去掉优势里的 std 归一化。

**要点**：
- 正确回答：越短每个 token 更新越大，倾向变短。
- 错误回答：越长每个 token 惩罚越小，倾向变长。
- 难度偏差：除以 std 让几乎全对或全错的问题权重被放大。
- 改法：优势用 `r_i − mean(r)`；loss 聚合用固定常数（如生成长度上限）做分母。

**追问链**：
1. 普通 PPO 实现也有这个问题吗？→ 有。按每条回答 mask 求平均的 `masked_mean` 同样会引入长度偏差，Dr. GRPO 论文专门指出了这一点。
2. 去掉 std 会不会让不同问题的梯度尺度差很多？→ 会有差别，但论文认为按问题归一化本身就是偏差来源；通常批级别的归一化更合理。

**易错点**：
- 只说“长度归一化有问题”，说不出正确回答和错误回答方向相反。

## train-grpo-003 DAPO 的四项技术分别解决什么问题
- level: 2
- tags: [training]

**一句话答案**：Clip-Higher 防熵塌缩；Dynamic Sampling 丢弃零优势组；Token-Level Loss 让长回答不被降权；Overlong Reward Shaping 处理截断噪声。

**要点**：
- Clip-Higher：上下 clip 边界解耦，论文用 ε_low = 0.2、ε_high = 0.28，让低概率的探索 token 有机会被提上来。
- Dynamic Sampling：过采样，丢掉组内准确率恰为 0 或 1 的问题。
- Token-Level Loss：所有回答的 token 一起求和再除以总 token 数。
- Overlong：截断样本的 loss 屏蔽；接近长度上限的一段缓冲区内线性加长度惩罚。

**追问链**：
1. 为什么只调高上界、不调低下界？→ 上界限制的是优势为正时概率能涨多少。低概率 token 的比率很容易撞到上界，调高上界才能让它们涨上去；下界调低会让概率下降过快，增加不稳定。
2. Dynamic Sampling 有什么代价？→ 要多采样才能凑满 batch，rollout 成本增加；随着训练模型变强，全对的组越来越多，过滤比例会上升。

**易错点**：
- 把 Dynamic Sampling 说成“采样温度动态调整”。它是按组准确率过滤。

## train-grpo-004 GSPO 为什么把重要性比率放到序列级
- level: 3
- tags: [training]

**一句话答案**：token 级比率每个位置只有一个样本，起不到分布校正作用，只引入随长度累积的噪声；奖励本来就是序列级的，GSPO 用按长度开方的序列似然比做比率和 clip，在 MoE 上尤其更稳。

**要点**：
- `s_i = (π_θ(y_i|x) / π_θold(y_i|x))^(1/|y_i|)`，即 token 比率的几何平均。
- 开方归一化降低方差，让不同长度回答的比率在同一尺度，可以共用一个 clip 范围。
- clip 范围比 GRPO 小几个数量级（论文实验约 3e-4、4e-4）。
- MoE：每次更新后同一 rollout 约 10% 激活专家会变，token 级比率剧烈波动；序列似然更稳定，不需要 Routing Replay。

**追问链**：
1. Routing Replay 是什么，为什么 GSPO 不需要？→ 缓存旧策略的专家路由，重算新策略概率时沿用，以稳定 token 比率；代价是额外显存和通信。GSPO 只依赖序列似然，路由变化对它影响小。
2. 序列级 clip 会不会太粗？→ 一个回答要么整体被 clip，要么整体不被 clip，丢失了 token 级的细节；论文的论点是奖励本来就没有 token 级信息，所以这个细节本就不可靠。

**易错点**：
- 忘了长度归一化，直接用整句似然比，数值会随长度爆炸。

## train-grpo-005 把 GRPO 用在 Agent 多轮工具调用上，要改哪些地方
- level: 3
- tags: [training, harness]

**一句话答案**：最关键的是工具返回的 token 不是模型生成的，计算 loss 时要 mask 掉；此外要处理更长的轨迹、更稀疏的奖励和更贵的 rollout。

**要点**：
- Loss mask：只对模型生成的 token 算策略梯度和 KL，工具返回、系统注入的内容全部屏蔽。
- 长度：多轮轨迹很长，长度偏差和截断问题更严重，优先用 token 级或固定分母的聚合。
- 奖励：通常只有最终结果奖励，可以加格式奖励、工具调用合法性等辅助项，但要防止奖励被钻空子。
- Rollout：每个样本要真正和环境交互，需要异步 rollout、工具结果缓存、沙箱。

**追问链**：
1. 不 mask 工具返回会怎样？→ 模型被训练去“预测”工具结果，梯度被大量不可控 token 稀释，还可能学会编造工具结果。
2. 多轮里优势怎么分配到每一轮？→ 最简单是整条轨迹共享一个优势；更细的做法是轮级奖励或过程奖励，代价是需要额外的标注或评委模型。

**易错点**：
- 只讲算法，不提 rollout 系统，面试官会认为没有真正训过。
