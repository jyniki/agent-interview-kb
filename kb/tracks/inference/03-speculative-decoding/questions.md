# 题目：投机解码

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## infer-spec-001 投机解码为什么能加速
- level: 1
- tags: [inference]

**一句话答案**：Decode 受显存带宽限制，验证几个 token 和生成一个 token 读的权重一样多、耗时接近；让便宜的草稿先猜 γ 个，目标模型一次前向并行验证，一轮就可能产出多个 token。

**要点**：
- 一轮最少产出 1 个 token，最多 γ+1 个。
- 第一次拒绝后，后面的猜测全部作废。
- Leviathan 等论文报告 T5-XXL 上快 2 到 3 倍且输出相同；Chen 等报告 Chinchilla 70B 上快 2 到 2.5 倍。
- 加速来自利用 Decode 时闲置的算力，前提是 batch 小。

**追问链**：
1. 为什么验证 γ+1 个位置几乎不比 1 个慢？→ 小 batch 时算术强度远低于硬件算力带宽比，多算的部分不增加读权重的时间。
2. 最坏情况会怎样？→ 每轮第一个就被拒，只产出 1 个 token，还多花了草稿的时间，比不开更慢。

**易错点**：
- 说“投机解码减少了计算量”。总计算量反而增加，省的是串行的目标模型前向次数。

## infer-spec-002 推导：为什么投机采样不改变输出分布
- level: 3
- tags: [inference]

**一句话答案**：以 min(1, p/q) 接受草稿 token，拒绝后从 norm(max(0, p − q)) 重采；接受部分贡献 min(p, q)，拒绝部分贡献 p − min(p, q)，相加正好是 p。

**要点**：
- 推导过程：
  - β = Σ min(p(x), q(x))
  - P(接受且为 x) = q(x) × min(1, p(x)/q(x)) = min(p(x), q(x))
  - 修正分布归一化常数为 Σ (p − min(p, q)) = 1 − β
  - P(拒绝且为 x) = (1 − β) × (p(x) − min(p, q)) / (1 − β) = p(x) − min(p, q)
  - 相加得 p(x)
- 草稿高估的 token 被按比例拒掉；草稿低估的 token 由修正分布补上。
- 温度为 0 时退化成“草稿等于目标 argmax 就接受”。

**追问链**：
1. 拒绝后为什么不能直接从 p 重采？→ 接受路径已经给了 min(p, q) 的概率，再从 p 重采会重复计算这部分，结果偏离 p。
2. 为什么拒绝后要丢掉后面所有猜测？→ 后面的猜测以被拒 token 为前提，前提变了，它们的条件分布就不对了。
3. 实际实现真的逐 token 一致吗？→ 不保证。分布等价是数学保证，实现里有浮点误差，batch 变化也会影响 logprobs。
4. Medusa 的 typical acceptance 满足这个证明吗？→ 不满足。它不要求严格匹配原分布，用分布偏差换更高接受率。

**易错点**：
- 把接受概率写成 p(x)，或者写成 min(1, q(x)/p(x))。

## infer-spec-003 现场计算：接受率 α = 0.8、每轮猜 γ = 4 个、草稿每步耗时是目标模型的 5%，投机解码加速比是多少
- level: 2
- tags: [inference]

**一句话答案**：期望产出 (1 − 0.8⁵) / (1 − 0.8) ≈ 3.36 个 token；草稿成本系数 c = 0.05 时一轮耗时 1 + 4c = 1.2，加速比约 2.8 倍。

**要点**：
- 公式（Leviathan 等定理 3.8）：speedup = (1 − α^(γ+1)) / ((1 − α)(γc + 1))。
- 计算过程：
  - 0.8⁵ = 0.328，1 − 0.328 = 0.672，0.672 / 0.2 = 3.36
  - γc + 1 = 1.2
  - 3.36 / 1.2 = 2.8
- 假设各位置接受概率独立同分布；验证 γ+1 个位置耗时等于验证 1 个。

**追问链**：
1. γ 从 4 加到 8 呢？→ 期望产出约 4.33，耗时 1.4，加速约 3.09 倍，收益递减。
2. c 变成 0.3 呢？→ 耗时 2.2，加速只剩约 1.53 倍；草稿不能太大。
3. α 掉到 0.5 呢？→ 期望产出约 1.94，加速约 1.61 倍。

**易错点**：
- 忘记全部接受时还能多采 1 个 token，把期望写成 (1 − α^γ) / (1 − α)。

## infer-spec-004 草稿模型、Medusa、EAGLE、MTP 有什么区别
- level: 2
- tags: [inference, training]

**一句话答案**：草稿模型是独立小模型；Medusa 在主干最后的隐状态上挂多个头一次猜多个位置，用树形注意力验证；EAGLE 在特征层自回归预测下一步特征；MTP 是预训练自带的多 token 预测模块，可当草稿。

**要点**：
- 独立草稿：多部署一个模型，要同 tokenizer。
- Medusa-1 冻结主干，Medusa-2 主干一起微调；论文报告 Medusa-1 超过 2.2 倍，Medusa-2 为 2.3 到 2.8 倍。
- EAGLE 预测倒数第二层特征，并输入往前错一位的 token 来消除不确定性；论文报告 LLaMA2-Chat 70B 上 2.7 到 3.5 倍。
- EAGLE-3 放弃特征预测，改为直接预测 token，融合多层特征。
- DeepSeek-V3 的 MTP 深度为 1，报告第二个 token 接受率 85% 到 90%，达到 1.8 倍 TPS。

**追问链**：
1. 哪些能严格保持分布？→ 用标准拒绝采样的都能：独立草稿、EAGLE、MTP、Medusa-1 配拒绝采样；Medusa 的 typical acceptance 和 Medusa-2 改了主干都不严格。
2. 用 V3 报告的接受率验算 1.8 倍？→ γ = 1 时期望产出 1 + α = 1.85 到 1.9，扣掉 MTP 模块开销，约 1.8 倍合理。
3. 不想训练任何东西怎么办？→ n-gram / prompt 查找，从输入和已生成文本里找重复片段。

**易错点**：
- 把 DeepSeek-V3 的 MTP 说成“推理必须用”。报告说推理时可以直接丢掉，主模型独立工作。

## infer-spec-005 为什么大 batch 时投机解码收益变小甚至变负
- level: 3
- tags: [inference]

**一句话答案**：投机解码借的是 Decode 闲置的算力；batch 为 B 时一步要验证 B × (γ+1) 个 token，强度超过算力带宽比后验证不再免费，被拒的 token 成了浪费，草稿还占显存和算力。

**要点**：
- H100 稠密 BF16 约 990 TFLOPS、3.35 TB/s，比值约 295。
- B = 64、γ = 4 时 B × 5 = 320，已越过比值。
- 被拒 token 的 KV 要先写后回收，batch 内接受长度参差，增加调度开销。
- vLLM 文档：投机解码针对中低 QPS、受带宽限制的负载；高 QPS 下收益缩小，推荐对波动负载用动态投机。
- EAGLE-3 论文报告 SGLang batch=64 下吞吐仍有 1.38 倍，说明对齐好的草稿能部分缓解。

**追问链**：
1. 怎么在线上处理？→ 按负载动态开关或调 γ；高峰期用不增加负载的 n-gram 方法。
2. 离线 RL rollout 该不该开？→ 通常追求吞吐、batch 大，先压测；长尾请求阶段 batch 变小时开可能有用。
3. 只看什么指标会被误导？→ 只看单请求延迟。要同时看接受长度、TPOT 和整体吞吐。

**易错点**：
- 说“投机解码同时提升延迟和吞吐”。它主要换的是延迟。

## infer-spec-006 Agent 场景什么时候值得开投机解码
- level: 2
- tags: [inference, harness]

**一句话答案**：低并发交互式 Agent 和输出大量复述输入的任务（改代码、引用工具结果）最值得，n-gram 草稿就很有效；输出很短的工具调用和高并发批量 rollout 收益有限，要按真实流量压测再决定。

**要点**：
- 编码 Agent 改文件：输出复述原文多，prompt 查找接受率高。
- 短 JSON 工具调用：Decode 步数少，固定开销占比高。
- 长思考链：步数多，延迟收益大，但开放文本接受率通常低于代码。
- 约束解码和投机解码同时用时，草稿 token 也要满足语法约束，否则会被拒。

**追问链**：
1. 怎么评估是否上线？→ 用真实 Agent 轨迹回放，比较开关前后的接受长度、TPOT、P99 延迟和吞吐，再看输出是否一致。
2. 温度设置有影响吗？→ 有。Leviathan 等论文观察到 argmax 采样（温度 0）的 α 和加速都高于温度 1，例如翻译任务上 3.4 倍对 2.6 倍。

**易错点**：
- 用公开 benchmark 上的加速比直接估自己的 Agent 流量。接受率和任务强相关。

## infer-spec-007 推导：投机解码的最优猜测长度 γ 满足什么条件，随接受率和草稿成本怎么变
- level: 3
- tags: [inference]

**一句话答案**：γ 加 1 多产出 α^(γ+1)、多花 c；继续加的条件是 α^(γ+1)/E(γ) > c/(1+γc)，第一个不满足的 γ 最优。α 越高最优 γ 越大，c 越大越小。

**要点**：
- E(γ) = (1 − α^(γ+1))/(1 − α)，加速比 S(γ) = E(γ)/(1 + γc)。
- S(γ+1) > S(γ) ⇔ α^(γ+1)(1 + γc) > c·E(γ)。
- 条件一旦不成立就一直不成立，S(γ) 单峰，所以从小往大找第一个不成立的 γ。
- 数值：c = 0.05 时 α 从 0.5 到 0.9，最优 γ 为 3、4、6、8、13；α = 0.8 时 S(8) ≈ 3.09。
- 峰附近很平：α = 0.8、c = 0.05 时 γ 取 5 到 12 都在峰值 95% 以内。

**追问链**：
1. c → 0 时怎样？→ γ 越大越好，但加速被 1/(1 − α) 封顶，α = 0.8 时最多 5 倍。
2. 为什么实践里 γ 常取得比理论最优小？→ α 随请求和位置波动；batch 大时多猜一个要真实付验证的算力，最优 γ 变小。
3. α ≤ c 时呢？→ 推论 3.9：任何 γ 都不加速，应该关掉。

**易错点**：
- 以为 γ 越大越好。多猜的边际产出按 α^(γ+1) 指数递减，草稿时间线性增加。

## infer-spec-008 估算：Qwen3-8B（BF16）在 H100 SXM 上、上下文 256、每轮猜 4 个，batch 多大时投机验证不再免费
- level: 3
- tags: [inference]

**一句话答案**：验证一步算 B×5 个 token，只读一遍权重和 KV；算力项追上带宽项的拐点约 B×5 ≈ 295，即 B 约 59，计入 KV 读取后约 68。超过后验证耗时随 B 线性涨。

**要点**：
- 硬件比值：990 TFLOPS / 3.35 TB/s ≈ 295 FLOP/B。
- 拐点：B·(γ+1)·F_tok/PEAK = (W + B·T·E_kv)/BW，解出 B* = (W/BW) / ((γ+1)·F_tok/PEAK − T·E_kv/BW) ≈ 68.5。
- B = 128 时验证一步是普通 Decode 的约 1.66 倍，B = 256 时约 2.67 倍。
- 按 roofline 估算、α = 0.8、0.6B 草稿：B = 1 时吞吐约 2.5 倍，约 186 时变成负收益。

**追问链**：
1. 上下文 32K 时还是这个拐点吗？→ 不是。KV 读取随 B 一起涨，强度被钉在 I_max(T) ≈ 7；(γ+1)·I_max < 295 时任何 batch 验证都免费，γ = 4 时上下文超过约 1,860 就成立。
2. 那长上下文时瓶颈在哪？→ 草稿也要读自己的 KV。完整 KV 的 Qwen3-0.6B 每 token KV 是目标的 78%，c 约 0.75，开投机反而慢；要用稀疏 KV 草稿或 n-gram。
3. 树形验证对拐点有什么影响？→ 每条序列送进目标的 token 数是树的节点数，拐点按节点数提前。

**易错点**：
- 只用 B·(γ+1) 和 295 比，忽略长上下文时 KV 读取会让验证重新变免费。

## infer-spec-009 用“接受数除以草稿提出数”估计投机解码的接受率有什么问题
- level: 2
- tags: [inference]

**一句话答案**：第一次拒绝后的草稿没被检验，算进分母会低估 α。应按位置算条件接受率（接受数 / 被检验数），或直接用每轮平均产出对公式 E(N)。

**要点**：
- 模拟：真实 α = 0.8、γ = 4 时，接受数 / 提出数约 0.59，接受数 / 被检验数约 0.80。
- 被检验数 = 接受数 + （本轮有拒绝时的那 1 个）。
- 接受长度也有两种口径：含 bonus 或修正 token（E(N)），和只算接受的草稿（E(N) − 1）。
- EAGLE 论文的 n-α 是“前面都接受的条件下”第 n 个位置的接受率。

**追问链**：
1. 为什么 α 会随位置变？→ 越往后草稿条件于自己的猜测，误差累积；Medusa 的第 k 个头跳着猜，越往后越不准。i.i.d. 假设只是近似。
2. 怎么用线上指标核对加速比？→ 取每轮平均产出 token 数和实测 c，代入 E(N)/(1 + γc)，再和实测 TPOT 比较。

**易错点**：
- 拿低估的 α 代公式，得出“投机不划算”的错误结论；或者比较两个引擎时没对齐口径。

## infer-spec-010 Medusa 的 typical acceptance 和 Leviathan 的宽容度参数为什么不保持输出分布
- level: 3
- tags: [inference]

**一句话答案**：两者都放松了验证。typical acceptance 只要候选概率高于 min(ε, δ·e^(−H)) 就接受，首 token 用贪心；宽容度把 q 乘 l<1 再比，只保证概率不超过 p/l。

**要点**：
- 标准规则的证明靠两项相加：接受部分 min(p, q)，修正部分 p − min(p, q)。改了接受概率，这两项就不再加成 p。
- typical acceptance：够典型的候选总被接受，这个位置的输出趋于确定；示例里 TV 距离达到 0.55。ε 越大质量越高、加速越小（Medusa 论文图 5）。
- 宽容度 l：α = Σ min(p/l, q)，l 越小接受越多；l 小到 α = 1 时输出退化成 q。
- Leviathan 等论文附录 A.5 报告 T5-XXL 配 T5-small 时，l = 1、0.5、0.3、0.1 的加速为 2.5、3.1、3.6、5 倍；正文全部用 l = 1。

**追问链**：
1. 什么场景必须用严格规则？→ 要和原模型同分布时，例如 RL rollout 的样本要来自当前策略，或者评测要和不开投机可比。
2. Medusa-2 配标准拒绝采样能保持分布吗？→ 能保持 Medusa-2 主干本身的分布，但主干微调过，已经不是原模型的分布。

**易错点**：
- 以为“用了投机解码框架”就一定无损。是否无损取决于验证规则和主干是否改动。
