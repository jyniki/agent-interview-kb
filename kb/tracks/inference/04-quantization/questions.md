# 题目：量化：权重、激活与 KV 量化

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## infer-quant-001 对称量化和非对称量化有什么区别
- level: 1
- tags: [inference]

**一句话答案**：对称量化零点固定为 0，用 max|x| 定缩放，适合以 0 为中心的分布；非对称量化用 min 和 max 定范围并多存一个零点，分布偏向一侧时刻度用得更满、误差更小。

**要点**：
- 对称：`s = max|x| / (2^(b−1) − 1)`，`x̂ = s·q`。
- 非对称：`s = (max − min) / (2^b − 1)`，`x̂ = s·(q − z)`。
- 权重多用对称；偏态的激活、KV 常用非对称（KIVI 就是非对称 2 bit）。
- 离群值会把 s 拉大，让其余值挤在少数刻度上，这是 LLM 量化的主要难点。

**追问链**：
1. 离群值怎么处理？→ 缩小量化粒度（per-channel、per-group）；把离群维度拆出来用高精度算（LLM.int8()）；或用等价变换把难度从激活搬到权重（SmoothQuant）。
2. 为什么 FP8 对离群值更宽容？→ 浮点有指数位，动态范围大，刻度不均匀，大值和小值都能表示。

**易错点**：
- 以为非对称一定更好。它多存零点，反量化多一次运算，对以 0 为中心的权重收益很小。

## infer-quant-002 现场估算：70B 模型 INT4 量化，每 128 个权重一组、每组一个 FP16 缩放和一个 FP16 零点，权重多大
- level: 2
- tags: [inference]

**一句话答案**：每 128 个权重配一个 FP16 缩放和一个 FP16 零点，额外 0.25 bit，等效约 4.25 bit；70e9 × 4.25 / 8 ≈ 37 GB，对比 BF16 的 140 GB。

**要点**：
- 计算过程：
  - 缩放：16 / 128 = 0.125 bit；零点：16 / 128 = 0.125 bit
  - 等效：4 + 0.25 = 4.25 bit
  - 权重：70e9 × 4.25 / 8 ≈ 37.2 GB
- 对比：BF16 140 GB，INT8 70 GB。
- 嵌入和输出层常不量化，实际文件更大一点。
- 一张 80 GB 卡放下权重后还剩 40 GB 左右给 KV。

**追问链**：
1. 组从 128 改成 32 呢？→ 额外开销变成 1 bit，等效约 5 bit，约 44 GB；精度更好，代价是体积和读缩放的开销。
2. 那 KV 能放多少？→ 回到[第 01 章](../01-kv-cache-memory/README.md)的公式，用 KV 头数、层数、head_dim 算每 token 字节，剩余显存除以它。

**易错点**：
- 只算 4 bit，忘了分组缩放和零点的开销。

## infer-quant-003 W4A16 为什么能加速 Decode，却可能让 Prefill 变慢
- level: 2
- tags: [inference]

**一句话答案**：小 batch Decode 受带宽限制，读的权重降到约 1/4，反量化几乎免费；Prefill 受算力限制，矩阵乘仍是 16 位，反量化是额外计算，可能变慢。加速 Prefill 要靠 W8A8。

**要点**：
- W4A16：权重 4 位存储，算时反量化到 16 位，激活保持 16 位。
- Decode：每步读全部权重，计算量小，读得少就快。
- Prefill 和大 batch Decode：计算密集，瓶颈不在读权重。
- W8A8（INT8 或 FP8）：矩阵乘直接用 8 位单元，两个阶段都能加速，但需要硬件支持。

**追问链**：
1. 长上下文 Decode 量化权重够吗？→ 不够。这时读 KV 是主要成本，要量化 KV。
2. 量化省下的显存去哪了？→ 通常分给 KV，并发上去，吞吐提升主要来自这里。

**易错点**：
- 说“量化一定更快”。要看瓶颈和 kernel。

## infer-quant-004 GPTQ 和 AWQ 的核心思路有什么不同
- level: 2
- tags: [inference]

**一句话答案**：GPTQ 用层输入的二阶信息逐列量化，并把每列的量化误差补偿到还没量化的列上；AWQ 用激活幅度找出约 1% 的显著通道，对这些通道做等价放大来减小它们的相对误差，不做反向传播和重构。

**要点**：
- GPTQ：Hessian H = 2XXᵀ，固定列顺序、延迟批量更新、Cholesky 分解；论文用 C4 的 128 段 2048 token 做校准，一张 A100 约 4 小时量化 175B 模型。
- AWQ：显著性看激活而不是权重；保留 1% 权重为 FP16 效果好但硬件不友好，所以改成等价缩放；缩放指数在 [0, 1] 上网格搜索。
- 两者都是只量化权重的 PTQ，常见配置 W4A16、分组 128。

**追问链**：
1. 哪个更好？→ 没有固定答案。论文各自报告了占优的设定；实际看目标引擎对哪种格式的 kernel 更成熟，再在自己的任务上比。
2. 校准数据要和业务一致吗？→ GPTQ 做重构，校准分布偏差影响更大；AWQ 只统计激活幅度，论文认为对校准集过拟合更少。Agent 场景最好混入带工具调用格式的样本再验证。
3. 为什么 AWQ 放大显著通道能减误差？→ 量化误差主要由组内缩放和舍入决定，放大单个通道不太改变组缩放，它的相对误差就变小；激活侧除回去保持输出等价。

**易错点**：
- 把 GPTQ 和 FP8 放在一起比。GPTQ 是算法，FP8 是数值格式。

## infer-quant-005 KV Cache 量化怎么做，Key 和 Value 为什么分开处理
- level: 3
- tags: [inference]

**一句话答案**：K、V 从 16 位压到 8 位或更低，省长上下文的显存和读带宽；Key 有固定的离群通道，按通道量化；Value 没有，按 token 量化；最近若干 token 保持全精度，凑满一组再量化。

**要点**：
- Key 按通道、Value 按 token 的依据出自 KIVI。
- 工程上最常用的是 FP8 KV，例如 vLLM 的 `--kv-cache-dtype fp8`，默认 per-tensor 缩放，推荐用校准数据估计缩放因子。
- KIVI：2 bit 非对称，最近 R=128 个 token 保持全精度。
- KVQuant：Key 按通道并在 RoPE 之前量化，加非均匀数据类型和离群值单独存，论文报告 3 bit 下困惑度上升小于 0.1。
- 代价：需要能读低位 KV 的 attention kernel；MLA 等缓存布局要专门适配；误差随长度累积。

**追问链**：
1. 为什么 Key 要在 RoPE 之前量化？→ RoPE 按位置旋转通道对，会把原本固定在某些通道上的离群值打散到不同位置，按通道量化就不准了。
2. 为什么 Value 按 token？→ 注意力输出是 Value 按注意力权重加权求和，按 token 量化让每个 token 的误差被限制在自己的向量里。
3. 量化 KV 后怎么验证？→ 长上下文检索（大海捞针）和长轨迹任务单独回归；滑动窗口等敏感层可以跳过量化。

**易错点**：
- 以为权重量化同时也量化了 KV。两者是独立配置。

## infer-quant-006 量化会怎样影响 Agent 的工具调用和长链推理，上线前怎么验证
- level: 3
- tags: [inference, evaluation, harness]

**一句话答案**：公开研究显示 8 位基本无损、4 位权重量化对简单任务影响小，但越难、越长、越接近真实应用的任务掉得越多；Agent 依赖精确参数和多步正确，所以要在自己的任务上单独测工具调用正确率和长轨迹成功率。

**要点**：
- Quantization Hurts Reasoning?（2025-04）：W8A8 基本无损，W4A16 或 KV 量化下降大多不超过 1%，1.5B 小模型上会超过；难任务下降最多是简单任务的 4 倍；KV 3 bit 时小模型下降超过 5%。
- ACBench（2025-05）：4 bit 量化下工具调用和工作流生成下降 1% 到 3%，真实应用类任务下降 10% 到 15%。
- 敏感原因：参数逐字符精确；多步错误传递；长上下文依赖 KV 精度。
- 评测清单：JSON 合法率、函数名和参数完全匹配率、按难度和步数分桶的成功率、长上下文检索、输出长度和步数变化。

**追问链**：
1. 只看困惑度可以吗？→ 不行。困惑度是平均指标，工具参数里一个数字错了对它几乎没影响，但调用会失败。
2. 量化后步数变多怎么办？→ 算总成本而不是单步成本：省下的单 token 成本可能被更多步数抵消，必要时换更高位宽或更大的量化模型。
3. 显存紧张，选“小模型 BF16”还是“大模型 4 bit”？→ Quantization Hurts Reasoning? 报告大的量化模型精度和延迟的权衡好于小的 BF16 模型，但要在自己的 Agent 任务上验证。

**易错点**：
- 只拿通用榜单分数判断“无损”，不测工具调用和长轨迹。

## infer-quant-007 均匀量化的舍入误差上界和期望是多少，量化粒度为什么越细误差越小
- level: 2
- tags: [inference]

**一句话答案**：不截断时误差不超过半个步长 s/2；误差近似均匀分布，期望平方误差 s²/12，每多 1 位约降到 1/4。粒度越细，每组的最大值不会更大，步长只会变小，离群值也只影响自己那一组。

**要点**：
- 推导：e 在 [−s/2, s/2] 上均匀，E[e²] = ∫ e²/s de = s²/12。
- 对称量化 s = max|x| / (2^(b−1) − 1)，所以组里最大的那个数决定整组的误差。
- 存储代价：每组一个 FP16 scale 多 16/g 位，加 FP16 零点再多 16/g 位；g=128 时合计 0.25 位。
- 截断能缩小 s，但被截断的元素误差不再受 s/2 约束。

**追问链**：
1. 均匀分布的假设什么时候不成立？→ 分布相对步长很尖或很稀疏时，例如大量精确为 0 的值；以及发生截断时。
2. 为什么不全用 g=32？→ 等效位宽从 4.25 升到 5，体积约多 18%，kernel 读 scale 的开销也变大；收益要在任务上测。

**易错点**：
- 以为误差和元素自身的大小成正比。均匀量化的绝对误差只和步长有关，小值的相对误差反而更大。

## infer-quant-008 推导 SmoothQuant 的平滑因子，说明迁移强度 α 取 0.5 时平衡了什么
- level: 3
- tags: [inference]

**一句话答案**：每个输入通道取 s_j = max|X_j|^α / max|W_j|^(1−α)，激活除以 s、权重行乘以 s，输出不变。α=0.5 时该通道两侧最大值相等，激活和权重分担同样的量化难度。

**要点**：
- 等价变换：Y = (X diag(s)⁻¹)(diag(s) W)，diag(s)⁻¹ 可离线并进前一层。
- 代入得 max|X̂_j| = (max|X_j| · max|W_j|)^(1−α)，max|Ŵ_j| = (max|X_j| · max|W_j|)^α。
- α 越大，越多难度搬到权重；论文多数模型用 0.5，激活离群更严重时用更大的值（如 0.75），α 由网格搜索决定。
- 为什么需要它：离群值沿输入通道（矩阵乘的内维），INT8 GEMM 的 scale 只能放在外维，激活只能 per-token 或 per-tensor，处理不了通道离群。

**追问链**：
1. 为什么不直接按输入通道量化激活？→ scale 在内维上，整数累加之后没法乘回去，Tensor Core 的高吞吐路径不允许中途插入缩放。
2. α=1 会怎样？→ 激活每个通道最大值相同，好量化；但离群值整个搬到权重的对应行，权重变得难量化，误差回升。

**易错点**：
- 以为 SmoothQuant 改变了模型的数学函数。它是等价变换，只改变量化难度放在哪一侧。

## infer-quant-009 写出 GPTQ 量化一列之后补偿剩余权重的公式，并说明它为什么比 RTN 的层输出误差小
- level: 3
- tags: [inference]

**一句话答案**：量化第 q 列后，把它的误差除以 [H⁻¹]_qq，再沿 H⁻¹ 的第 q 列分摊到未量化的权重上，H = 2XXᵀ。输入通道相关时误差能被抵消，RTN 做不到。

**要点**：
- 公式：δ_F = −(w_q − quant(w_q)) / [H⁻¹]_qq · H⁻¹_{:,q}（GPTQ 式 (2)）。
- 目标：逐层最小化 ‖WX − ŴX‖²，按行拆开是二次型 ½(w − ŵ)H(w − ŵ)ᵀ，所有行共用 H。
- 量化一列后用一步高斯消元从 H⁻¹ 里删掉这一列，不用重新求逆。
- 三个工程改动：所有行用固定列顺序；B=128 列一块做延迟批量更新；用 Cholesky 预先求出需要的 H⁻¹ 行，加 1% 平均对角元的阻尼。
- GPTQ 的权重离原值可能更远，但层输出更准。

**追问链**：
1. 为什么能用固定列顺序？→ 论文发现大模型上贪心顺序的收益很小；固定顺序后所有行的 H_F⁻¹ 相同，只需更新 d_col 次。
2. 为什么要 Cholesky？→ 反复消元会累积数值误差，H⁻¹ 可能变得不定，把权重往错的方向推；每步只需要 H⁻¹ 一行的右半部分，正好是 Cholesky 上三角因子的一行。
3. act-order 做了什么？→ 按 H 对角元从大到小排列量化顺序，重要的列先量化、有更多剩余列帮它补偿。

**易错点**：
- 以为 GPTQ 换了量化网格。网格事先固定，GPTQ 只决定每个权重舍入到哪一格，并调整还没量化的权重。

## infer-quant-010 现场估算：H100 SXM（BF16 稠密约 990 TFLOPS、带宽 3.35 TB/s）上 W4A16（等效 4.25 位）的线性层，batch 多大时不再比 BF16 快
- level: 2
- tags: [inference]

**一句话答案**：线性层强度 I = 16b / w，W4A16 约 3.76b。硬件比值约 295，b ≈ 78 时 W4A16 就受算力限制；更大 batch 和 Prefill 两者都算力受限，不再加速。

**要点**：
- 计算 2bN，读权重 N·w/8 字节，激活字节忽略。
- 小 batch 时加速比约等于字节比 16 / 4.25 ≈ 3.76。
- W4A16 的矩阵乘仍以 BF16 算力执行，反量化是额外计算，算力受限时可能更慢。
- 要加速算力受限的阶段，用 W8A8：INT8/FP8 稠密算力约为 BF16 的 2 倍。

**追问链**：
1. 长上下文 Decode 时这个结论还成立吗？→ 还要加上读 KV 的字节，而且 KV 不随 batch 摊薄；权重量化减不了这部分，要靠 KV 量化或 GQA/MLA。
2. 为什么实际转折点可能更早？→ 反量化占用计算单元和寄存器，kernel 达不到理论峰值。

**易错点**：
- 用 4 位而不是含分组开销的等效位宽算字节；或者把 W4A16 的算力当成 INT4 算力。
