# 题目：主流 Agent Benchmark 与它们的局限

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## eval-bench-001 拿到一个没见过的 Agent Benchmark，你怎么快速判断它的价值
- level: 2
- tags: [evaluation]

**一句话答案**：问四件事：测什么能力；题怎么来、怎么保证质量；怎么判分、判分会漏掉什么；已知局限，尤其是污染、饱和和环境漂移。

**要点**：
- 判分方式大致三类：执行测试、检查环境终态、比对短答案；知道类别就能推出它会漏什么。
- 题目质量：有没有人工复核、有没有参考解、有没有不可完成题这类反面题。
- 污染：题和答案是否公开，有没有保留集或按时间更新。
- 饱和：分数是否已接近上限，剩下的失败题里有多少是坏题。

**追问链**：
1. 执行测试类会漏什么？→ 测试覆盖不全时错补丁能过；测试太窄（要求题面没提的实现细节）或太宽（测了题面没要求的行为）时对补丁被拒；也测不到可维护性。
2. 终态检查类会漏什么？→ 过程违规，比如没确认就执行写操作；终态检查函数本身也可能写错。
3. 有现成的审查提纲吗？→ Zhu 等人的 Agentic Benchmark Checklist，从任务设置和奖励设计两方面检查，报告缺陷能让结果相对偏差最多 100%。

**易错点**：
- 只看榜单分数和题量，不看判分逻辑。
- 认为人工核验过的子集就没有污染。核验解决的是题错，不是记忆。

## eval-bench-002 SWE-bench 有哪些变体，各自补了什么缺口
- level: 2
- tags: [evaluation, harness]

**一句话答案**：Lite 是便宜子集；Verified 人工剔除坏题；Multimodal 补前端和图片；Multilingual 补多语言；Live 持续收新题防污染；Pro 测长程多文件任务，留私有题。

**要点**：
- 规模：Lite 300 题，Verified 500 题，Multilingual 9 种语言，Live 收 2024 年后的 issue。
- 判法基本不变：打补丁后跑 FAIL_TO_PASS 和 PASS_TO_PASS 测试。
- Verified：93 位开发者标注 1699 题，每题 3 人取最严重判定，剔除 68.3%。
- Multimodal 617 题，17 个 JavaScript 库，每题题面或测试至少一张图。
- Live 首发 1319 题、93 个仓库，自动化流水线建环境。
- Pro 1865 题、41 个仓库，分公开、保留、商业三部分。

**追问链**：
1. OpenAI 审计里“太窄”和“太宽”的测试各指什么，会怎样误判？→ 太窄：要求题面没提的实现细节；太宽：测了题面没要求的行为；两者都会拒绝正确补丁，让分数低估。（背景：审计的 138 道难题里，至少 59.4% 有实质问题，即测试有缺陷或题面不清；其中 35.5% 太窄、18.8% 太宽。）
2. 怎么证明模型是记住了而不是会做？→ 只给 issue 文本不给仓库，看能否说出 bug 所在文件；对比在 SWE-bench 以外仓库上的同样任务，差距大说明有记忆（SWE-Bench Illusion）。
3. Lite 的过滤规则偏向什么题？→ 自包含的单文件小改动：去掉带图片外链、少于 40 词、改多个文件或超过 3 个 hunk 的题。

**易错点**：
- 把 Lite 当成“更难”或“更干净”的版本。它只是更便宜，不解决测试质量问题。

## eval-bench-003 τ-bench 和 τ²-bench 有什么区别
- level: 2
- tags: [evaluation, harness]

**一句话答案**：τ-bench 只有 Agent 能改环境，用户只给信息；τ²-bench 加了双控：用户也有工具，能操作模拟手机；判分加入状态断言，并用消融实验把推理错误和协调错误分开。

**要点**：
- 双控只在新加的电信领域。
- τ²-bench 含零售 115 题、航空 50 题的校订版，加电信 114 题。
- 电信题由生成器把 15 组原子子任务组合成 2285 题再均衡抽样。
- 判分可组合：数据库检查、必需信息检查、状态断言、自然语言断言、动作匹配；电信只用断言。
- No-User：Agent 控制全部工具，只测推理和工具调用。Oracle Plan：给出正确调用序列，只测和用户协调。

**追问链**：
1. 双控为什么更难？→ Agent 不能直接看和改用户那边的状态，要靠对话引导用户操作并确认结果，是部分可观察的协作问题。
2. 消融的价值是什么？→ 分数掉了能定位是推理不会，还是沟通协调不会，对应不同的改法。
3. τ-bench 判分有什么已知问题？→ 终态对不代表过程合规；Agentic Benchmark Checklist 指出它曾把空回复判为成功。

**易错点**：
- 说 τ²-bench 只是 τ-bench 加了一个领域。核心变化是用户也能动环境，以及消融设计。

## eval-bench-004 BFCL 怎么评测函数调用，多轮部分怎么判
- level: 2
- tags: [evaluation, harness]

**一句话答案**：单轮题把调用解析成 AST 和标准调用比对，覆盖单个、多选、并行、组合和无关检测；多轮每轮结束后做状态检查（后端状态等于标准状态）和响应检查（调用包含人工标的最小调用集合），两项每轮都过才算对。

**要点**：
- 无关检测测“该不该调”：给的函数都不该用时要克制住。
- Live 部分来自用户贡献的真实函数和请求。
- v3 多轮 1000 条，含缺参数、缺函数、长上下文等增强类别；一轮超过 20 步判错。
- 状态检查允许不同路径，只要终态一致；响应检查覆盖只读请求，因为只读调用不改状态。
- 总分是子类不加权平均，子类构成变了就不能和旧版直接比。

**追问链**：
1. AST 比对有什么问题？→ 语义等价但写法不同的参数可能判错；只测单步，不测整体任务完成。
2. 为什么多轮不只做状态检查？→ 查询类操作不留状态痕迹，只看状态会让“没查就编”的回答也过。
3. 对自建工具评测有什么借鉴？→ 写操作看状态，读操作看最小必需调用集合，再加无关检测这类反面题。

**易错点**：
- 只看总分不看子类。无关检测和多轮子类往往才是业务里出事的地方。

## eval-bench-005 GAIA 和 BrowseComp 都是短答案，出题思路有什么不同
- level: 2
- tags: [evaluation]

**一句话答案**：GAIA 按所需步数和工具数分三级，答案短且唯一，用准精确匹配判，留一部分题不公开答案；BrowseComp 倒着出题，组合多个特征做到难找好验证，要求当时的模型答不出，用模型评委判语义等价。

**要点**：
- GAIA 留 300 题不公开答案；BrowseComp 组合的是搜索空间大的特征。
- GAIA 466 题：一级至多 5 步，二级约 5-10 步且组合工具，三级不限。
- GAIA 两位新标注者独立作答，和出题人一致才保留，候选里约 68% 有效。
- BrowseComp 1266 题，还让模型报置信度测校准。
- BrowseComp 作者自述：不涉及长答案和澄清歧义，参考答案很可能但不保证唯一。

**追问链**：
1. 短答案判分的好处和代价？→ 便宜、可复现；只能测有唯一答案的任务，答案公开后容易被搜到或背下。
2. 为什么 GAIA 不公开测试集答案？→ 防止答案进入训练数据或被直接检索。
3. 自建深度研究评测能直接照搬吗？→ 只能借鉴“难找好验证”的出题方式；真实需求多是长答案报告，还要配 rubric 评委（见 [02](../02-llm-as-judge/README.md)）。

**易错点**：
- 把 BrowseComp 当成“综合研究能力”评测。它测的是窄的检索坚持能力。

## eval-bench-006 环境类 Benchmark（网页、桌面、终端）有哪些典型问题
- level: 2
- tags: [evaluation, harness]

**一句话答案**：环境会漂移让好题变坏题；不可完成题会诱导模型过度放弃；判分写松会被钻空子；跑一次又慢又贵。对应做法是定期修题和评测函数、正反两面都出题、用找作弊 Agent 审判分、并行化环境。

**要点**：
- WebArena 812 题、241 个模板，判分是问答比对或用选择器、数据库查询取内容后查关键字。
- OSWorld 369 题，每题有初始化配置、getter 和 evaluator，共 134 种评测函数，可给部分分。
- OSWorld-Verified 处理约 300 条反馈：网页结构变化、验证码、预订日期过期、评测过严、初始化时序问题；多数改评测函数而非题面。
- WebArena 发现提示“做不到就答 N/A”后，模型会把大量能做的题也判成做不到。
- Terminal-Bench 2.0 89 题：CI 确认参考解能过、空操作失败；让 Agent 专门找作弊，发现过改测试环境、猜答案、列举所有答案。

**追问链**：
1. 怎么防止环境漂移？→ 尽量自建可复现环境（WebArena 的做法）；必须连真实网站时标记易变题、固定快照、定期复核。
2. 为什么要测空操作 Agent？→ 空操作能过的题说明判分没检查任何东西，是坏题。
3. 终态检查和看命令输出，Terminal-Bench 为什么选前者？→ 允许任意解法；代价是要确保终态检查足够严，所以要做找作弊审查。

**易错点**：
- 以为“环境真实”就等于“评测可靠”。真实环境带来漂移和反爬，可靠性要靠持续维护。

## eval-bench-007 公开 Benchmark 的污染有哪些检测手段，为什么只做 n-gram 去重不够
- level: 3
- tags: [evaluation, training]

**一句话答案**：静态检查做 n-gram 和改写重叠，行为上做新题对照、按时间切分、保留集和记忆诊断；n-gram 查不出改写和翻译，要用 LLM 判定补上。

**要点**：
- n-gram 查不出改写和翻译。Yang 等用 LLM 判断改写重叠，在 RedPajama-Data-1T 和 StarCoder-Data 里发现 8%-18% 的 HumanEval 题有重叠。
- GSM1k 仿照 GSM8k 重出题：部分模型族掉分，越能背出原题的模型掉得越多。
- 按时间切分和持续更新：LiveCodeBench、SWE-bench-Live。
- 保留集：GAIA 测试集、SWE-Bench Pro 保留集和商业集。
- 金丝雀字符串只是方便过滤，仓库公开时防护有限。

**追问链**：
1. 金丝雀字符串能防污染吗？→ 只方便训练方过滤；仓库被转载或训练方不过滤时就没用。
2. 污染和饱和有什么关系？→ 都让分数失去区分度；接近上限时剩下的失败题里坏题比例变高，要审计这些题。

**易错点**：
- 只做 n-gram 去重就说“没有污染”。
- 一看新题掉分就断定污染，不排除难度差异。

## eval-bench-008 执行测试类 Benchmark 的测试太窄、太宽、太松各会让分数往哪边偏，为什么用标准补丁验证测试查不出前两种
- level: 3
- tags: [evaluation, harness]

**一句话答案**：太窄、太宽都会拒绝正确解，让分数低估；太松会放过错解，让分数高估。测试和标准补丁出自同一个 PR，标准补丁在这三种测试上都能过，所以查不出；要用独立写的正确解或人对照题面读测试。

**要点**：
- 太窄：测了题面没提的实现细节，如函数名、报错文本。OpenAI 举过 pylint-dev__pylint-4551：测试直接 import 一个题面没提的 `get_annotation`。
- 太宽：测了题面没要求的额外行为，比如 PR 顺手改的边界情况。
- 太松：只覆盖了题面例子，只修一部分的错补丁也能过。
- 把评分器看成分类器：太窄、太宽降低 Se，太松降低 Sp。
- 背景：OpenAI 审计的 138 道 Verified 难题里，至少 59.4% 有实质问题，35.5% 太窄、18.8% 太宽。

**追问链**：
1. 怎么查出太松的测试？→ 跑空操作补丁和只硬编码题面例子的补丁，能拿分就说明测试太松；Terminal-Bench 在 CI 里要求空操作必须失败。
2. 太窄的测试和污染怎么叠在一起？→ 太窄的测试要求题面没提的名字或参数，背过原 PR 的系统能写对，没背过的写不对；误判从“对所有系统一样”变成“偏向有记忆的系统”。
3. Terminal-Bench 的“明确”标准是什么？→ 测试通过当且仅当终态可接受：“当”排除太窄太宽，“仅当”排除太松。

**易错点**：
- 以为人工核验过的题集就没有测试问题。Verified 核验后，审计难题仍有大量太窄、太宽。
- 只想到“错补丁能过”一个方向，忘了测试也会拒绝正确补丁。

## eval-bench-009 评分器灵敏度 0.85、特异度 0.95 时，两个系统 10 个点的真实差距在分数上剩多少
- level: 3
- tags: [evaluation]

**一句话答案**：观测分 q = (1 − Sp) + (Se + Sp − 1)p，差距乘斜率 0.8，只剩 8 个点；同样检出力要多约 1.56 倍的题。前提是误判和被测系统无关。

**要点**：
- 截距 1 − Sp：什么都不会的系统也有 5 分；上限 Se：全对的系统也只有 85 分。
- 已知 Se、Sp 可以反解 p̂ = (q + Sp − 1)/(Se + Sp − 1)，代价是标准误放大 1/(Se + Sp − 1) 倍。
- Se、Sp 要在一批人工复核过的题上估。
- 推导见 evaluation/01 第 4.1 节。

**追问链**：
1. 什么情况下反解救不回来？→ 误判和系统相关时，比如有记忆的系统更容易过太窄的测试，或评委偏爱某种风格；这时斜率不是常数，排序都可能错。
2. 修评分器和加题哪个划算？→ 加题只降抽样误差；提高 Se、Sp 同时减小压缩，能用代码判的不用模型判。
3. 榜单上差 4 个点的两个系统一定有强弱吗？→ 不一定；500 题、通过率 60% 附近，抽样标准误约 2.2 个点，再加误判压缩，差 4 个点常常不显著。

**易错点**：
- 以为评分器误判只会加噪声、不改变期望。它把差距系统性地压小。

## eval-bench-010 只做 13-gram 去重为什么查不出改写过的测试题，把 n 调小行不行
- level: 2
- tags: [evaluation, training]

**一句话答案**：n-gram 只认字面，换说法或翻译后片段几乎全不重合；把 n 调小，无关文本也开始命中，误报和真泄漏分不开。要用嵌入检索找候选，再让强模型判断是不是同一道题。

**要点**：
- GPT-3 论文用 13-gram 重叠定义污染，GPT-4 报告用 50 字符重叠（Yang 等 2311.04850 转述）。
- Yang 等的 LLM decontaminator：先用嵌入相似度取 top-k 训练样本，再让强模型逐对判断。
- n-gram 检查要拿到训练语料；拿不到时只能做行为检测：新题对照、按时间切分、保留集、记忆诊断。

**追问链**：
1. 嵌入相似度单独用有什么问题？→ 要定阈值：设高了漏报，设低了误报；同主题的不同题也会很相似。
2. 实践里怎么组合？→ n-gram 便宜，先粗筛原样泄漏；嵌入检索加模型判定复核改写；再用新题对照看行为。
3. 新题上掉分就能断定污染吗？→ 不能；Recht 等重建 ImageNet 测试集的掉分主要来自新题略难，要先排除难度差异。

**易错点**：
- 去重后分数没变就说“没有污染”。改写过的题根本没被去掉。
