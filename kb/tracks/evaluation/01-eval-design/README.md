# 评测设计：任务分层、数据集构造与指标

> 层级：垂类 · evaluation · 预计 180 分钟 · 题目：[questions.md](questions.md)
> 前置：[core/09 评测与 Benchmark](../../../core/09-evaluation/README.md)、[core/02 Agent 架构与设计模式](../../../core/02-agent-architecture/README.md)

## 1 这一章解决什么问题

“你怎么评测你的 Agent”是评测岗和 Agent 岗的高频题。只答“建个测试集，看准确率”，第二层追问就会卡住：成功怎么定义？题从哪来？跑一次够不够？差 3 个点算不算提升？

常见的做法是攒一两百道题，每个版本跑一遍，比总分。它有三个缺陷：

1. 成功没定义清楚，分数变了说不出是哪里变了；
2. 总分把简单题和高风险题混在一起，高风险题退化了也看不出来；
3. 不算误差。一两百题上差 3 个点，多半是噪声。

这一章把评测当成一次实验来设计：先定义成功和失败代价，再决定题怎么分层、怎么构造、看哪些指标，最后算清误差有多大、需要多少题才能下结论。

```mermaid
flowchart LR
  A[成功定义与失败代价] --> B[分层：难度/场景/风险]
  B --> C[构造与标注]
  C --> D[指标：主指标 + 护栏]
  D --> E[统计：区间、配对、样本量]
  E -->|题不够或波动太大| C
```

学完你应该能：

- 给一个 Agent 写出可判定的成功标准，并按失败代价排序；
- 按难度、场景、风险给评测集分层，用线上占比加权还原整体通过率；
- 说出一道好题的标准，知道评分器的误判怎么压缩版本差距；
- 设计主指标和护栏指标，知道 pass^k、成本、延迟、安全各回答什么问题；
- 推出正态近似和 Wilson 区间，知道什么时候前者会坏；
- 写出配对标准误和簇标准误，说清它们各修正了什么；
- 从检验的定义推出样本量公式，估算“检出 3 个点要多少题”。

**本章符号**（后文沿用）：

| 符号 | 含义 |
|---|---|
| n | 题数（独立抽出的题目个数） |
| s_i | 第 i 题的得分；0/1 结果时 s_i ∈ {0, 1}；每题跑多次时是这道题的平均分 |
| x_i | 第 i 题的“真实”期望得分（条件均值），例如这题的真实通过率 |
| ε_i | 采样带来的随机部分，s_i = x_i + ε_i，σ_i² = Var(ε_i) |
| p, p̂ | 整体真实通过率与观测通过率，p̂ = c / n，c 为通过题数 |
| K | 每题重复跑的次数（试次数） |
| d_i | 配对比较里第 i 题的得分差 s_{A,i} − s_{B,i} |
| δ | 想检出的版本差距（最小可检出差距，MDE） |
| z_q | 标准正态的上 q 分位数，z_{0.025} ≈ 1.96，z_{0.20} ≈ 0.84 |
| α, 1 − β | 显著性水平（假阳性率）与检出力（真有差距时检出的概率） |

## 2 先定义成功：任务目标与失败代价

**问题**：成功的定义含糊，后面所有分数都没法解释。“回答得好”不是标准，“客服 Agent 按退款规则完成退款”才是。

**做法**：对每类任务写三样东西。

| 要写清的 | 例子（客服 Agent 处理退款） |
|---|---|
| 终态 | 订单状态变为“已退款”，金额等于规则算出的值 |
| 必须告诉用户的信息 | 退款金额、到账时间 |
| 不能做的事 | 未经用户确认就执行写操作；退超过规则上限的金额 |

终态要落到评分器能检查的东西上：数据库字段、文件内容、API 调用参数。终态和轨迹的区别见 [core/09 的终态与轨迹一节](../../../core/09-evaluation/README.md)。

再按失败代价给错误排序。不同错误的代价差几个数量级：

| 错误类型 | 例子 | 代价 | 评测上的处理 |
|---|---|---|---|
| 不可逆的错误写操作 | 退错金额、删错数据 | 高 | 单列安全指标，一票否决 |
| 错误事实 | 编造政策条款 | 中到高 | 确定性校验优先 |
| 没完成但没造成伤害 | 转人工、要求补充信息 | 低 | 计入成功率，但和“做错”分开统计 |
| 多花成本 | 多调了几次只读工具 | 低 | 计入成本指标 |

### 2.1 为什么高代价错误要一票否决，而不是加权进总分

设一次运行有三种结局：成功、安全失败（拒答、转人工）、有害失败。把代价写成期望：

```text
E[代价] = P(安全失败) × c_safe + P(有害失败) × c_harm        c_harm ≫ c_safe
```

c_harm 比 c_safe 大几个数量级时，E[代价] 几乎只由 P(有害失败) 决定。这时候把它加权进一个总分，总分的变化会被它主导，其余指标看不出来；权重取小了，又会被成功率的波动淹没。两头都不好，所以把它拿出来单独设门禁：P(有害失败) 的上界低于阈值才放行（上界怎么算见第 6.3 节）。

一个常见错误是把“拒答”和“答错”合并成“失败”。这样一个什么都拒答的 Agent，安全指标很好看，成功率却没人能解释。三种结局要分开报：

| 结局 | 报什么 | 谁关心 |
|---|---|---|
| 成功 | 成功率 | 产品效果 |
| 安全失败 | 拒答率、转人工率 | 体验与人力成本 |
| 有害失败 | 违规写操作率、越权次数 | 一票否决 |

**代价**：成功标准写得越细，题目维护成本越高。实用做法是终态和禁止项写死，表达质量这类软标准留给评委（见 [02 LLM-as-Judge](../02-llm-as-judge/README.md)）。

## 3 评测集分层：难度、场景、风险

**问题**：总分掩盖退化。总分不变时，可能是简单题涨了，高风险题掉了。

**做法**：每道题打三类标签，报分时分层报。

| 维度 | 典型取值 | 为什么要分 |
|---|---|---|
| 难度 | 单步 / 多步 / 需要澄清 / 长程 | 区分“能力提升”和“简单题变多” |
| 场景 | 查询、办理、投诉、闲聊、越界请求 | 对应不同的产品入口和负责人 |
| 风险 | 只读 / 可逆写 / 不可逆写 / 涉及隐私 | 高风险层要求接近 100%，单独设门禁 |

还要分两种用途的题集。Anthropic 的评测工程文章把它们叫能力评测和回归评测：能力评测一开始通过率就该低，给团队一个往上爬的目标；回归评测应该接近 100% 通过，用来发现退化。能力题做到饱和，可以转进回归集。题集到 100% 就只能抓退化，看不出新的提升。

**代价**：层分得越细，每层题越少，每层的置信区间越宽。一般主指标只报 3 到 5 层，细标签用于定位问题。

### 3.1 评测集的比例不是线上的比例：按层加权

高风险请求在线上很少。按线上比例抽题，不可逆写层可能只有几道题，什么都测不出。所以评测集通常对高风险层**过采样**。代价是评测集的直接平均不再代表线上。

设第 h 层在线上的占比为 w_h（Σ w_h = 1），评测集里有 n_h 道题，观测通过率 p̂_h。线上整体通过率的估计和它的标准误是：

```text
p̂_strat = Σ_h w_h · p̂_h

Var(p̂_strat) = Σ_h w_h² · Var(p̂_h) = Σ_h w_h² · p_h(1 − p_h) / n_h
```

推导只用了两条：各层独立抽题，所以方差可以相加；常数 w_h 提出来要平方。直接平均 Σ n_h p̂_h / Σ n_h 等于用 n_h / n 当权重，过采样的层被放大了。

一组数（第 7.6 节代码验证）：三层线上占比 70% / 25% / 5%，真实通过率 90% / 80% / 60%，评测集各抽 200 / 150 / 150 题。线上整体是 0.86，评测集直接平均却是 0.78，差了 8 个点。

分层还有一个用处：**总分掩盖退化**。同一组数里，新版只读层涨 3 个点、可逆写层不变、不可逆写层掉 15 个点。加权总分变化 0.70×3 − 0.05×15 = +1.35 个点，看起来还进步了，高风险层的退化完全被盖住。

### 3.2 每层要多少题

每层是一个独立的通过率，误差按第 6 节算。150 题、通过率 60% 的层，95% 区间半宽约 ±8 个点。高风险层的门禁通常是“零失败”，题数由三法则定：想说明失败率低于 1%，要约 300 道题全部通过（第 6.3 节）。所以高风险层的题数往往由门禁决定，不由线上占比决定。

## 4 数据集构造与标注

**来源对比**：

| 来源 | 优点 | 风险 |
|---|---|---|
| 线上真实请求采样 | 分布真实 | 简单题占多数，高风险题极少；要脱敏 |
| 历史失败与工单 | 每道题都对应真实问题 | 只加不删会偏向旧问题 |
| 人工构造边界题 | 覆盖罕见高风险情况 | 和真实分布有偏差 |
| 模型合成 | 量大、便宜 | 题目风格单一，可能和被测模型同源 |

**从多少题开始**：Anthropic 的文章建议先从真实失败里取 20-50 个简单任务。早期改动效果大，小样本就看得出来；等题攒够再开始，评测只会越来越难建。这和第 6 节的样本量公式一致：n 和 1/δ² 成正比，差距 δ 是 20 个点时几十题就够（V 取 0.3，n ≈ 7.85 × 0.3 / 0.04 ≈ 59），差距缩到 3 个点就要上千题。

**一道好题的标准**（同一篇文章）：

1. 两位领域专家各自独立判，会得出相同的通过或不通过结论。
2. 评分器检查的每一项，题面都写清楚了。题面没说精度，评分器却按精度判，就是坏题。
3. 有一份参考解，能通过所有评分器。它证明题可解，也证明评分器配对了。
4. 正反两面都有。例如既测“该查知识库时查了”，也测“闲聊时没有乱查”。只测一面，系统会被调成什么都做。

文章还提到，一道题跑 100 次通过率都是 0，通常说明题坏了，而不是 Agent 不行。

**标注流程**：

- 写标注指南，附正反例。
- 每道题至少两人独立标，算一致率和 Cohen's kappa（算法见 [02](../02-llm-as-judge/README.md)）。不一致的题回到指南讨论，指南改了再标。
- 分歧大的题，多半是题面有歧义，改题比投票更有效。SWE-bench Verified 的做法可以参考：每题三位标注者，取三人中最严重的判定，题面描述不清或测试会拒绝正确解的题直接剔除（细节见 [04 Benchmark](../04-benchmarks/README.md)）。

**代价**：严格过滤会删掉很多题。题少了，统计分辨率就下降（见第 6 节）。

### 4.1 评分器有误判时，分数差距会被压缩

标注不一致和评分器出错，本质是同一件事：观测到的“通过”不等于真的通过。设评分器把真成功判成功的概率是 Se（灵敏度），把真失败判失败的概率是 Sp（特异度）。真实通过率为 p 时，观测通过率 q 是：

```text
q = Se · p + (1 − Sp) · (1 − p)
  = (1 − Sp) + (Se + Sp − 1) · p
```

q 是 p 的线性函数，斜率是 Se + Sp − 1。由此推出三件事：

1. **差距被压缩。** 两个版本的观测差 q_A − q_B = (Se + Sp − 1)(p_A − p_B)。Se = 0.95、Sp = 0.90 时斜率 0.85，真实 5 个点只剩 4.25 个点。
2. **可以反解。** 已知 Se、Sp（在一批人工复核过的题上估出来），p̂ = (q̂ + Sp − 1) / (Se + Sp − 1)。这在流行病学里叫 Rogan-Gladen 估计。
3. **校正有代价。** 反解把标准误放大 1 / (Se + Sp − 1) 倍。要保持同样的检出力，题数要乘 1 / (Se + Sp − 1)²，上面的例子是 1.38 倍。

这是推导，第 7.5 节用模拟验证。它假设评分器的错误和题目、版本无关。真实的评委可能对某个版本的风格系统性偏好（如冗长偏差，见 [02](../02-llm-as-judge/README.md)），那时偏差不是一个常数斜率，反解也救不回来，只能换评分方式。

工程上的结论：评分器精度是评测分辨率的一部分。与其把题数翻倍，不如先把评分器的 Se、Sp 提上去。能用代码判的不用模型判，就是这个原因。

## 5 指标体系

一个指标只回答一个问题。至少要有下面几类：

| 类别 | 指标 | 回答的问题 |
|---|---|---|
| 效果 | 成功率（pass^1 = pass@1） | 平均做对多少 |
| 可靠性 | pass^k | 同一题连续 k 次都做对的概率 |
| 搜索上限 | pass@k | k 次里至少一次做对的概率 |
| 成本 | 每任务 token、工具调用次数、金额 | 做对一题花多少 |
| 延迟 | 端到端 P50 / P95、首 token 时间 | 用户等多久 |
| 安全 | 违规写操作率、越权调用数、隐私泄露数 | 有没有做不该做的事 |

Anthropic 的文章也把延迟、token 用量、每任务成本和错误率列为可以在固定题库上持续跟踪的量。

### 5.1 pass^k 和 pass@k

定义和无偏估计在 [core/09 的 pass@k 与 pass^k 一节](../../../core/09-evaluation/README.md) 主讲，这里只列结论。τ-bench 提出 pass^k：同一任务 k 个独立试次全部成功的概率，再对所有任务平均。每题跑 n 次、成功 c 次（n ≥ k）：

```text
pass^k = E_task[ C(c, k) / C(n, k) ]
pass@k = 1 − E_task[ C(n−c, k) / C(n, k) ]
```

pass@k 的这个无偏估计来自 Codex 论文。k = 1 时两者相等，都是平均成功率。k 越大，pass@k 越高，pass^k 越低。Anthropic 的文章给了一个直观的数：单次成功率 75%，连续 3 次都成功约为 0.75³ ≈ 42%。

**为什么不能先算 p̂ 再取幂**：例如某题 n = 8、c = 6、k = 4。

| 算法 | pass^4 |
|---|---|
| 组合估计 C(6,4)/C(8,4) | 15/70 ≈ 0.21 |
| 先算 p̂ = 0.75，再取 0.75⁴ | ≈ 0.32 |

p^k 是凸函数，p̂^k 的期望大于 p^k，所以直接取幂会把稳定性估高。报 pass^k 要写明 n 和估计方法。

**pass^k 对分层的意义**：pass^k 是逐题 x_i^k 的平均，不是整体 p 的 k 次方。两个系统平均成功率都是 75%，一个每题都是 75%，pass^3 = 0.42；另一个 75% 的题必过、25% 的题必挂，pass^3 = 0.75。后者的失败集中在固定的题上，可以靠定位那批题修好；前者是到处随机出错，更难修。所以 pass^k 和 pass^1 的差距大小本身就是诊断信息。

**怎么选**：可以多次采样、再用测试挑一个结果的任务（例如代码生成），看 pass@k；面向用户、每次只给一个结果的任务（例如客服），看 pass^k。

### 5.2 多个指标怎么权衡

指标多了，几乎每次改动都会有“某个指标变好”。处理办法是事先分角色：

| 角色 | 个数 | 判定规则 | 例子 |
|---|---|---|---|
| 主指标 | 1 个 | 配对比较显著变好才算提升 | 成功率 |
| 护栏指标 | 几个 | 只要求不显著变差（非劣） | pass^k、P95 延迟、每成功任务成本 |
| 硬门槛 | 少数 | 超过阈值直接否决，不和别的指标交换 | 有害写操作数、越权次数 |

三类规则对应三种不同的统计问题。主指标是“差距的区间是否全在 0 以上”；护栏是非劣检验，“差距的区间下界是否高于 −m”，m 是事先约定的容忍度；硬门槛看的是第 6.3 节的上界。

成本要按**每个成功任务**算，不按每次尝试算。每次尝试成本 c、成功率 s 时，每成功一次平均花 c / s。新版成功率从 80% 涨到 84%，每次尝试成本从 0.10 涨到 0.15，单位成功成本涨了 43%（第 7.6 节代码）。这类改动值不值得做，是产品决策，评测的职责是把这笔账摆出来。

延迟要报分位数。P95 只由最慢的 5% 决定，同样的题数下，它的估计比均值抖得多。比较 P95 时，要么多跑几轮，要么用 bootstrap 按题重抽样给区间。

两个版本在成本和成功率上互有胜负时，画出“成功率 × 单位成功成本”的散点，只保留不被别人同时在两维上都超过的点（帕累托前沿），再按预算选。不要把两个量揉成一个加权分，权重怎么定都说不清。

线上护栏和门禁见 [05 线上评测与回归门禁](../05-online-regression/README.md)。

## 6 统计显著性与样本量

**问题**：Agent 评测题少、每题有随机性。一两百题上差 3 个点，很可能是噪声。

这一节的统计框架来自 Evan Miller 的《Adding Error Bars to Evals》（arXiv 2411.00640）：把评测集里的题看成从一个看不见的“题目总体”里随机抽出来的样本。我们关心的是 Agent 在这个总体上的真实通过率，而不是在这几百道具体题上的得分。误差有两个来源：

```text
s_i = x_i + ε_i
Var(s) = Var(x) + E[σ_i²]          （全方差公式）
          抽到哪些题   每题内部的随机性
```

Var(x) 是题目难度的差异，由题目总体决定，改不了，只能靠加题摊薄。E[σ_i²] 是同一道题每次运行结果不同带来的方差，可以靠每题多跑几次压下去（第 6.5 节）。

### 6.1 单个通过率的置信区间：正态近似

成功是 0/1 时，c 服从二项分布 Binomial(n, p)，p̂ = c / n：

```text
E[p̂] = p        Var(p̂) = p(1 − p) / n
```

n 大时由中心极限定理，p̂ 近似服从 N(p, p(1 − p)/n)。用 p̂ 代替未知的 p，得到正态近似区间（也叫 Wald 区间，Miller 文中式 2、3）：

```text
SE = sqrt( p̂ (1 − p̂) / n )
95% 区间 ≈ p̂ ± 1.96 × SE
```

p(1 − p) 在 p = 0.5 时最大，等于 1/4。所以最坏半宽是 1.96 × 0.5 / √n ≈ 1/√n。好记的结论：

| 题数 n | 95% 区间半宽（最坏） |
|---|---|
| 100 | 约 ±10 个点 |
| 400 | 约 ±5 个点 |
| 1000 | 约 ±3 个点 |

题的得分不是 0/1（例如 F1、每题多跑几次的平均分）时，用样本方差代替 p̂(1 − p̂)：SE = sqrt(Σ(s_i − s̄)² / (n − 1) / n)（Miller 式 1）。这时套 0/1 的公式会偏宽。

### 6.2 Wilson 区间：通过率接近 0 或 1 时

正态近似在 p̂ 接近 0 或 1、题又少时会坏。坏在两处：

1. **区间会越界。** 30 题过 29 题，正态区间约 [0.90, 1.03]，上界超过 100%。
2. **覆盖率不到名义值。** 用 p̂ 代替 p 估方差，p̂ 恰好落在边上时方差被低估。p̂ = 1 时 SE = 0，区间缩成一个点。第 7.1 节的模拟里，30 题、真实通过率 98% 时，“95%”正态区间实际只盖住真值约 45% 的次数。

Wilson（1927）的做法是不在方差里用 p̂，而是保留未知的 p，反过来问：哪些 p 不会被检验拒绝？

```text
| p̂ − p | ≤ z · sqrt( p(1 − p) / n )
```

两边平方，整理成关于 p 的二次不等式：

```text
(p̂ − p)² ≤ (z²/n) · p(1 − p)
(1 + z²/n) p² − (2p̂ + z²/n) p + p̂² ≤ 0
```

两个根就是区间端点：

```text
         p̂ + z²/(2n)  ±  z · sqrt( p̂(1 − p̂)/n + z²/(4n²) )
p  =  ──────────────────────────────────────────────────────
                          1 + z²/n
```

几个性质可以直接看出来：

- 中心是 (p̂ + z²/(2n)) / (1 + z²/n)，向 1/2 收缩。n 越小收缩越多。
- p̂ = 1 时下界小于 1，上界恰好是 1，区间宽度不为 0。
- n 很大时 z²/n → 0，退化成正态近似。

30 题过 29 题，Wilson 区间约 [0.83, 0.99]。Brown、Cai、DasGupta（2001）系统比较过二项比例的几种区间。摘要的结论是：正态近似的覆盖率“持续地差”，和通常的经验不符；n 小时推荐 Wilson 区间或等尾 Jeffreys 区间，n 较大时推荐 Agresti-Coull 区间。回归集通过率通常在 95% 以上，正好落在正态近似最差的区域，报区间时应默认用 Wilson。

### 6.3 一题都没失败：三法则

回归集、安全门禁经常是 n 题全过。p̂ 的失败率是 0，正态区间宽度为 0，没有意义。要问的是：真实失败率 f 最大可能是多少，还能让“n 题全过”不算太意外？

n 题全过的概率是 (1 − f)^n。把“不太意外”定为概率至少 5%，解出 f 的上界：

```text
(1 − f)^n = 0.05
n · ln(1 − f) = ln 0.05 ≈ −3.0
f ≈ 3 / n                   （f 很小时 ln(1 − f) ≈ −f）
```

这就是三法则（Hanley 与 Lippman-Hand，1983）：n 题全过时，失败率的 95% 单侧上界约为 3/n。

| 全过的题数 | 失败率上界（95%） |
|---|---|
| 30 | 约 10% |
| 100 | 约 3% |
| 300 | 约 1% |
| 3000 | 约 0.1% |

反过来用：想对一个高风险层说“失败率低于 1%”，至少要 300 道题全过。30 题全过，只能说失败率大概不超过 10%。

### 6.4 比较两个版本：配对比较

两个版本 A、B 跑同一批题时，有两种算差值标准误的方法（Miller 第 4 节）。

**非配对**：把两个分数当独立的，

```text
SE_unpaired = sqrt( SE_A² + SE_B² )
```

**配对**：逐题求差 d_i = s_{A,i} − s_{B,i}，再把 d_i 当一组样本算标准误（Miller 式 7）：

```text
SE_paired = sqrt( Σ(d_i − d̄)² / (n − 1) / n )
```

两者的差别从方差展开就能看到：

```text
Var(d̄) = [ Var(s_A) + Var(s_B) − 2 Cov(s_A, s_B) ] / n
```

非配对等于假设协方差为 0。两个版本对“哪题难、哪题容易”的看法一致时，s_A 和 s_B 正相关，配对把这部分扣掉了。Miller 进一步指出，两个版本各自的随机部分 ε 互不相关，所以扣掉的只是难度那一项：Var_paired = Var_unpaired − 2 Cov(x_A, x_B) / n。他的例子：两个模型的连续分数都在 [0, 1] 上均匀分布、相关系数 0.5，差值方差从 1/6 降到 1/9，减少三分之一。

只有两个版本各自的标准误和逐题相关系数 r 时，也能换算（Miller 给出的关系式）：

```text
SE_paired = sqrt( SE_A² + SE_B² − 2 · SE_A · SE_B · r )
```

**0/1 结果时只有“一对一错”的题有信息。** 把 n 道题按两个版本的对错分成四格：都对、只有 A 对（b 题）、只有 B 对（c 题）、都错。d_i 只取 −1、0、1：

```text
d̄ = (b − c) / n
Var(d) ≈ (b + c)/n − d̄²
```

都对和都错的题 d_i = 0，对差值和方差都没有贡献。在原假设“两个版本一样好”下，b + c 道不一致的题里 A 赢的题数服从 Binomial(b + c, 1/2)，据此可以做精确检验（McNemar 检验的精确版）。例如 11 道一对一错的题里新版赢 7 题、旧版赢 4 题，双侧 p ≈ 0.55，分辨不出。如果是 15 比 1，p ≈ 0.0005。

Miller 的建议是：只要两个版本在同一批题上跑，就用配对标准误，并报出逐题相关系数。这几乎没有代价。题目难度不相关时，两种算法结果差不多（第 7.2 节验证），配对不会吃亏。

### 6.5 重复试次与簇：统计单位是什么

**每题跑 K 次。** 正确的统计单位是题，不是运行。先算每题的平均分 s_i = (1/K) Σ_k s_{i,k}，再按题算标准误。这时每题内部的方差被除以 K：

```text
Var(µ̂) = [ Var(x) + E[σ_i²] / K ] / n
```

把 K × n 次运行当成独立样本，相当于把分母写成 n·K，而同一题的多次运行共享同一个 x_i，并不独立，方差会被低估。Miller 第 3.1 节举例：题目真实通过率 x ~ U[0, 1] 时 Var(x) = 1/12、E[σ²] = 1/6，于是

```text
Var(µ̂ | K) = Var(µ̂ | K = 1) × (1 + 2/K) / 3
```

K 从 1 加到 2 方差降 1/3，加到 4 降 1/2，上限是降 2/3。E[σ²]/K 远小于 Var(x) 之后，再加 K 就没用了，只能加题。

**同源的题。** 同一份文档派生的多道问答、同一个任务翻译成多种语言、同一个代码仓库里的多个任务，彼此相关。Miller 式 4 给出簇标准误：

```text
SE_clustered² = SE_CLT² + (1/n²) Σ_c Σ_i Σ_{j≠i} (s_{i,c} − s̄)(s_{j,c} − s̄)
```

第二项只累加同一个簇 c 内不同题的交叉乘积。簇内题完全不相关时，它的期望是 0，退化成普通标准误；簇内题完全相关时，一个簇只相当于一道题。

用一个简化模型看放大倍数（推导）：每簇 m 道题，题间相关系数为 ρ，单题方差为 σ²。

```text
Var(簇内总分) = m σ² + m(m − 1) ρ σ²
Var(s̄) = (σ² / n) × [ 1 + (m − 1) ρ ]
```

1 + (m − 1)ρ 叫设计效应。每份文档出 8 道题、簇内相关 0.2 时设计效应约 2.4，普通标准误要乘 √2.4 ≈ 1.55 才对，相当于 400 道题只顶 167 道独立题。论文报告，在阅读理解类评测 DROP 上，簇标准误约是普通标准误的 3 倍。

两种修正可以叠加。比较两个版本、题又成簇时，对逐题差值 d_i 用簇标准误（Miller 式 8）。

### 6.6 样本量估算：从检验的定义推出来

想在比较两个版本时检出 δ 的差距。设差值的单题方差为 V，d̄ 近似服从 N(真实差距, V/n)。

1. 原假设（真实差距 0）下，双侧检验在 d̄ > z_{α/2} · sqrt(V/n) 时拒绝。
2. 备择假设（真实差距 δ）下，检出的概率是 P(d̄ > z_{α/2} · sqrt(V/n))。要它等于 1 − β：

```text
( δ − z_{α/2} · sqrt(V/n) ) / sqrt(V/n) = z_β
δ = (z_{α/2} + z_β) · sqrt(V / n)
n = (z_{α/2} + z_β)² · V / δ²
```

α = 0.05、检出力 80% 时 (1.96 + 0.84)² ≈ 7.85。这就是 Miller 式 9，他把 V 写成三部分：

```text
V = ω² + σ_A² / K_A + σ_B² / K_B
ω² = Var(x_A) + Var(x_B) − 2 Cov(x_A, x_B)       （配对后难度差异的方差）
```

几个例子，都可以手算：

| 情况 | V | δ | 题数 |
|---|---|---|---|
| Miller 的例子：ω² = 1/9、每题无随机性 | 0.111 | 3 个点 | 969 |
| 不配对、两个版本通过率都约 80% | 2 × 0.8 × 0.2 = 0.32 | 5 个点 | 约 1005 |
| 同上 | 0.32 | 3 个点 | 约 2791 |
| 配对、0/1 结果、15% 的题一对一错 | 0.15 − 0.03² ≈ 0.149 | 3 个点 | 约 1301 |
| 配对、0/1 结果、10% 的题一对一错 | ≈ 0.099 | 3 个点 | 约 865 |

0/1 配对的 V 用的是上一节的 (b + c)/n − d̄²。可以看出：**配对后要多少题，几乎只取决于一对一错的题占多少**。两个版本越像，不一致的题越少，同样的差距越容易检出。

Miller 据 969 这个数建议新评测至少 1000 题。他也给出反过来的用法（式 10）：题数固定时算最小可检出差距。n = 198、ω² = 1/9、σ_A² = σ_B² = 1/6 时，每题从跑 1 次加到跑 10 次，最小可检出差距从 13.2% 降到 7.5%。

V 要从历史数据估：拿上一轮两个版本的逐题结果，算差值的方差。没有历史数据时，用不配对的 2p(1 − p) 做保守估计。

### 6.7 边跑边看和多指标：假阳性怎么变多

上面的检验都假设“事先定好题数和指标，只看一次”。两种常见做法会破坏这个假设：

- **边跑边看。** 每加 100 题就看一次，显著就停。两个版本其实一样时，看 10 次至少一次“显著”的概率在第 7.5 节的模拟里约 20%，远高于名义的 5%。要么事先定题数，要么用序贯检验那一类专门的方法。
- **多指标挑着报。** 10 个独立、实际都没差别的指标各做一次 α = 0.05 的检验，至少一个显著的概率是 1 − 0.95¹⁰ ≈ 40%。最简单的修正是 Bonferroni：每个检验用 α / 10。更实用的是第 5.2 节的做法：事先只定一个主指标做显著性检验，其他做非劣护栏。

**代价**：题数和单题重复次数都要花钱。现实做法是：

- 回归集题少，只用来抓大的退化，阈值按区间定；
- 关键决策前，在更大的题集上配对比较；
- 先降低每题的波动（固定工具结果、隔离环境），再加题。

Anthropic 的文章还提醒，每个试次要从干净环境开始。残留文件、缓存、资源耗尽这类共享状态会让失败相互关联，也可能抬高分数。

## 7 实现：用模拟验证上面的结论

每段代码单独运行，只用标准库和 numpy。模拟的思路都一样：先设定“真实”的题目总体，重复抽很多次评测集，看公式算出的标准误或区间和真实波动是否一致。

### 7.1 Wilson 区间与覆盖率

验证第 6.2 节：Wilson 区间的端点正好是得分检验统计量等于 z 的地方；30 题过 29 题时两种区间的数值；通过率接近 1 时正态近似的覆盖率远低于 95%，Wilson 接近名义值。

```python
import math
import numpy as np

Z = 1.959963984540054          # 标准正态的 97.5% 分位数

def wald(c, n, z=Z):
    p = c / n
    h = z * math.sqrt(p * (1 - p) / n)
    return p - h, p + h

def wilson(c, n, z=Z):
    p = c / n
    denom = 1 + z * z / n
    center = (p + z * z / (2 * n)) / denom
    half = z / denom * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return center - half, center + half

# 1) 正文的例子：30 题过 29 题
lo, hi = wald(29, 30)
assert round(lo, 2) == 0.90 and round(hi, 2) == 1.03       # 上界超过 1
lo, hi = wilson(29, 30)
assert round(lo, 2) == 0.83 and round(hi, 2) == 0.99

# 2) Wilson 区间就是“得分检验不拒绝”的 p 的集合：端点处检验统计量恰好等于 z
for c, n in [(29, 30), (3, 40), (50, 100)]:
    for b in wilson(c, n):
        zstat = abs(c / n - b) / math.sqrt(b * (1 - b) / n)
        assert abs(zstat - Z) < 1e-9

# 3) 覆盖率模拟：真实通过率 p，每次抽 n 道题，看区间有没有盖住 p
rng = np.random.default_rng(0)
def coverage(method, p, n, reps=20000):
    cs = rng.binomial(n, p, size=reps)
    hit = 0
    for c in cs:
        lo, hi = method(int(c), n)
        hit += lo <= p <= hi
    return hit / reps

res = {}
for n in (30, 100):
    for p in (0.5, 0.8, 0.9, 0.95, 0.98):
        res[(n, p)] = (coverage(wald, p, n), coverage(wilson, p, n))
        print(n, p, "Wald %.3f  Wilson %.3f" % res[(n, p)])

# 通过率居中时两者都接近 95%
assert abs(res[(100, 0.5)][0] - 0.95) < 0.015 and abs(res[(100, 0.5)][1] - 0.95) < 0.015
# 通过率接近 1、题又少时，Wald 的覆盖率远低于名义值
assert res[(30, 0.98)][0] < 0.60
assert res[(30, 0.95)][0] < 0.85
# Wilson 在所有格点上都不低于 0.90，平均接近 0.95
wil = [v[1] for v in res.values()]
assert min(wil) > 0.90 and abs(np.mean(wil) - 0.95) < 0.02
```

模拟输出的覆盖率（20000 次重复）大致是：

| n | 真实通过率 | 正态近似 | Wilson |
|---|---|---|---|
| 30 | 0.50 | 0.957 | 0.957 |
| 30 | 0.90 | 0.801 | 0.973 |
| 30 | 0.98 | 0.451 | 0.980 |
| 100 | 0.95 | 0.880 | 0.965 |
| 100 | 0.98 | 0.869 | 0.947 |

二项分布是离散的，覆盖率随 p 锯齿式跳动，Wilson 也会在 0.94 到 0.98 之间摆动。这是正常的；正态近似的问题是系统性地偏低。

### 7.2 配对与非配对标准误

验证第 6.4 节：两个版本共享题目难度时，非配对标准误明显高估差值的波动，配对标准误和真实波动一致；难度不相关时两者相同；Miller 的换算式成立；0/1 结果时差值方差只由一对一错的题决定；McNemar 精确检验的两个 p 值。

```python
import math
import numpy as np

rng = np.random.default_rng(1)
n, reps = 400, 4000

def one_eval(shared=True):
    """两个版本跑同一批 n 道题，返回逐题 0/1 结果 sA、sB，形状都是 (n,)"""
    d = rng.normal(0, 2.5, n)                 # 题目“容易程度”，两个版本共享
    dB = d if shared else rng.normal(0, 2.5, n)
    pA = 1 / (1 + np.exp(-(d + 1.2)))         # 版本 A 的逐题通过概率
    pB = 1 / (1 + np.exp(-(dB + 1.0)))        # 版本 B 略弱
    sA = (rng.random(n) < pA).astype(float)
    sB = (rng.random(n) < pB).astype(float)
    return sA, sB

def se_unpaired(sA, sB):
    return math.sqrt(sA.var(ddof=1) / n + sB.var(ddof=1) / n)

def se_paired(sA, sB):
    return (sA - sB).std(ddof=1) / math.sqrt(n)

for shared in (True, False):
    diffs, su, sp = [], [], []
    for _ in range(reps):
        sA, sB = one_eval(shared)
        diffs.append(sA.mean() - sB.mean())
        su.append(se_unpaired(sA, sB))
        sp.append(se_paired(sA, sB))
    true_sd = np.std(diffs)                   # 差值在重复实验间的真实波动
    print("shared" if shared else "indep",
          "true %.4f  unpaired %.4f  paired %.4f" % (true_sd, np.mean(su), np.mean(sp)))
    # 配对标准误和真实波动一致，误差在 5% 以内
    assert abs(np.mean(sp) / true_sd - 1) < 0.05
    if shared:
        # 两个版本对“哪题难”看法一致时，非配对标准误明显偏大
        assert np.mean(su) > 1.3 * true_sd
        assert np.mean(sp) < 0.8 * np.mean(su)
    else:
        # 难度不相关时，两种算法差不多，配对也不吃亏
        assert abs(np.mean(su) / np.mean(sp) - 1) < 0.05

# Miller 给的换算式：只知道两个版本各自的标准误和逐题相关系数，也能算配对标准误
sA, sB = one_eval()
seA, seB = sA.std(ddof=1) / math.sqrt(n), sB.std(ddof=1) / math.sqrt(n)
r = np.corrcoef(sA, sB)[0, 1]
assert abs(math.sqrt(seA**2 + seB**2 - 2 * seA * seB * r) - se_paired(sA, sB)) < 1e-12

# 0/1 结果时，差值 d_i 只取 -1、0、1，“都对”和“都错”的题对差值和方差都没有贡献
b = int(((sA == 1) & (sB == 0)).sum())       # 只有 A 对
c = int(((sA == 0) & (sB == 1)).sum())       # 只有 B 对
dbar = (b - c) / n
var_d = ((b + c) / n - dbar**2) * n / (n - 1)
assert abs(var_d - (sA - sB).var(ddof=1)) < 1e-12

# McNemar 精确检验：在 b + c 道不一致的题里，原假设下 b ~ Binomial(b + c, 1/2)
def mcnemar_exact(b, c):
    m, k = b + c, min(b, c)
    tail = sum(math.comb(m, i) for i in range(k + 1)) / 2**m
    return min(1.0, 2 * tail)

assert round(mcnemar_exact(7, 4), 2) == 0.55
assert round(mcnemar_exact(15, 1), 4) == 0.0005
```

这组设定下逐题相关系数约 0.43，非配对标准误约 0.034，真实波动和配对标准误都约 0.025。用非配对的标准误，区间宽了 37%，相当于白白扔掉近一半的题。

### 7.3 簇标准误与重复试次

验证第 6.5 节：同源题时普通标准误低估约三分之一，Miller 式 4 修正回来；设计效应 1 + (m − 1)ρ 和模拟的方差放大倍数一致；每题跑 K 次时把所有运行混在一起算会偏小，按题算才对，且符合 Miller 的 (1 + 2/K)/3。

```python
import math
import numpy as np

rng = np.random.default_rng(2)

def clustered_se(s, cl):
    """Miller 式 4：SE² = SE_CLT² + (1/n²) Σ_c Σ_i Σ_{j≠i} (s_i − s̄)(s_j − s̄)"""
    n, u = len(s), s - s.mean()
    se2 = s.var(ddof=1) / n
    cross = 0.0
    for c in np.unique(cl):
        uc = u[cl == c]
        cross += uc.sum() ** 2 - (uc ** 2).sum()      # 去掉 i = j 的项
    return math.sqrt(se2 + cross / n**2)

# 一份文档派生 m 道题：同一文档的题共享一个“文档难度”
C, m, reps = 50, 8, 3000                              # 50 份文档，每份 8 题，共 400 题
cl = np.repeat(np.arange(C), m)
means, naive, clus = [], [], []
for _ in range(reps):
    doc = rng.normal(0, 1.2, C)[cl]                   # 文档级效应，形状 (400,)
    q = rng.normal(0, 0.5, C * m)                     # 题目级效应
    p = 1 / (1 + np.exp(-(0.8 + doc + q)))
    s = (rng.random(C * m) < p).astype(float)
    means.append(s.mean())
    naive.append(s.std(ddof=1) / math.sqrt(len(s)))
    clus.append(clustered_se(s, cl))
true_sd = np.std(means)
ratio = np.mean(naive) / true_sd
print("true %.4f naive %.4f clustered %.4f" % (true_sd, np.mean(naive), np.mean(clus)))
assert ratio < 0.7                                    # 普通标准误低估了约三分之一
assert abs(np.mean(clus) / true_sd - 1) < 0.08        # 簇标准误修正回来

# 设计效应：簇内相关 ρ、每簇 m 题时，方差放大约 1 + (m − 1)ρ（推导见正文）
s_all = []
for _ in range(400):
    doc = rng.normal(0, 1.2, C)[cl]
    p = 1 / (1 + np.exp(-(0.8 + doc + rng.normal(0, 0.5, C * m))))
    s_all.append((rng.random(C * m) < p).astype(float).reshape(C, m))
S = np.array(s_all)                                   # 形状 (400, C, m)
v = S.var()
pair = np.mean([(S[:, :, i] - S.mean()) * (S[:, :, j] - S.mean())
                for i in range(m) for j in range(m) if i != j])
rho = pair / v
deff = 1 + (m - 1) * rho
assert abs(deff - (true_sd / np.mean(naive)) ** 2) / deff < 0.15

# 每题跑 K 次：把 K·n 次运行当独立样本，标准误同样偏小
n, K = 200, 5
pooled, by_q, mu = [], [], []
for _ in range(3000):
    x = rng.uniform(0, 1, n)                          # 逐题真实通过率 x_i ~ U[0,1]
    runs = (rng.random((n, K)) < x[:, None]).astype(float)   # 形状 (n, K)
    mu.append(runs.mean())
    pooled.append(runs.std(ddof=1) / math.sqrt(n * K))
    by_q.append(runs.mean(axis=1).std(ddof=1) / math.sqrt(n))
true_sd = np.std(mu)
assert abs(np.mean(by_q) / true_sd - 1) < 0.05        # 先求逐题均值再算：对
assert np.mean(pooled) < 0.75 * true_sd               # 混在一起算：偏小
# Miller 3.1 节：x ~ U[0,1] 时 Var(µ̂|K) = Var(µ̂|K=1) × (1 + 2/K)/3
var1 = (1 / 12 + 1 / 6) / n
assert abs(true_sd**2 / (var1 * (1 + 2 / K) / 3) - 1) < 0.08
```

### 7.4 样本量公式与模拟检出率

验证第 6.6 节和第 6.3 节：Miller 的 969 题和 13.2% → 7.5%；在“真实差 3 个点”的模拟里按公式算题数，实际检出率接近 80%；同样题数用非配对检验，检出率掉到约 55%；三法则的精确值和 3/n 的差距。

```python
import math
import numpy as np

Z_A, Z_B = 1.959963984540054, 0.8416212335729143      # z_{0.025}、z_{0.20}

def n_needed(var_d, delta):
    return math.ceil((Z_A + Z_B) ** 2 * var_d / delta**2)

# 1) Miller 的例子：ω² = 1/9、δ = 3 个点 → 969 题；不配对、通过率都约 80%、δ = 5 个点 → 约 1005 题
assert n_needed(1 / 9, 0.03) == 969
assert n_needed(2 * 0.8 * 0.2, 0.05) == 1005
# Miller 式 10：n = 198、ω² = 1/9、σ² = 1/6，K 从 1 加到 10，最小可检出差距从 13.2% 降到 7.5%
mde = lambda K: (Z_A + Z_B) * math.sqrt((1 / 9 + 2 * (1 / 6) / K) / 198)
assert round(mde(1), 3) == 0.133 and round(mde(10), 3) == 0.076

# 2) 模拟：两个版本真实差 3 个点，用公式算题数，再看实际检出率是不是 80%
rng = np.random.default_rng(3)
def draw(n, shift_a=0.25):
    d = rng.normal(1.0, 2.5, n)                      # 共享的题目难度
    pA = 1 / (1 + np.exp(-(d + shift_a)))
    pB = 1 / (1 + np.exp(-d))
    return (rng.random(n) < pA).astype(float), (rng.random(n) < pB).astype(float), pA - pB

# 先用一次大规模“历史数据”估差值方差和真实差距
sA, sB, gap = draw(200_000)
delta = gap.mean()
var_paired = (sA - sB).var()
var_unpaired = sA.var() + sB.var()
n_p, n_u = n_needed(var_paired, delta), n_needed(var_unpaired, delta)
print("delta %.4f  n_paired %d  n_unpaired %d" % (delta, n_p, n_u))
assert 0.025 < delta < 0.035
assert n_p < 0.8 * n_u                               # 配对省下 20% 以上的题

def power(n, paired, reps=3000):
    hit = 0
    for _ in range(reps):
        a, b, _ = draw(n)
        if paired:
            se = (a - b).std(ddof=1) / math.sqrt(n)
        else:
            se = math.sqrt(a.var(ddof=1) / n + b.var(ddof=1) / n)
        hit += (a.mean() - b.mean()) / se > Z_A          # 双侧检验里正确方向的那一侧
    return hit / reps

pw_p, pw_u = power(n_p, True), power(n_p, False)
print("paired power %.3f   unpaired power at same n %.3f" % (pw_p, pw_u))
assert abs(pw_p - 0.80) < 0.03                        # 公式给的题数，模拟检出率接近 80%
assert pw_u < 0.70                                    # 同样题数不配对，检出率明显下降

# 3) 三法则：n 题全过时，失败率 95% 单侧上界精确值 1 − 0.05^(1/n) ≈ 3/n
for n in (30, 100, 300):
    exact = 1 - 0.05 ** (1 / n)
    assert abs(exact - 3 / n) / exact < 0.06
assert round(-math.log(0.05), 2) == 3.00              # 3 来自 −ln 0.05 ≈ 3.0
# 失败率真等于 3/30 = 10% 时，30 题全过的概率约 4%，所以上界合理
assert abs((1 - 0.10) ** 30 - 0.042) < 0.001
```

这组模拟里配对需要约 2075 题，不配对需要约 3854 题。题数比第 6.6 节的表大，是因为这里约 25% 的题一对一错，V ≈ 0.245。题数由 V 决定，V 要用自己的历史数据估，不能照抄别人的 1000。

### 7.5 评分器误判、边跑边看、多指标

验证第 4.1 节和第 6.7 节：评分器误判把差距压缩成 (Se + Sp − 1) 倍，反解无偏但标准误放大；每 100 题看一次、一显著就停，假阳性从 5% 升到 15% 以上；10 个指标挑着报的假阳性约 40%。

```python
import math
import numpy as np

# 评分器有误差：真成功被判成功的概率 Se（灵敏度），真失败被判失败的概率 Sp（特异度）
Se, Sp = 0.95, 0.90
observed = lambda p: Se * p + (1 - Sp) * (1 - p)
corrected = lambda q: (q + Sp - 1) / (Se + Sp - 1)

pA, pB = 0.70, 0.65
qA, qB = observed(pA), observed(pB)
assert abs(qA - 0.695) < 1e-12 and abs(qB - 0.6525) < 1e-12
# 观测到的差距被压缩成真实差距的 (Se + Sp − 1) 倍：5 个点只剩 4.25 个点
assert abs((qA - qB) - (Se + Sp - 1) * (pA - pB)) < 1e-12
# 已知 Se、Sp 时可以反解回真实通过率
assert abs(corrected(qA) - pA) < 1e-12

# 模拟：评分器逐题独立出错，校正后的均值无偏
rng = np.random.default_rng(4)
n, reps = 1000, 2000
est = []
for _ in range(reps):
    truth = rng.random(n) < pA
    flip = np.where(truth, rng.random(n) > Se, rng.random(n) > Sp)
    judged = truth ^ flip
    est.append(corrected(judged.mean()))
assert abs(np.mean(est) - pA) < 0.002
# 代价：校正后的标准误被放大 1/(Se + Sp − 1) 倍，同样的检出力要多约 1/(Se+Sp−1)² 倍的题
sd_raw = math.sqrt(qA * (1 - qA) / n)
assert abs(np.std(est) / (sd_raw / (Se + Sp - 1)) - 1) < 0.05
assert round(1 / (Se + Sp - 1) ** 2, 2) == 1.38

# 多重比较：10 个相互独立、实际都没有差别的指标各做一次 α = 0.05 的检验
assert round(1 - 0.95**10, 2) == 0.40       # 至少一个“显著”的概率约 40%
assert 1 - (1 - 0.05 / 10) ** 10 <= 0.05     # Bonferroni：每个检验用 α/10

# 边跑边看：每加 100 题就做一次检验，一显著就停。两个版本其实没有差别
reps, N, Z = 4000, 1000, 1.959963984540054
d = rng.choice([-1.0, 0.0, 1.0], p=[0.075, 0.85, 0.075], size=(reps, N))   # 逐题差值
stopped = np.zeros(reps, bool)
for m in range(100, N + 1, 100):
    x = d[:, :m]
    z = x.mean(1) / (x.std(1, ddof=1) / math.sqrt(m))
    stopped |= np.abs(z) > Z
once = np.abs(d.mean(1) / (d.std(1, ddof=1) / math.sqrt(N))) > Z
assert abs(once.mean() - 0.05) < 0.012       # 只在最后看一次：假阳性约 5%
assert stopped.mean() > 0.15                 # 看 10 次：假阳性升到 15% 以上
```

### 7.6 分层加权与单位成功成本

验证第 3.1 节和第 5.2 节：过采样后直接平均偏离线上 8 个点，按线上占比加权无偏，分层标准误公式和模拟一致；高风险层掉 15 个点时加权总分几乎不动；成功率涨 4 个点、单次成本涨 50% 时，单位成功成本涨 43%。

```python
import math
import numpy as np

# 三层：线上流量占比 w、真实通过率 p、评测集里每层的题数 n（高风险层故意多抽）
w = np.array([0.70, 0.25, 0.05])       # 只读、可逆写、不可逆写
p = np.array([0.90, 0.80, 0.60])
n = np.array([200, 150, 150])
prod = float(w @ p)                    # 线上真实的整体通过率
naive_truth = float(n @ p / n.sum())   # 评测集直接平均的期望
assert round(prod, 2) == 0.86 and round(naive_truth, 2) == 0.78

rng = np.random.default_rng(5)
naive, strat = [], []
for _ in range(20000):
    ph = rng.binomial(n, p) / n                     # 每层观测通过率，形状 (3,)
    naive.append(float(n @ ph / n.sum()))
    strat.append(float(w @ ph))
assert abs(np.mean(naive) - 0.78) < 0.002           # 直接平均：偏离线上 8 个点
assert abs(np.mean(strat) - prod) < 0.002           # 按线上占比加权：无偏
se_formula = math.sqrt(float(np.sum(w**2 * p * (1 - p) / n)))
assert abs(np.std(strat) / se_formula - 1) < 0.03   # 分层标准误公式和模拟一致

# 每层自己的区间宽度：150 题、通过率 60% 时半宽约 ±8 个点
assert round(1.96 * math.sqrt(0.6 * 0.4 / 150), 3) == 0.078

# 总分掩盖退化：新版只读层 +3 个点，不可逆写层 −15 个点，加权总分几乎不动
p_new = np.array([0.93, 0.80, 0.45])
assert abs(float(w @ p_new) - prod) < 0.015
assert p_new[2] - p[2] < -0.1

# 成本：每次尝试成本 c、成功率 s 时，每个成功任务的平均成本是 c / s
cost_per_success = lambda c, s: c / s
a, b = cost_per_success(0.10, 0.80), cost_per_success(0.15, 0.84)
assert round(a, 3) == 0.125 and round(b / a - 1, 2) == 0.43   # 成功率 +4 个点，单位成功成本 +43%
```

## 8 数值例子：400 道题上新版高 3.5 个点

两个版本跑同一批 400 道题，逐题对错汇总成 2×2 表：

| | B 对 | B 错 |
|---|---|---|
| **A 对** | 210 | 38 |
| **A 错** | 24 | 128 |

A 的通过率 (210 + 38)/400 = 62.0%，B 是 (210 + 24)/400 = 58.5%，差 3.5 个点。按三种方法各走一遍：

1. **非配对**：SE = sqrt(0.62×0.38/400 + 0.585×0.415/400) ≈ 0.0346。95% 区间 3.5 ± 6.8 个点，即 [−3.3, +10.3]，含 0。
2. **配对**：一对一错的题 b + c = 62，差值方差 ≈ 62/400 − 0.035² ≈ 0.1538（再乘 n/(n−1) 修正）。SE ≈ sqrt(0.1542/400) ≈ 0.0196。95% 区间 3.5 ± 3.85 个点，即 [−0.3, +7.3]，还是含 0，但窄了 43%。
3. **McNemar 精确检验**：62 道不一致的题里 A 赢 38 题。原假设下 38 ~ Binomial(62, 1/2)，双侧 p ≈ 0.098，不显著。

逐题相关系数 r ≈ 0.68，说明两个版本对哪题难的看法高度一致，配对收益大。

结论：这批题分辨不出 3.5 个点。要稳定检出这么大的差距（α = 0.05、检出力 80%），按第 6.6 节，V ≈ 0.154，n ≈ 7.85 × 0.154 / 0.035² ≈ 986 题。如果不配对，V ≈ 0.478，要约 3070 题。

```python
import math

Z = 1.959963984540054
# 400 道题上的 2×2 表：两版都对 210，只有 A 对 38，只有 B 对 24，两版都错 128
both, a_only, b_only, neither = 210, 38, 24, 128
n = both + a_only + b_only + neither
pA, pB = (both + a_only) / n, (both + b_only) / n
diff = pA - pB
assert n == 400 and pA == 0.62 and pB == 0.585 and abs(diff - 0.035) < 1e-12

# 非配对：两个比例各算标准误再合成
se_u = math.sqrt(pA * (1 - pA) / n + pB * (1 - pB) / n)
lo_u, hi_u = diff - Z * se_u, diff + Z * se_u
assert round(se_u, 4) == 0.0346 and round(lo_u, 3) == -0.033 and round(hi_u, 3) == 0.103

# 配对：逐题差值 d_i ∈ {−1, 0, 1}，样本方差用 n − 1
var_d = ((a_only + b_only) / n - diff**2) * n / (n - 1)
se_p = math.sqrt(var_d / n)
lo_p, hi_p = diff - Z * se_p, diff + Z * se_p
assert round(se_p, 4) == 0.0196 and round(lo_p, 3) == -0.003 and round(hi_p, 3) == 0.073
assert se_p / se_u < 0.6                      # 同一份数据，配对标准误小 40% 以上

# 逐题相关系数，以及 Miller 的换算式
cov = both / n - pA * pB
r = cov / math.sqrt(pA * (1 - pA) * pB * (1 - pB))
assert round(r, 2) == 0.68
se_from_r = math.sqrt(pA*(1-pA)/n + pB*(1-pB)/n - 2*r*math.sqrt(pA*(1-pA)*pB*(1-pB))/n)
assert abs(se_from_r - math.sqrt((a_only + b_only) / n - diff**2) / math.sqrt(n)) < 1e-12

# McNemar 精确检验：62 道不一致的题里 A 赢 38 题
m, k = a_only + b_only, min(a_only, b_only)
p_exact = min(1.0, 2 * sum(math.comb(m, i) for i in range(k + 1)) / 2**m)
assert 0.09 < p_exact < 0.11                  # 不显著

# 要稳定检出 3.5 个点：不一致率 q = 62/400，V ≈ q − δ²，n ≈ (z_{α/2}+z_β)² V / δ²
q = m / n
n_need = math.ceil((1.959963984540054 + 0.8416212335729143) ** 2 * (q - diff**2) / diff**2)
assert 980 < n_need < 1000
n_unpaired = math.ceil((1.959963984540054 + 0.8416212335729143) ** 2 * (pA*(1-pA) + pB*(1-pB)) / diff**2)
assert 3060 < n_unpaired < 3075
print(round(se_u, 4), round(se_p, 4), round(r, 3), round(p_exact, 3), n_need)
```

## 9 工程细节与常见坑

**1. 把 K × n 次运行当独立样本**

- 现象：每题跑 5 次，报出的区间比只跑 1 次窄了一半多，版本之间“处处显著”，换一批题就复现不了。
- 原因：同一题的多次运行共享 x_i，分母该是 n 不是 n·K。第 7.3 节里混算的标准误不到真实值的 75%。
- 排查：看报告里的“样本数”是题数还是运行数；按题聚合后重算一次，区间明显变宽就是这个问题。
- 处理：先求逐题均值，再按题算标准误。

**2. 同源题按独立题算**

- 现象：从几十份文档生成了几百道问答，区间看着很窄，但换一批文档后分数跳得比区间宽得多。
- 原因：同一文档的题共享文档难度，设计效应 1 + (m − 1)ρ 大于 1。
- 排查：给每道题记录来源 ID（文档、仓库、模板），用 Miller 式 4 算簇标准误，和普通标准误比一比。比值明显大于 1 就要按簇报。
- 处理：报告同时写题数和簇数；抽子集估方差时整簇抽（Miller 附录 C 的建议）；与其每份文档出更多题，不如增加文档数。

**3. 两个版本没跑同一批题**

- 现象：A 在上周的题集上跑，B 在这周加了新题的题集上跑，差距忽大忽小。
- 原因：没法配对，非配对比较又混进了题集变化。
- 排查：对比两次运行的题目 ID 集合。
- 处理：比较只在两者共有的题上做配对；题集要版本化，报告写明题集版本。

**4. 回归集用正态区间**

- 现象：回归集 50 题过 49 题，报出区间 [0.94, 1.02]，或者 50 题全过报出“100% ± 0%”。
- 原因：通过率接近 1 时正态近似失效（第 6.2 节）。
- 排查：看区间是否越过 [0, 1] 或宽度为 0。
- 处理：用 Wilson 区间；全过时报 3/n 的失败率上界。

**5. 每题之间共享环境状态**

- 现象：同一版本连跑两轮，分数差了好几个点；或失败成片出现在同一时间段。
- 原因：上一个试次的残留文件、缓存、配额耗尽影响下一个，失败相互关联，独立性假设不成立。Anthropic 的文章提到过 Agent 读到前一个试次留下的 git 历史、从而占便宜的情况。
- 排查：把题目打乱顺序重跑，看失败是否跟着时间位置走而不是跟着题走。
- 处理：每个试次从干净环境开始；外部工具结果能录制回放的就固定下来（见 [harness/06 Trace 与回放](../../harness/06-tracing-replay/README.md)）。

**6. 为了降方差把温度调成 0**

- 现象：温度 0 下分数很稳，上线（温度不为 0）后表现不一样。
- 原因：Miller 第 3.3 节指出，降温度可能只是把题内方差搬到了题间方差，还会改变期望分数。他的例子里，温度从 1 降到 0，难度方差从 1/12 变成 1/4，反而大了 3 倍。
- 处理：用部署时的温度评测，靠每题多跑几次压题内方差。

**7. 边跑边看、显著就停**

- 现象：评测跑到一半看到显著就宣布结论，复跑后消失。
- 原因：多次查看抬高假阳性（第 7.5 节里约 20%）。
- 处理：事先按样本量公式定题数，跑完再看；必须提前看时，提前约定查看次数并相应收紧阈值。

**8. 评分器换了版本**

- 现象：Agent 没改，分数变了。
- 原因：评委模型、rubric 或评分脚本变了，Se、Sp 变了（第 4.1 节）。
- 排查：用固定的历史轨迹重新打分，看分数是否变化。
- 处理：评分器也要版本化；换评分器时在同一批轨迹上新旧各打一次，算一致率。

**9. 不显著就当作“没区别”**

- 现象：新版本没显著变好，于是被判定和旧版一样，护栏指标也这么处理。
- 原因：不显著只说明分辨不出，可能是题不够。护栏要证明的是“没变差”，要看区间下界是否高于容忍线，而不是看是否显著。
- 处理：报区间，不只报 p 值；护栏用非劣判定（第 5.2 节）。

## 10 对比与取舍

### 10.1 区间与检验方法

| 方法 | 适用 | 优点 | 缺点 |
|---|---|---|---|
| 正态近似（Wald） | 单个通过率，n 大、p 不靠边 | 好算、好口算 | p 接近 0 或 1、n 小时覆盖率不足、会越界 |
| Wilson 区间 | 单个通过率，尤其回归集 | 覆盖率接近名义值、不越界 | 公式稍长 |
| 三法则 | n 题全过 | 一个除法 | 只给上界 |
| 非配对标准误 | 两个版本在不同题集上 | 不要求同一批题 | 同一批题时浪费分辨率 |
| 配对标准误 | 两个版本同一批题 | 扣掉题目难度，区间更窄 | 需要逐题结果 |
| McNemar 精确检验 | 0/1 配对、不一致题少 | 小样本也精确 | 只给 p 值，不给区间 |
| 簇标准误 | 题按来源成组 | 修正同源相关 | 簇少（几十个以下）时本身不稳 |
| bootstrap | 复杂统计量（P95、比值、pass^k） | 通用 | 要按题（或按簇）重抽，抽运行就错了 |

### 10.2 花钱降误差：加题、加试次、修评分器

| 手段 | 降的是哪一项 | 什么时候选 |
|---|---|---|
| 加题 | Var(x)/n 和 E[σ²]/(nK) 都降 | 默认手段；题目难度差异大时只有它有用 |
| 每题多跑几次 | 只降 E[σ²]/K | 题内随机性大（Agent 每次结果差别大）且 E[σ²]/K 仍和 Var(x) 同量级 |
| 配对 | 扣掉 2Cov(x_A, x_B) | 只要同一批题就用，几乎免费 |
| 提高评分器精度 | 恢复被压缩的差距 | 评委和人工一致率低时，优先于加题 |
| 增加簇数而非簇内题数 | 降设计效应 | 题按文档、仓库生成时 |

### 10.3 面试时怎么串起来讲

被问“给你一个 Agent，怎么设计评测”时，按顺序答：

1. 成功定义：终态、必须告诉用户的信息、禁止项；按失败代价排序，有害失败一票否决。
2. 分层：难度、场景、风险三类标签；高风险层过采样，报整体时按线上占比加权；能力集和回归集分开。
3. 数据：真实失败打底，边界题补齐，两人独立标注，每题有参考解；评分器精度本身要测。
4. 判定：能用代码判的不用模型（见 [02](../02-llm-as-judge/README.md)），过程问题用轨迹规则（见 [03](../03-trajectory-eval/README.md)）。
5. 指标：主指标一个，pass^k、成本、延迟做护栏，安全做硬门槛。
6. 统计：按题（或按簇）算标准误，同一批题做配对比较，回归集用 Wilson 区间；事先按样本量公式定题数。

追问“差 3 个点算不算提升”，答三层：先看区间（配对标准误）；再看统计单位对不对（试次、簇）；最后看要多少题才能分辨（样本量公式，配对后主要看一对一错的题占比）。
