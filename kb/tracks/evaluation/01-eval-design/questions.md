# 题目：评测设计：任务分层、数据集构造与指标

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## eval-design-001 评测一个 Agent，第一步做什么
- level: 2
- tags: [evaluation, core]

**一句话答案**：先定义成功：写清终态、必须告诉用户的信息和禁止项，再按失败代价给错误排序；之后才谈题集和指标。

**要点**：
- 终态要可判定，例如数据库里订单状态和金额，而不是“回答得好”。
- 禁止项单列，例如未经确认的写操作、越权调用，用一票否决。
- 失败代价分级：不可逆写错 > 错误事实 > 没完成但无害 > 多花成本。
- “拒答”和“答错”分开统计，否则全拒答的系统看起来很安全。

**追问链**：
1. 开放式任务没有唯一终态怎么办？→ 拆成可判定的部分（必须包含的要点、引用是否真实）和软标准，软标准交给有 rubric 的评委，并和人工校准。
2. 为什么要按失败代价排序？→ 不同错误代价差很多，代价决定门禁阈值：高风险层要接近 100%，低风险层看平均即可。
3. 谁来定义成功？→ 领域专家和产品一起定，评测团队负责把它写成评分器可检查的条件。

**易错点**：
- 一上来就说“找个 benchmark 跑一下”。公开 benchmark 是别人的任务分布。
- 只定义成功率，不定义禁止项。

## eval-design-002 评测集怎么分层，能力集和回归集有什么区别
- level: 2
- tags: [evaluation]

**一句话答案**：按难度、场景、风险打标签并分层报分；能力集一开始通过率就低，给团队爬坡的目标，回归集应接近 100%，用来抓退化，饱和的能力题可以转进回归集。

**要点**：
- 难度：单步、多步、需要澄清、长程。
- 场景：查询、办理、投诉、越界请求等，对应产品入口。
- 风险：只读、可逆写、不可逆写、涉及隐私；高风险层单独设门禁。
- 总分不变时，可能简单题涨、高风险题掉，只看总分会漏掉退化。
- 能力集和回归集的区分来自 Anthropic《Demystifying evals for AI agents》。

**追问链**：
1. 层分多细合适？→ 层越细每层题越少，区间越宽。主指标报 3 到 5 层，细标签用于定位。
2. 回归集到 100% 还有用吗？→ 有，它的用途就是抓退化；但它已经看不出新的提升，需要新的能力题。
3. 题从哪来？→ 真实请求和历史失败打底，人工补边界和高风险题，合成数据只做补充。

**易错点**：
- 把能力集当回归门禁用。能力集通过率本来就低，用它做门禁会天天报警或者阈值形同虚设。

## eval-design-003 什么是一道好的评测题，标注怎么保证质量
- level: 2
- tags: [evaluation]

**一句话答案**：两位领域专家独立判会得出相同结论；评分器检查的每一项题面都写明；有一份能通过所有评分器的参考解；正反两面都有题。标注至少两人独立做，用一致率和 kappa 检查，分歧多的题先改题面。

**要点**：
- 题面没写精度，评分器却按精度判，是典型坏题。
- 参考解证明题可解，也证明评分器配置正确。
- 正反两面：既测“该做时做了”，也测“不该做时没做”。
- 一题跑很多次通过率都是 0，先怀疑题坏了。
- SWE-bench Verified：每题三位标注者，取最严重的判定，题面不清或测试会拒绝正确解的题剔除。

**追问链**：
1. 两位标注者结论不一致怎么办？→ 先看是不是题面或指南有歧义，改题和指南后重标；投票只是兜底。
2. 为什么要报 kappa 而不只报一致率？→ 大部分题容易判时一致率天然高，kappa 扣掉碰巧一致的部分。
3. 严格过滤的代价是什么？→ 题变少，统计分辨率下降；SWE-bench Verified 自己也说过滤可能偏严。

**易错点**：
- 认为题越多越好。有歧义的题越多，分数噪声越大。

## eval-design-004 每题跑 n 次成功 c 次，怎么估计 pass^k，为什么不能用 p̂^k
- level: 2
- tags: [evaluation, training]

**一句话答案**：逐题用无放回组合估计 C(c,k)/C(n,k)，再对所有题平均，要求 n ≥ k。p̂^k 会估高：x^k 是凸函数，按 Jensen 不等式 E[p̂^k] ≥ p^k。

**要点**：
- pass^k 由 τ-bench 提出，衡量多个试次下行为的可靠性。
- k 越大，pass@k 越高，pass^k 越低；单次 75%，3 次全对约 42%。
- 多候选可用测试挑选的任务看 pass@k；每次只给用户一个结果的任务看 pass^k。
- 先算 p̂ 再取 p̂^k 会把 pass^k 估高（凸函数，Jensen 不等式）。
- pass@k 的对应估计是 1 − C(n−c,k)/C(n,k)；k = 1 时两者相等。

**追问链**：
1. 举个两种算法差别的例子？→ n = 8、c = 6、k = 4：组合估计 15/70 ≈ 0.21，p̂⁴ = 0.75⁴ ≈ 0.32。
2. 每题只跑 3 次能报 pass^5 吗？→ 不能，需要 n ≥ k。
3. τ-bench 里 pass^k 低一定是 Agent 不行吗？→ 不一定。它的模拟用户温度为 1，环境本身有随机性，要先区分波动来自 Agent 还是环境。

**易错点**：
- 把多数投票后的结果当作 pass^k。投票后的系统是一个新系统，算的是它的 pass@1。

## eval-design-005 在 100 道题的 Agent 评测集上，新版本比旧版本高 3 个点，能说它更好吗
- level: 3
- tags: [evaluation]

**一句话答案**：不能直接说。100 题时单个通过率的 95% 区间半宽约 8 到 10 个点；要在同一批题上配对比较，只看“一对一错”的题，用精确二项检验或配对标准误给区间，含 0 就不能下结论。

**要点**：
- 0/1 结果的标准误 `sqrt(p̂(1−p̂)/n)`，95% 区间 ≈ p̂ ± 1.96 SE。
- 题少且通过率接近 0 或 1 时用 Wilson 区间；全过时失败率上界约 3/n。
- 配对扣掉题目难度的共同部分，同样题数区间更窄。
- 每题跑 K 次时，先求每题平均，再按题算标准误；同源题按簇算。
- 样本量：`n ≈ (z_{α/2} + z_β)² × Var(差值) / δ²`；不配对、通过率 80%、检出 5 个点约需 1000 题。

**追问链**：
1. 11 道一对一错的题，新版赢 7 题，显著吗？→ 不显著，精确二项检验双侧 p ≈ 0.55；15 比 1 才 p ≈ 0.0005。
2. 不显著是不是说明两个版本一样？→ 不是，只说明这批题分辨不出，可能要加题或降低单题波动。
3. 把 3 次运行当 300 个样本算有什么问题？→ 同一题的多次运行高度相关，会低估方差，区间过窄。
4. 显著了就能上线吗？→ 还要看分层结果和护栏指标，差距可能只在不重要的题上。

**易错点**：
- 两个版本各算一个总分直接比，不配对也不给区间。
- 同时比很多指标，挑一个显著的报。应事先定主指标。

## eval-design-006 给你一个企业知识库问答 Agent，设计它的离线评测方案
- level: 3
- tags: [evaluation, harness]

**一句话答案**：先定义成功（答案正确、引用真实、不越权），按类型、难度、风险分层，真实失败打底加边界题；确定性校验优先，开放项用校准过的评委；报成功率、pass^k、成本、延迟、安全并给区间；回归集接发布门禁。

**要点**：
- 成功定义：事实与文档一致；引用指向真实段落；无权访问的文档不出现在回答里；文档里没有答案时要说明没有。
- 分层：单文档事实、跨文档汇总、需要澄清、无答案、权限边界；风险层（权限、隐私）单独门禁。
- 数据：线上问题脱敏采样，历史差评回流，人工补无答案和越权题；两人独立标注，每题附参考答案和来源段落。
- 判定：引用 ID 存在性、权限、格式用代码判；事实点用要点清单判；表达质量用 rubric 评委，并和人工算 kappa。
- 指标：成功率为主，pass^k 看稳定性，每题 token 和检索次数看成本，P95 延迟，越权泄露数为 0 的硬门槛。
- 环境：固定文档快照和索引版本，每个试次干净环境，避免文档更新带来漂移。
- 统计：报题数和 95% 区间，版本对比在同一批题上配对。

**追问链**：
1. 知识库文档在更新，评测集怎么不过期？→ 题目绑定文档快照版本；定期按新快照重建参考答案，过期题淘汰。
2. 检索错了和生成错了怎么区分？→ 单独评检索：参考来源段落是否被召回；再在给定正确段落时评生成。两层分数对照定位（见 [03](../03-trajectory-eval/README.md)）。
3. 第一版做多大？→ 先从真实失败里取 20-50 题跑起来，随着改动效果变小再扩到几百题以上。
4. 离线分数涨了线上没感觉怎么办？→ 可能评测集分布偏了或被过拟合，要对比线上抽检结果，见 [05](../05-online-regression/README.md)。

**易错点**：
- 只用一个 LLM 评委打总分，不做确定性校验，也不校准评委。
- 忘了“无答案”和“越权”两类反面题。

## eval-design-007 回归集 30 题过 29 题，为什么不能用 p̂ ± 1.96·SE 报区间，该怎么报
- level: 2
- tags: [evaluation]

**一句话答案**：通过率接近 1 且题少时正态近似会越界、覆盖率不足，p̂ = 1 时区间宽度为 0。改用 Wilson 区间：保留未知 p 解得分检验的二次不等式；全过时报 3/n 的失败率上界。

**要点**：
- 30 题过 29 题：正态区间约 [0.90, 1.03]，Wilson 约 [0.83, 0.99]。
- 正态近似用 p̂ 估方差，p̂ 靠边时方差被低估；模拟里 30 题、真实 98% 时，“95%”区间只覆盖约 45%。
- Wilson：解 (p̂ − p)² ≤ (z²/n)·p(1 − p)，中心 (p̂ + z²/2n)/(1 + z²/n)，向 1/2 收缩。
- 三法则：(1 − f)^n = 0.05，n·ln(1 − f) = ln 0.05 ≈ −3，f ≈ 3/n。
- Brown、Cai、DasGupta（2001）推荐小 n 时用 Wilson 或 Jeffreys 区间。

**追问链**：
1. Wilson 区间的中心为什么不是 p̂？→ 端点是二次方程的根，中心是 (p̂ + z²/2n)/(1 + z²/n)，被拉向 1/2；n 大时 z²/n → 0，退化成正态近似。
2. 想说明高风险层失败率低于 1%，要多少题？→ 约 300 题全部通过，因为上界约 3/n。
3. 三法则里的 3 从哪来？→ 来自 −ln 0.05 ≈ 3.0，再用 f 很小时 ln(1 − f) ≈ −f。

**易错点**：
- 全过时报“100% ± 0%”。
- 把三法则当成双侧区间；它是 95% 单侧上界。

## eval-design-008 两个版本跑同一批题，配对标准误为什么比非配对小，0/1 结果时信息来自哪些题
- level: 3
- tags: [evaluation]

**一句话答案**：差值方差是 [Var(s_A) + Var(s_B) − 2Cov]/n，非配对等于假设协方差为 0。两版对题目难度看法一致时协方差为正，配对把它扣掉。0/1 结果时只有一对一错的题有信息。

**要点**：
- 配对标准误：逐题差 d_i，SE = sqrt(Σ(d_i − d̄)²/(n − 1)/n)（Miller 式 7）。
- 随机部分 ε 跨版本不相关，所以扣掉的是 2Cov(x_A, x_B)/n。
- 换算式：SE_paired = sqrt(SE_A² + SE_B² − 2·SE_A·SE_B·r)。
- 0/1 时 d̄ = (b − c)/n，Var(d) ≈ (b + c)/n − d̄²；精确检验在 b + c 道不一致题上用 Binomial(b + c, 1/2)。
- Miller 的例子：连续分数均匀分布、相关 0.5，差值方差从 1/6 降到 1/9。

**追问链**：
1. 题目难度和两个版本都不相关时，配对会吃亏吗？→ 不会，两种标准误差不多；所以同一批题上应默认配对。
2. 400 题里 62 题一对一错、A 赢 38 题，显著吗？→ 不显著，精确检验双侧 p ≈ 0.098；配对区间约 [−0.3, +7.3] 个点，含 0。
3. 两个版本越像，检出同样的差距越难还是越容易？→ 越容易：不一致的题越少，差值方差越小，所需题数越少。

**易错点**：
- 两个版本各算一个区间，看是否重叠来判断显著。这相当于比非配对还保守。
- 以为“都对”的题也在帮忙缩小区间。

## eval-design-009 每份文档生成 8 道问答、共 400 题，为什么普通标准误会低估，怎么修正
- level: 3
- tags: [evaluation]

**一句话答案**：同一文档的题共享文档难度，彼此正相关，不满足独立抽样。方差放大约 1 + (m − 1)ρ 倍（设计效应），要用簇标准误：在普通方差上加同簇内不同题的交叉乘积和 /n²。

**要点**：
- Miller 式 4：SE_clustered² = SE_CLT² + (1/n²) Σ_c Σ_i Σ_{j≠i} (s_{i,c} − s̄)(s_{j,c} − s̄)。
- 簇内完全不相关时退化成普通标准误；完全相关时一个簇只顶一道题。
- m = 8、ρ = 0.2 时设计效应约 2.4，400 题只顶约 167 道独立题。
- 论文报告 DROP 上簇标准误约是普通标准误的 3 倍。
- 比较两个版本时，对逐题差值用簇标准误（Miller 式 8）。

**追问链**：
1. 每题跑 K 次是同一个问题吗？→ 是同一类：同一题的多次运行共享 x_i，统计单位是题，先求逐题均值再算标准误。
2. 预算固定，增加文档数还是每份文档多出题？→ 增加文档数；簇内多出题会被设计效应抵消。
3. 抽子集估方差时要注意什么？→ 整簇抽，保留簇内相关结构。

**易错点**：
- 报告只写题数不写簇数。
- 簇很少（几十个以下）时，簇标准误本身也不稳。

## eval-design-010 配对比较、α = 0.05、检出力 80%、15% 的题两版一对一错，检出 3 个点差距要多少题
- level: 3
- tags: [evaluation]

**一句话答案**：n = (z_{α/2} + z_β)²·V/δ²，系数约 7.85。0/1 配对时 V ≈ 不一致率 − δ² ≈ 0.149，n ≈ 7.85 × 0.149 / 0.0009 ≈ 1300 题。

**要点**：
- 推导：原假设下在 d̄ > z_{α/2}·sqrt(V/n) 时拒绝；要求备择下概率为 1 − β，得 δ = (z_{α/2} + z_β)·sqrt(V/n)。
- Miller 式 9：V = ω² + σ_A²/K_A + σ_B²/K_B；ω² = 1/9、δ = 3 个点时 969 题。
- 不配对、通过率约 80%：V ≈ 0.32，3 个点要约 2800 题。
- 不一致率 10% 时约 865 题：配对后所需题数主要看一对一错的比例。
- 模拟里按公式定题数，实际检出率约 80%；同样题数不配对只有约 55%。

**追问链**：
1. 题数固定时怎么用这个公式？→ 反解最小可检出差距 δ = (z_{α/2} + z_β)·sqrt(V/n)，判断这批题值不值得跑。
2. 每题多跑几次能替代加题吗？→ 只能降 σ²/K 那一项，题目难度差异 ω² 只能靠加题摊薄。
3. V 从哪来？→ 用上一轮两个版本的逐题结果算差值方差；没有历史数据时用不配对的 2p(1 − p) 保守估计。

**易错点**：
- 每加一批题就看一次、显著就停，假阳性会远高于 5%。
- 照抄“1000 题”，不按自己的 V 算。
