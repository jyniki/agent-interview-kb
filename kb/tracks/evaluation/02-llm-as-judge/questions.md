# 题目：LLM-as-Judge：偏差、校准与一致性

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## eval-judge-001 LLM 评委的提示应该怎么写
- level: 2
- tags: [evaluation]

**一句话答案**：rubric 拆维度逐项判，最好一维一调用；能二值就不打 1-10 分；先引原文给证据再下结论；信息不够可返回 Unknown；有标准解就给参考答案；输出用 schema 约束，解析失败算评测失败。

**要点**：
- 逐项判让评委和人工的分歧能定位到维度。
- 二值边界清楚，比 1-10 分稳定，也更容易和人工对齐。
- 先给证据降低被自信语气说服的概率。
- Unknown 单独统计送人工，不逼评委编结论。
- 参考引导：MT-Bench 论文中，给参考答案的评委在数学题上失败最少。

**追问链**：
1. 为什么一维一调用而不是一次评完？→ 一个评委同时管多个维度容易互相影响、判断不一致；分开调用更好调试，代价是成本上升。
2. rubric 改了以后旧分数还能比吗？→ 不能直接比，要在同一批样本上用新 rubric 重跑旧版本。
3. G-Eval 做了什么？→ 让模型先生成评估步骤，再按表单逐项填分，并讨论了评委可能偏好模型生成的文本。

**易错点**：
- 解析失败默认通过。评委一出故障，门禁就形同虚设。

## eval-judge-002 怎么用对照实验分别测出位置偏差、冗长偏差和自我偏好
- level: 2
- tags: [evaluation]

**一句话答案**：位置偏差：同一对答案正倒序各评一次，看结论翻转比例；冗长偏差：给回答加长但不加信息，看评委是否偏好加长版；自我偏好：评委给自家模型的胜率和人工判的比，高出的部分就是偏好。

**要点**：
- 对冲：位置偏差两次都赢才算赢；冗长偏差在 rubric 写明长度不加分；自我偏好让评委和被评系统用不同模型，或用多源评委。
- 位置偏差：MT-Bench 论文用两份质量相近的答案正倒序各评一次；开放类题和质量接近的两个答案上偏差更重。
- Wang 等：只调换顺序就能让评委结论大幅翻转；提出 Multiple Evidence、Balanced Position、Human-in-the-Loop 三种校准。
- 冗长偏差：MT-Bench 论文的重复列表攻击，把列表改写后拼在前面，不加任何新信息。
- 自我偏好：Panickssery 等发现自我识别能力和自我偏好近似线性相关。
- 另有被答案带偏：评委会做的题，看了错答案后也会判错；先独立解题做参考可以缓解。

**追问链**：
1. 交换顺序后两次结论不一致怎么处理？→ 记平局，或合并两次分数；翻转多的样本送人工；翻转比例很高时改成单答案 rubric 判定。
2. 自我偏好为什么难发现？→ 它每次都偏同一个方向，分数内部看不出异常，只有和人工标注对比才看得出。
3. 用最强的模型做评委能消除偏差吗？→ 偏差会小一些但不会消失，能不能用只能靠人工校准回答。

**易错点**：
- 只交换一次顺序却仍按第一次结果计分。
- 把“评委多次结论一致”当成没有偏差。偏差是系统性的，多次采样抵消不了。

## eval-judge-003 评委和人工一致率 88%，这个评委能用吗
- level: 3
- tags: [evaluation]

**一句话答案**：不一定。要看样本量、类别分布和 kappa，还要拆开看放过率和误杀率；正样本占 80% 时全判通过也有 80% 一致率，kappa 却是 0。

**要点**：
- `kappa = (p_o − p_e) / (1 − p_e)`，p_e 是双方按各自判通过的比例独立随机判时的一致率。
- 例：人工过 80 条，评委过 82 条且其中 75 条人工也过；p_o = 0.88，p_e = 0.692，kappa ≈ 0.61。
- 人工判不过的 20 条里评委放过 7 条，放过率 35%。
- 先测人与人的一致性，作为评委能达到的上限参考；MT-Bench 论文里强评委与人工一致率超过 80%，和人与人相当。
- 校准集小时一致率误差大，30 条里差 3 条就是 10 个点。

**追问链**：
1. 放过和误杀哪个更要紧？→ 看场景。高风险场景放过坏答案代价更大，要单独设放过率上限。
2. 校准后评委分数怎么用？→ 用校准集测得的放过率和误杀率，把评委通过率换算成接近人工口径的估计，并把校准集误差带进区间；没做这一步时只用于同一评委下的版本比较。
3. 什么时候要重新校准？→ 评委模型升级、rubric 改动、被评系统大改之后。
4. 分歧样本先改哪边？→ 先读样本：多数是 rubric 含糊就改 rubric，少数是人工标错就修标注。

**易错点**：
- 把评委的自一致（同一输入多次结论相同）当成评委准确。
- 只抽容易判的样本做校准，一致率虚高。

## eval-judge-004 多评委怎么组合，代价是什么
- level: 2
- tags: [evaluation]

**一句话答案**：同一评委多次采样取多数降低随机性；不同来源模型做评委取多数对冲自我偏好；评委意见不一致的样本送人工。代价是成本随评委数线性增加，同源评委偏差方向一致，投票抵消不了。

**要点**：
- 三种一致要分开：自一致（稳不稳）、交换一致（位置偏差多大）、与人工一致（准不准）。
- 评委分歧本身是有用信号，可以用来挑送人工的样本。
- 备用评委也要和人工校准，换评委等于换尺子。

**追问链**：
1. 成本太高怎么办？→ 先用代码判定兜住可判定部分，评委只评软项；对稳定的样本少采样，对分歧样本多采样。
2. 三个评委两个说过一个说不过，怎么判？→ 普通样本取多数；高风险样本只要有一个不过就送人工。
3. 主评委限流时怎么办？→ 切到校准过的备用评委，并在报告里标明评委版本，前后分数不直接比。

**易错点**：
- 用同一家族的几个模型投票，以为已经对冲了自我偏好。

## eval-judge-005 哪些场景不应该用 LLM 评委
- level: 2
- tags: [evaluation, training]

**一句话答案**：答案能确定性判定时、评委自己不会做的题、需要外部事实核验而评委拿不到来源时、高风险不可逆决定、直接当训练奖励、以及没做过人工校准时。

**要点**：
- 可确定性判定（数值、终态、单元测试）用代码，评委只会加噪声。
- 评委不会的题会被被评答案带偏。
- 事实核验要给评委来源，否则只能凭印象。
- 高风险：规则一票否决加人工复核。
- 当训练奖励：策略会学会讨好评委，分数涨质量不涨。

**追问链**：
1. 开放式写作没法用代码判，又不想全靠评委怎么办？→ 把可检查的部分拆出来（必须包含的要点、引用存在性、格式）用代码判，剩下的软项用评委并定期和人工对齐。
2. 训练时一定不能用评委奖励吗？→ 可以用，但要和规则奖励组合，定期抽样人工复核，监控评委分和人工分是否背离。

**易错点**：
- 认为评委越强就越能替代人工。人工的作用是校准和抽检，不能省。

## eval-judge-006 给客服 Agent 设计一套 LLM 评委，并证明它可信
- level: 3
- tags: [evaluation, harness]

**一句话答案**：终态、金额、禁止操作交给代码判，评委只评是否解答、是否告知必要信息、语气等软项；每项二值、要证据、可返回 Unknown；用两人独立标的校准集算 kappa、放过率和误杀率；对冲三类偏差，定期复测。

**要点**：
- 分工：数据库状态、金额、越权调用用代码判；软项用评委。
- rubric：每项一句可判定的问题，附通过和不通过的例子。
- 三类偏差指位置、冗长和自我偏好。
- 偏差对冲：单答案判定为主，避免两两比较的位置偏差；rubric 写明长度不加分；评委与被评 Agent 用不同模型。
- 校准集：覆盖各场景、投诉和越界请求，含“短而全”“长而空”对照样本；先测人与人一致性。
- 门槛：kappa 和放过率达到事先定的标准才用于门禁，不达标只做参考。
- 运维：评委版本、rubric 版本写进报告；Unknown 和评委分歧样本送人工；每次模型或 rubric 变更后重测。

**追问链**：
1. 多轮对话怎么评？→ 评委看完整对话，按维度分别判；和轮数相关的要求（例如多少轮内解决）用代码统计，不交给评委。
2. 校准集需要多大？→ 至少要让放过率的区间窄到能做决定；几十条只能看大方向，要逐步扩到几百条，并覆盖难样本。
3. 评委分数涨了但用户投诉没降，查什么？→ 评委口径可能和用户需求不一致或已被系统“讨好”；对比人工抽检，重新校准 rubric。

**易错点**：
- 让评委判断退款金额对不对。能用代码判的交给评委，只会引入偏差。
- 没有校准就把评委分数当成“客服满意度”。

## eval-judge-007 为什么成对比较时交换顺序、结论翻转记平局能消除位置偏差，代价是什么
- level: 3
- tags: [evaluation]

**一句话答案**：交换后记平局的得分逐样本等于两种顺序单次得分的平均，位置偏差在两种顺序里方向相反，相加抵消；质量相同时得分正好 0.5，方向不会错。代价是调用翻倍，偏差越大平局越多、得分越往 0.5 靠。

**要点**：
- 记 a 为 X 在前时选 X，c 为 Y 在前时选 Y：score = a(1−c) + 0.5[ac + (1−a)(1−c)] = 0.5(a + 1 − c)。
- logistic 模型下 E[score] = 0.5[σ(αΔ + b) + σ(αΔ − b)]，Δ = 0 时为 0.5，Δ > 0 时大于 0.5。
- 随机分配位置的期望与此相同，只是方差更大。
- MT-Bench 论文用这种保守做法；Wang 等的 BPC 是把正倒序分数取平均。
- 得分是评委眼里的胜率，不等于真实胜率，仍要和人工校准。

**追问链**：
1. 只评一次会怎样？→ 期望是 σ(αΔ + b)，b 够大时即使 X 更差也能过 0.5，结论由位置决定。
2. 一致率很低、胜率在 50% 附近，能说两个版本一样好吗？→ 不能。平局多可能是偏差大把得分拉向 0.5，要改单答打分或对平局样本送人工。
3. 这个方法能对付冗长偏差吗？→ 不能。长度没法交换，没有对称的顺序可以抵消。

**易错点**：
- 交换后仍按第一次的结论计分，或把翻转样本直接丢掉不计入分母。

## eval-judge-008 评委判出通过率 80%，校准集上放过率 35%、误杀率 6.25%，按人工口径通过率是多少
- level: 3
- tags: [evaluation]

**一句话答案**：全概率公式 q = f + (1−f−m)π，解得 π̂ = (q−f)/(1−f−m) ≈ 0.766；再用 delta 方法把校准集误差带进区间；1−f−m 接近 0 时无法校正。

**要点**：
- 直接报 q 的偏差是 f(1 − π) − mπ：放过多偏高，误杀多偏低。
- 方差 ≈ [q(1−q)/N + (1−π)²f(1−f)/n₀ + π²m(1−m)/n₁] / J²，J = 1 − f − m。
- N = 2000、校准集人工不过 20 条、人工过 80 条时，区间约 [0.654, 0.878]，大头来自 f 的项。
- 这个形式就是流行病学里的 Rogan-Gladen 估计，1 − m 是灵敏度，1 − f 是特异度。
- 同一评委比两个版本时，评委看到的差距是真实差距的 J 倍。

**追问链**：
1. 想把区间缩窄，钱花在哪？→ 花在人工标注上，尤其是人工判不过的样本；多跑评委只缩 q 的项，它本来就最小。
2. 校准集多抽了难样本，校正还成立吗？→ 成立。f、m 按人工标签条件估计，不依赖校准集的类别比例；但 PPI 的平均差要求校准集是待评集的随机样本，会偏。
3. 校正后超过 1 怎么办？→ 截断只用于报告；它说明待评集上评委的 f、m 和校准集不同，要从待评集补标注。

**易错点**：
- 把放过率的分母写成全部样本或评委判过的样本，它应是人工判不过的样本。

## eval-judge-009 多个评委多数投票，准确率随评委数怎么变，错误相关时有什么不同
- level: 2
- tags: [evaluation]

**一句话答案**：独立且单个正确率 p > 0.5 时，正确率 P(Binomial(n,p) > n/2) 随 n 增大趋近 1；错误相关时共同盲区的错去不掉，有上限；p < 0.5 时越投越错。

**要点**：
- p = 0.75：1、3、5、9 个评委分别约 0.75、0.844、0.896、0.951。
- 共同盲区模型：以概率 c 所有评委同判，正确率 = c·p + (1 − c)·P(Binomial > n/2)，上限 c·p + 1 − c。
- c = 0.5、p = 0.75 时 9 个评委只到约 0.85，上限 0.875。
- 偶数个评委有平票：严格多数下 4 个（0.738）不如 3 个（0.844）。
- 同一评委多次采样只消随机错误；不同来源的评委 c 更小。

**追问链**：
1. 加评委没效果先查什么？→ 评委两两在错误样本上的重合度，以及单个评委在哪些层上正确率低于 0.5。
2. 高风险样本还取多数吗？→ 不取，任何一个判不过就送人工，用误杀换放过。

**易错点**：
- 用同一家族的几个模型投票，以为错误独立、已对冲自我偏好。

## eval-judge-010 同一个评委在两个数据集上放过率和误杀率都是 10%，kappa 为什么一个 0.8 一个 0.43
- level: 3
- tags: [evaluation]

**一句话答案**：偶然一致 p_e 由类别比例决定。通过率从 0.5 变成 0.95，一致率都是 0.9，p_e 却从 0.5 升到约 0.82，kappa 随之下降。评委属性应看放过率和误杀率。

**要点**：
- κ = (p_o − p_e)/(1 − p_e)，p_e = πq + (1 − π)(1 − q)。
- 二分类闭式：κ = 2(ad − bc) / [(a+b)(b+d) + (a+c)(c+d)]，独立时 ad − bc 期望为 0。
- kappa 比一致率好：全判通过或按比例乱判的评委得 0，而不是 80%、68%。
- 放过率、误杀率按人工标签条件化，评委行为不变时不随通过率变。

**追问链**：
1. 那 kappa 还有什么用？→ 在同一个数据集上横向比较几个评委，或比较评委和人与人的一致性。
2. 两个独立乱判、各八成判过的标注者，一致率和 kappa 是多少？→ 一致率期望 0.68，kappa 期望 0。

**易错点**：
- 跨数据集比较 kappa，把下降归因于评委变差。
