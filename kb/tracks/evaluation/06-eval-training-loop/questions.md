# 题目：评测与训练闭环：bad case 回流与防过拟合

> 对应知识章：[README.md](README.md)。先闭卷作答，再看答案。

## eval-loop-001 线上发现一个 bad case，下一步怎么处理
- level: 2
- tags: [evaluation, training]

**一句话答案**：先归因：判分错就修评分器，工具、检索、需求问题走非模型修复，模型行为问题才考虑训练；同时把它脱敏写成有成功标准和参考解的评测题，确认旧版本稳定失败，再补几道同类题。

**要点**：
- 三条去路：评测题、训练数据、非模型修复。
- 判分错误进训练，会教模型迎合错误的判分。
- 评测题六步：脱敏、写成功标准、写参考解、确认旧版失败、决定放回归集还是能力集、补同类题。
- 按用户影响排优先级。

**追问链**：
1. 一道题跑很多次都是 0 分说明什么？→ 先怀疑题坏了：题面不清、评分器配错或不可解。
2. 什么情况放回归集，什么情况放能力集？→ 修好后应该一直对的行为放回归集；代表一类还做不好的能力放能力集。
3. bad case 只加不减有什么问题？→ 评测和训练都偏向最近出过事的问题；要按类别控制数量并淘汰过时题。

**易错点**：
- 直接把 bad case 加进训练集，不归因也不留评测题。

## eval-loop-002 同一个 bad case，能同时进评测集和训练集吗
- level: 2
- tags: [evaluation, training]

**一句话答案**：原题不能同时进两边。常见做法是原题进评测集，按它的失败类型另外合成或采集相似但不同的样本进训练集，再对训练样本做去污染，确认和评测题没有改写重叠。

**要点**：
- 原题进训练，评测分数只说明模型记住了这道题。
- 训练用同类新样本，评测才能检验“这一类”是否学会。
- 训练数据形式：修正轨迹（SFT）、失败轨迹做负例的偏好对、RL 环境任务、奖励规则。
- 每条训练样本记录来源，出问题能整批删除。

**追问链**：
1. 合成的同类样本和原题太像怎么办？→ 用 embedding 检索加 LLM 判定检查改写重叠，太像的丢掉或改得更远。
2. 什么时候用偏好对而不是 SFT？→ 模型会做但常选错时用偏好对；不会某个流程时用修正轨迹 SFT。
3. 能用 RL 吗？→ 有可验证终态的场景可以做成环境任务，奖励设计见 [training/05](../../training/05-reward-verifier/README.md)。

**易错点**：
- 以为“只用了一道题训练，影响很小”。这道题的评测结果从此失效。

## eval-loop-003 评测集和训练集怎么隔离
- level: 2
- tags: [evaluation, training]

**一句话答案**：存储和权限隔离；按源头切分，同一会话、文档、用户派生的样本只在一边；按时间切分；n-gram 加 embedding 检索加 LLM 判定做去污染，合成数据也要查；每条样本记录来源。

**要点**：
- 同源题：同一份文档派生的两道题分到两边，模型等于间接见过答案。
- 只做 n-gram 不够：改写和翻译能绕过。Yang 等用 LLM 判断改写重叠，在公开预训练代码数据里发现 8%-18% 的 HumanEval 题有重叠。
- 教师模型见过评测题时，生成的合成数据也会带着题的影子。
- 高风险层用更严的去污染阈值。

**追问链**：
1. 按源头切分的代价？→ 两边样本都变少；主题相近的样本可能被误删。
2. 去污染之后怎么验证真的干净？→ 定期用新采样的题对照：旧题涨、新题不涨就要怀疑。
3. 评测集需要保密吗？→ 至少 holdout 要限制访问；评测集公开出去，就可能进别人的或自己的训练语料。

**易错点**：
- 随机切分会话级数据，不按源头切。

## eval-loop-004 怎么判断团队已经过拟合了自己的评测集
- level: 3
- tags: [evaluation, training]

**一句话答案**：同一组版本同时跑旧题集和新采样的题：旧题上的提升在新题上不出现，就是过拟合；新题上同幅提升、只是整体低一截，多半是新题更难。辅助信号是评委分涨而确定性校验不动、和线上差距拉大。

**要点**：
- 其他信号：修复说不出对哪一类有效。
- 原因：每次看分数选方案都是一次挑选，挑多了就混进运气；只改 prompt 也会发生。
- 四种形态：针对题面打补丁、迎合评分器、记住题目、题集老化。
- GSM1k 仿照 GSM8k 重出题，部分模型族掉分，越能背出原题掉得越多。
- Recht 等重建 ImageNet 测试集后普遍掉分，主要来自新题略难，提醒不要把掉分都算成过拟合。

**追问链**：
1. 为什么要看历次版本而不是只看最新版？→ 单看一个版本分不清难度差和过拟合；看提升是否同步出现才能分。
2. 迎合评分器怎么发现？→ 评委分涨，确定性校验和人工抽检不动；读高分样本找规律。
3. 怎么减少“挑选”带来的过拟合？→ 事先定主指标和候选数，限制看 holdout 的次数。

**易错点**：
- 认为不训练模型就不会过拟合。

## eval-loop-005 开发集、回归集、holdout 怎么分工，holdout 被看过了怎么办
- level: 2
- tags: [evaluation]

**一句话答案**：开发集随便看、用来调；回归集卡门禁防退化；holdout 只在关键决策前跑一次，结果不用于逐条调方案。根据 holdout 的结果改了系统，它就降级成开发集，从新采样的请求里另建 holdout。

**要点**：
- Dwork 等把这叫自适应数据分析：反复用同一留出集检验根据之前结果选出的假设，会拟合留出集本身。
- 留出集每被看一次，就漏一点信息给调优。
- holdout 够用就行，太大挤占开发题，关键是少看。
- 训练时选检查点也是挑选：挑选用开发集，最终确认用 holdout。

**追问链**：
1. holdout 多大合适？→ 足够分辨你关心的最小改进（按 [01](../01-eval-design/README.md) 的样本量估算），再大就是浪费。
2. 训练奖励能直接用评测集的评分器吗？→ 最好不完全相同，否则奖励被钻空子在评测上也看不出来。
3. 团队每天都想看 holdout 怎么办？→ 限制访问和频率，只在发布或选检查点时开；平时看开发集和回归集。

**易错点**：
- 每轮都看 holdout 结果调方案，还把它当 holdout 报分。

## eval-loop-006 设计题：为编程助手 Agent 设计评测驱动的迭代流程
- level: 3
- tags: [evaluation, training, harness]

**一句话答案**：开发集、回归集、holdout 三套题，取自线上失败和人工边界题；改动跑快门禁，合并跑全量回归，发布前用 holdout 确认一次；每周读线上轨迹归因回流，每月补题、淘汰旧题、重建 holdout。

**要点**：
- 成功标准：测试通过、不改测试文件、不引入无关改动、危险命令需确认。
- 题源：线上会话里用户撤销或大改的生成、工单；人工补“不该删”“不该改测试”这类反面题。
- 回流：判分错修评分器；工具问题修工具；模型行为问题原题进评测，同类新样本进训练。
- 隔离：同一仓库派生的题只在一边；训练数据做 n-gram 加 embedding 加 LLM 判定去污染。
- 防过拟合：修复说清对哪一类有效；评测分和线上采纳率、撤销率对照，差距拉大报警。
- 一轮只改少数变量，便于归因。

**追问链**：
1. 训练了一轮，回归集涨了，holdout 没涨，怎么办？→ 怀疑回归集被拟合或训练数据和回归集同源；查同源和去污染，读涨分题的轨迹。
2. 迭代多快合适？→ 每轮的预期提升要大于题集能分辨的幅度，否则在追噪声。
3. 新的基础模型发布了怎么用这套流程？→ 先跑能力集看哪些押注兑现，再跑回归集看有没有退化，最后用 holdout 确认。

**易错点**：
- 只有一套评测集，既调又卡门禁又报最终分。

## eval-loop-007 20 个真实通过率都是 70% 的 prompt 版本，在同一套 200 道题上挑最高分，报出的分数平均虚高多少
- level: 3
- tags: [evaluation]

**一句话答案**：约 6 个百分点。单版本标准误 se ≈ √(0.7×0.3/200) ≈ 0.032，挑最大值的期望偏差 ≈ se · E[M_20] ≈ 0.032 × 1.87；换新题重测平均回落到 70%。

**要点**：
- p̂_i ≈ p + se · Z_i，被选中者 ≈ p + se · max Z_i，偏差 = se · E[M_N]。
- E[M_N] = ∫ x · N φ(x) Φ(x)^(N−1) dx，可用 Φ⁻¹((N − 0.375)/(N + 0.25)) 近似；√(2 ln N) 在 N 小时偏大。
- 偏差随 N 按对数增长，随题数按 1/√n 下降。
- 候选得分相关系数为 ρ 时，偏差乘 √(1 − ρ)。

**追问链**：
1. 为什么换新题会回落？→ 新题上的噪声和“它为什么被选中”无关，期望就是真实水平。
2. 想把虚高压到 2 个点以内要多少题？→ n ≥ p(1 − p) · E[M_N]² / δ²，约 1800 题。
3. 候选是同一基线上的小改动，偏差会怎样？→ 得分相关度高，偏差按 √(1 − ρ) 缩小，但只要 ρ < 1 就不为 0。

**易错点**：
- 把开发集上的最好分数直接写进发布报告。

## eval-loop-008 Thresholdout 怎么让一个 holdout 被反复使用而不过拟合
- level: 3
- tags: [evaluation]

**一句话答案**：每次查询先比较训练集和 holdout 上的均值，差值低于加噪阈值就只返回训练集均值；超过阈值才返回加 Laplace 噪声的 holdout 均值，并扣一次过拟合预算，预算用完就停止回答。

**要点**：
- 出处：Dwork 等，arXiv 1506.02629，第 4 节和图 1；噪声来自差分隐私的稀疏向量技术。
- 不过拟合时分析者只拿到“一致”这一比特，泄露的 holdout 信息很少。
- 论文合成实验：标签与特征无关，标准复用 holdout 报出超过 63% 的准确率，Thresholdout 给出接近真实水平的估计。
- 工程上借思路：holdout 默认只报过不过门槛、限次、记录查看。

**追问链**：
1. 为什么工程上很少直接部署？→ 要有统一查询服务，阈值和预算依赖证明常数，论文实验参数也低于证明所需。
2. 不用这个算法，最简单的替代是什么？→ holdout 每个决策只看一次，看过就降级成开发集，重新采样建 holdout。
3. 被反复查看的普通 holdout 会怎样？→ 当成开发集在爬山，分数一路上涨，新请求上不涨。

**易错点**：
- 以为 holdout 只要不拿来训练，就怎么看都不会过拟合。

## eval-loop-009 bad case 回流时为什么要按失败类别分层抽样，怎么做
- level: 2
- tags: [evaluation, training]

**一句话答案**：按出现频率抽，大类占满名额，小类和高风险类只有一两条，看不出修没修好。做法是先归因分类，单类设上限，高风险类加权，名额用不完注水重分，类内随机抽，并记录抽样权重以便还原分布。

**要点**：
- 一类只有 m 条时，通过率标准误为 √(p(1 − p)/m)，m = 2 时约 0.32。
- 大类常由单个工具 bug 造成，修好后整类消失，回流题很快过时。
- 分层后的回流集不代表线上分布：适合开发集、能力集和训练数据，不能代替 holdout 报总分。
- 估计线上失败分布时按 1/抽样比例 加权还原。

**追问链**：
1. 某类池子里条数少于分到的名额怎么办？→ 全部拿走，剩余名额按权重分给其他没满的类。
2. 类内为什么要随机抽？→ 挑最新或最显眼的会在类内再偏一次。
3. 工具修好后这一类的题怎么处理？→ 留少量进回归集防回退，其余淘汰。

**易错点**：
- 直接用分层回流集的总分代表线上质量。
