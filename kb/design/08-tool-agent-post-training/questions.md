# 追问题：让开源模型学会调用企业内部工具

> 对应设计题：[README.md](README.md)。先白板作答整题，再用这些追问自测。

## design-tooltrain-001 让开源模型学会调用内部 API 时，什么时候 SFT 就够，什么时候要加 DPO 或 RL
- level: 3
- tags: [training, evaluation]

**一句话答案**：格式错、参数错、不会固定流程，SFT 示范就够；会做但常选错（该追问时编参数、该拒绝时硬调用）加 DPO；多步任务成功率低且终态可程序判定，上 RL。先看评测现象再决定。

**要点**：
- 训练前先做不训练的基线：改工具描述、按场景路由、约束解码。
- DPO 的偏好对来自失败轨迹（rejected）和修正轨迹（chosen），参考模型用 SFT 模型。
- RL 奖励参考 ToolRL：格式加正确性，正确性按工具名、参数名、参数值分别比对，权重大于格式。
- 0/N 的题很多时，RL 采不到正样本，要先补教师数据或换基座。

**追问链**：
1. 为什么多步任务更适合 RL 而不是 DPO？→ 多步的轨迹空间大，离线偏好对覆盖不了；DPO 只在数据出现过的回答上调概率，策略变了信号就偏。
2. 上 RL 前要准备什么？→ 可并发重置的预发或模拟环境、程序判定的终态评分器、对奖励做对抗测试，以及 SFT 冷启动模型。

**易错点**：
- 默认“RL 一定比 SFT 好”，说不出评测上的依据。
- 跳过基线，直接训练。

## design-tooltrain-002 估算：8B 模型全参 SFT，3 万条工具调用样本、每条 3,000 token、训 3 个 epoch，H100 稠密 BF16 约 990 TFLOPS、MFU 按 40% 算，要多少算力和时间
- level: 2
- tags: [training]

**一句话答案**：2.7 亿 token × 6 × 8.2e9 ≈ 1.3e19 FLOPs；每卡约 396 TFLOPS，约 9.3 卡·时，8 卡约 1.2 小时。训练很便宜，成本在造数据和评测。

**要点**：
- 3 万 × 3,000 × 3 = 2.7 亿 token。
- 训练每 token 约 6N FLOPs（Kaplan 等第 2.1 节，非嵌入口径）。
- 模型状态 16Ψ ≈ 131 GB，ZeRO-3 切到 8 卡每卡约 16.4 GB；LoRA 下冻结基座约 2Ψ ≈ 16.4 GB。
- 教师通过率 40% 时，要生成约 7.5 万条候选。

**追问链**：
1. 为什么说成本不在训练？→ 一次 SFT 一两个小时；造数据要教师推理、真实执行和人工抽检，评测每次都要在预发环境跑全量，这些花的时间和人力多得多。
2. 改用 LoRA 能省多少？→ 省的是梯度和优化器状态，激活和计算量基本不变，训练时间不会少很多。

**易错点**：
- 用带 sparsity 的 1,979 TFLOPS 算，高估一倍。
- 以为 LoRA 也能把计算量降到几分之一。

## design-tooltrain-003 合成工具调用训练数据时，怎么保证数据是对的
- level: 2
- tags: [training]

**一句话答案**：任务覆盖单步、多步、无需调用、缺参数、报错恢复；轨迹过格式、执行、语义三层校验，格式和执行用程序，语义用评委加人工抽检；按 API × 类型定配额、去重，样本带 API 版本。

**要点**：
- APIGen 的三层：格式检查、真实执行、语义验证。
- ToolACE 的规则层查 schema 和调用合法性，模型层拆成子问题查幻觉参数、一致性和工具结果；整条样本一次判效果差。
- 写操作在预发环境执行后回滚。
- 工具结果不计 loss；混入通用数据防止通用能力退化。

**追问链**：
1. 评委过滤有什么风险？→ 带入评委偏好；要先用人工标注样本测它的放过率和误杀率。
2. API 改了字段，旧数据怎么办？→ 按样本里记录的 API 版本找出受影响的样本，重新生成或删除。

**易错点**：
- 只做格式校验，不真跑。
- 只合成“一路顺利”的样本，没有无需调用和缺参数的样本。

## design-tooltrain-004 内部工具调用模型怎么评测，才能证明可以上线
- level: 2
- tags: [evaluation]

**一句话答案**：按 API 和任务类型分层：单步匹配、执行成功、多步终态与 pass^k、无需调用的误调用率、缺参数的追问率、写操作错误数（目标 0）、留出 API 泛化、通用能力；再经影子和灰度验证。

**要点**：
- 单步可参照 BFCL 的 AST 检查；无需调用参照它的 relevance detection。
- 留出几个 API 不进训练，检验对新 API 的泛化。
- 评测集和训练数据按来源隔离、去污染。
- 影子模式只生成不执行，和现有流程比对；先灰度只读 API。

**追问链**：
1. 为什么要单独报留出 API？→ API 会持续变化和新增；训练 API 上的分数可能来自记忆，留出层才反映读定义再调用的能力。
2. 线上失败怎么回流？→ 先归因：工具描述问题改描述，模型行为问题才构造同类新样本进训练，原题进评测集。

**易错点**：
- 只报一个总正确率。
- 不测通用能力退化。
